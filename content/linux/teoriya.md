# Linux за 10 днів по 15 хв

Щоб писати і запускати лаби з Python в Ubuntu (WSL) на ноутбуці. День = одна тема: 5 хв прочитати,
10 хв зробити руками в терміналі, 5 питань самоперевірки. Усі вправи «Руками» прогнано скриптом
у справжній Ubuntu 24.04 (87 перевірок, 17.11.2026).

## Тема 0. Встановлення: Ubuntu, VS Code, усе для лаб

### Крок 0. Що таке WSL, коротко

WSL - це справжня Ubuntu всередині Windows. Не віртуалка з окремим вікном, а термінал: відкрив
«Ubuntu» з меню Пуск - і ти в Linux. Файли Windows там теж видно (диск C: це `/mnt/c`).

### Крок 1. Перевір версію Windows (1 хв)

Win + R → `winver` → Enter. Дивись рядок «Збірка ОС» (OS Build).

- Windows 11 - усе працює, включно з вікнами turtle.
- Windows 10, збірка 19044 або більша (19045 теж) - усе працює, включно з вікнами turtle
  (потрібен свіжий WSL: `wsl --update`, крок 2).
  → Перевірено на твоєму ПК 17.11.2026: Windows 10 збірка 19045, WSL 3.0.5, вікно Tk у WSL відкривається.
- Windows 10, збірка від 19041 до 19043 - Ubuntu встановиться, але вікна (turtle) з Linux не відкриються.
  Тоді або онови Windows (Параметри → Оновлення), або turtle-лабу запускай звичайним Python у Windows (крок 6).
- Менше 19041 - спершу онови Windows.

Джерела: Microsoft, «Install WSL» (Windows 10 2004+, збірка 19041+) і «Run Linux GUI apps with WSL»
(«Windows 10 Build 19044+ or Windows 11»), learn.microsoft.com, перевірено 17.11.2026.

### Крок 2. Встановити Ubuntu (10-20 хв, більшість - чекати)

1. Пуск → набери `PowerShell` → правою кнопкою → «Запуск від імені адміністратора».
2. Введи і натисни Enter:
   ```powershell
   wsl --install
   ```
   Ставить WSL і Ubuntu (Ubuntu - за замовчуванням).
3. Перезавантаж ноутбук, коли попросить.
4. Після перезавантаження відкриється вікно Ubuntu (або відкрий «Ubuntu» з меню Пуск).
   Воно попросить:
   - **username** - ім'я в Linux, маленькими латинськими, без пробілів, напр. `evgen`;
   - **password** - пароль. Коли друкуєш, **нічого не видно, навіть зірочок**. Це нормально.
     Запам'ятай його: він потрібен для `sudo` (день 4).
5. Побачиш рядок типу `evgen@NOUT:~$` - ти в Linux.

Якщо `wsl --install` пише, що WSL уже є, - просто відкрий «Ubuntu» з меню Пуск.
Якщо Ubuntu нема в меню: `wsl --install -d Ubuntu` в адмінському PowerShell.

Одразу після встановлення (у звичайному PowerShell):
```powershell
wsl --update
wsl --version
```
`wsl --update` ставить найновіший WSL з Microsoft Store - саме він уміє відкривати вікна (turtle) на Windows 10.
`wsl --version` має показати кілька рядків (WSL version, WSLg version). Якщо пише, що такої команди нема, -
WSL старий, повтори `wsl --update`.

### Крок 3. Встановити VS Code з розширеннями (5 хв)

1. Скачай VS Code з https://code.visualstudio.com і встав **у Windows** (не в Ubuntu).
   У майстрі встановлення залиш галочку **«Add to PATH»** - без неї не працюватиме `code .` з Ubuntu.
2. Відкрий VS Code → ліворуч значок «Extensions» (чотири квадратики) → встанови:
   - **WSL** (від Microsoft, id `ms-vscode-remote.remote-wsl`);
   - **Python** (від Microsoft, id `ms-python.python`).
3. Закрий і заново відкрий вікно Ubuntu (щоб воно побачило `code`).
4. Після першого `code .` з Ubuntu (крок 5) зайди в Extensions: біля Python буде кнопка
   **«Install in WSL: Ubuntu»** - натисни. Розширення з Windows саме в Ubuntu не працює, без цього не буде
   вибору інтерпретатора і підказок.

   > **Нове тут:**
   >
   > - `code` - відкриває файл або теку у VS Code. Назва: code - від Visual Studio Code («код»). `.` - крапка = поточна тека: відкрити її всю як проєкт.
   >
   > **Як читати:**
   >
   > - Слово з мінусом (як `-O` тут) - **прапорець**: уточнює, що саме зробити команді.
   > - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
   > - Символи `~` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1).
   >
   > Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

### Крок 4. Усе для лаб одним скриптом (5-20 хв)

У вікні Ubuntu по черзі (після кожного рядка Enter):

```bash
cd ~
wget -O ustanovka.sh https://evge14n.github.io/uni-prep/files/ustanovka.sh
less ustanovka.sh
bash ustanovka.sh
```

> **Нове тут:**
>
> - `cd` - переходить в іншу теку. Назва: change directory - «змінити теку». `~` - домашня тека /home/evgen; `~/univer` - шлях від неї.
> - `~` (tilde) - твоя домашня тека, /home/evgen.
> - `wget` - завантажує файл з інтернету за адресою. Назва: World Wide Web + get - «дістати з вебу». `-O` (`--output-document`) - під яким імʼям зберегти файл (output document - «файл для виводу»).
> - `less` - гортає довгий файл по сторінках, вихід q. Назва: less - «менше»: жарт, бо less is more - кращий за старий переглядач more.
> - `bash` - програма, що читає й виконує твої команди; `bash файл.sh` - з файлу. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»).

- `wget` скачує файл (`-O ustanovka.sh` - зберегти саме під цим імʼям, навіть якщо скачуєш удруге), `less` показує, що в ньому (гортати стрілками, вийти - `q`).
  Завжди дивись, що за скрипт, перш ніж запускати.
- `bash ustanovka.sh` попросить пароль Ubuntu (символи не видно). Перший раз оновлення йде довго.
  **Не закривай вікно, поки не з'явиться «Готово»** - якщо закрити посередині, Ubuntu обірве
  встановлення (див. «Якщо щось пішло не так»).

Що робить скрипт (той самий файл лежить у `Linux\ustanovka.sh`):
1. Оновлює Ubuntu (`apt update`, `apt upgrade`).
2. Ставить python3, venv, pip, python3-tk (для turtle), pytest, flake8, git, nano, tree.
3. Робить теку `~/univer` і в ній віртуальне середовище `.venv` з pytest, flake8, black,
   pycodestyle, ruff, mypy, matplotlib, numpy (те, що просить викладач).
4. Робить теку `~/univer/labs` для лаб і `~/univer/praktyka` для вправ курсу.
5. Додає дві команди: `univer` (перейти в ~/univer і увімкнути venv) і `perevir файл.py`
   (doctest + flake8 + mypy одним махом).

> **Нове тут:**
>
> - `apt update` - завантажує свіжий список програм і версій, нічого не ставить. Назва: `apt` - Advanced Package Tool - «розширений інструмент для пакетів (програм)».
> - `apt upgrade` - ставить новіші версії всіх встановлених програм. Назва: upgrade - «перейти на новішу версію».
> - `perevir` - перевіряє лабу всіма інструментами одразу (doctest, стиль, типи).

Потім один раз скажи git, хто ти:
```bash
git config --global user.name "Твоє Імʼя Прізвище"
git config --global user.email "твоя@пошта"
```

> **Нове тут:**
>
> - `git config` - читає і змінює налаштування git (імʼя, пошта, редактор). `--global` - для тебе на цьому ноутбуці: пише у файл `~/.gitconfig`, діє в усіх репо (global - «загальне»).
> - `"..."` (double quotes) - усе між лапками - одне слово, навіть з пробілами.

### Крок 5. Перевір, що все працює (2 хв)

Закрий і знову відкрий Ubuntu, потім:
```bash
univer
python --version
type perevir
code .
```

> **Нове тут:**
>
> - `univer` - переходить у ~/univer і вмикає venv.
> - `type` - каже, що це за команда і де вона. Назва: type - «тип».
> - `python3` - запускає Python: твій файл `.py`, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. `--version` - надрукувати версію Python, напр. Python 3.12.3.

- `univer` - рядок почнеться з `(.venv)`. Це значить, що venv увімкнено.
- `python --version` - Python 3.12.x.
- `type perevir` - перший рядок «perevir is a function». Як нею користуватись - день 8.
- `code .` - відкриється VS Code, внизу ліворуч зелене «WSL: Ubuntu». Перший раз довантажує
  сервер у Ubuntu, це хвилина.

Перевірка turtle (вікно має з'явитися на 2 секунди):
```bash
python -c "import turtle; turtle.forward(100); turtle.left(90); turtle.forward(50); import time; time.sleep(2)"
```

> **Нове тут:**
>
> - `python3`: `-c` - виконати один рядок коду без файлу: `python3 -c 'print(2 ** 10)'` (command - «команда»).

### Крок 6. Де тримати лаби і як віддати файл

**Рекомендую:** лаби в Linux, у `~/univer/labs/ЛР4` і т. д. Там усе працює найшвидше
(Microsoft прямо радить тримати файли проєкту у файловій системі WSL, а не в `/mnt/c`).

- Відкрити теку лаби у Провіднику Windows (щоб скинути файл викладачу, на флешку, у Moodle):
  ```bash
  cd ~/univer/labs/ЛР4
  explorer.exe .
  ```

  > **Нове тут:**
  >
  > - `explorer.exe` - відкриває теку в Провіднику Windows (лише у WSL). Назва: explorer - «оглядач». `.` - крапка = поточна тека.

  Крапка в кінці обов'язкова. Адреса в Провіднику буде `\\wsl.localhost\Ubuntu\home\evgen\...`.
- Забрати файл з Windows у Linux (напр. заготовку з «Завантажень»):
  ```bash
  cp /mnt/c/Users/IMYA/Downloads/lab4.py ~/univer/labs/ЛР4/
  ```

  > **Нове тут:**
  >
  > - `cp` - копіює файл або теку. Назва: copy - «копіювати».

  Замість `IMYA` - імʼя Windows-користувача (подивись: `ls /mnt/c/Users`). Апостроф у команду не пиши:
  bash сприйме його як лапку і чекатиме продовження (рядок `>`; вийти - Ctrl+C).

  > **Нове тут:**
  >
  > - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки).

Якщо лаби вже лежать у теці Windows і хочеш працювати прямо там - можна. Тоді один раз:
```bash
NO_APT=1 bash ustanovka.sh "C:\Users\IMYA\Documents\Програмування"
```
(`NO_APT=1` - не оновлювати Ubuntu вдруге), і в `~/univer/prog` буде посилання на цю теку.
Працює, просто повільніше на великих теках.

**ЛР4 (turtle) і цей курс не сперечаються.** Розбір ЛР4 (`Лабораторні\ЛР4\`) радить для turtle звичайний Python
у Windows - це найпростіше і точно працює. У WSL turtle теж працює, якщо `wsl --version` друкує рядок `WSLg version`
(крок 2) і стоїть `python3-tk` (його ставить `ustanovka.sh`). Обирай будь-що; Linux у цьому курсі - для решти:
перевірки `perevir`, git, скрипти.

**Turtle (ЛР4), якщо вікно не з'явилося** (стара збірка Windows 10, крок 1): той самий файл
запускай звичайним Python у Windows - відкрий його у VS Code **без WSL** (File → Open Folder на
Windows-теці) або в IDLE і натисни Run. Код однаковий, різниця лише де запускаєш.

### Якщо щось пішло не так

| Що бачиш | Що зробити |
|---|---|
| `E: dpkg was interrupted, you must manually run 'sudo dpkg --configure -a'` | `sudo dpkg --configure -a`, потім знову `bash ustanovka.sh` |
| `Could not get lock /var/lib/dpkg/lock-frontend` | Ubuntu сама ставить оновлення у фоні. Зачекай 5 хв і повтори |
| `code: command not found` | VS Code встановлено без «Add to PATH» або не перевідкрив Ubuntu. Перевстанови з галочкою |
| `WslRegisterDistribution failed with error: 0x80370102` або «Virtual Machine Platform» | на ноутбуці вимкнена віртуалізація. Увімкни в BIOS/UEFI (Intel VT-x або AMD-V/SVM, зазвичай вкладка Advanced або CPU Configuration), потім знову `wsl --install` |
| `sudo: ... incorrect password` | пароль Ubuntu (крок 2), не Windows. Забув - у PowerShell: `wsl -u root passwd ІМЯ_В_UBUNTU` (те імʼя, що в рядку перед @) |
| `bash: $'\r': command not found` | скрипт збережено з кінцями рядків Windows (CRLF). Виправити: `sed -i 's/\r$//' файл.sh` |
| `error: externally-managed-environment` при `pip install` | ти не у venv. Спершу `univer` (або `source ~/univer/.venv/bin/activate`) |
| Ubuntu «зникла» посеред довгої команди | WSL вимикається, коли закрито всі вікна Ubuntu. Тримай вікно відкритим до кінця |

> **Нове тут:**
>
> - `sudo` - виконує одну команду як адміністратор; спитає твій пароль (видно зірочки). Назва: superuser do - «зроби як суперкористувач» (адміністратор).
> - `dpkg` - ставить один файл `.deb` і веде список встановлених програм. Назва: Debian package - «пакет Debian». `--configure` - доналаштовує розпаковані пакети; з `-a` - усі, які перервались (configure - «налаштувати»); `-a` (`--pending`) - з `--configure`: усі пакети, що чекають налаштування (pending - «ті, що чекають»).
> - `sed` - друкує потрібні рядки або замінює текст. Назва: stream editor - «потоковий редактор». `-i` (`--in-place`) - змінити САМ файл (без `-i` sed лише показує); `-i.bak` - ще й копія (in-place - «на місці»).
> - `'...'` (single quotes) - текст буквально: `$`, `*` і пробіли всередині - звичайні символи.
> - `pip install` - ставить бібліотеку Python (лише у venv). Назва: `pip` - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».
> - `source` - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». `~/univer/.venv/bin/activate` - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.

Повністю перезапустити Ubuntu (якщо все зависло): у PowerShell `wsl --shutdown`, потім знову відкрити Ubuntu.

## Тема 1. День 1: Термінал і де які файли

**Навіщо:** у терміналі ти пишеш команду, Enter - Linux виконує. Усе інше в курсі на цьому стоїть.

### Коротко (5 хв)

Відкрий «Ubuntu» з меню Пуск. Бачиш рядок-запрошення:

```text
evgen@NOUT:~$
 │     │   │ └ $ - чекаю команду (у root тут #)
 │     │   └── ~ - де ти зараз (~ = твоя домашня тека)
 │     └────── ім'я комп'ютера
 └──────────── ім'я користувача
```

**Як влаштовані файли.** У Windows є диски C:, D:. У Linux одне «дерево», корінь - `/`.

```text
/                      корінь
├── home/evgen/        твоя домашня тека, вона ж ~
│   └── univer/        лаби (зробив скрипт установки)
├── mnt/c/             диск C: Windows
├── mnt/d/             диск D: Windows (якщо є)
├── usr/bin/           програми (python3, git, ls)
└── tmp/               тимчасове, чиститься
```

- Шлях **абсолютний** починається з `/`: `/home/evgen/univer`.
- **Відносний** - від того місця, де ти зараз: `univer/labs`.
- `.` - ця тека, `..` - тека вище, `~` - домашня.
- Великі й малі літери різні: `Lab.py` і `lab.py` - два різні файли.
- Роздільник `/`, а не `\` як у Windows.

**Команди дня:**

| Команда | Що робить |
|---|---|
| `pwd` | де я (print working directory) |
| `ls` | що тут лежить |
| `ls -la` | детально (`-l`), з прихованими (`-a`, імена з крапкою) |
| `cd тека` | зайти в теку |
| `cd ..` | на рівень вище |
| `cd` або `cd ~` | додому |
| `cd -` | туди, де був перед цим |
| `clear` або Ctrl+L | очистити екран |
| `команда --help` | коротка довідка |
| `man команда` | повна довідка (вийти - `q`) |

> **Нове тут:**
>
> - `pwd` - показує, в якій теці ти зараз. Назва: print working directory - «надрукувати робочу (поточну) теку».
> - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки). `-l` - докладний список: права, власник, розмір у байтах, дата зміни (long - «довгий»); `-a` (`--all`) - показати й приховані (назва з крапки), разом з . і .. (all - «усі»).
> - `cd` - переходить в іншу теку. Назва: change directory - «змінити теку». `..` - тека на рівень вище; `../..` - на два рівні вище; `~` - домашня тека /home/evgen; `~/univer` - шлях від неї; `-` - назад, у теку, де ти був перед цим (cd друкує її шлях).
> - `~` (tilde) - твоя домашня тека, /home/evgen.
> - `clear` - очищає екран термінала (те саме, що Ctrl+L). Назва: clear - «очистити» (екран).
> - `man` - відкриває повний посібник до команди. Назва: manual - «посібник».
>
> **Як читати:**
>
> - Слово з мінусом (як `-a` тут) - **прапорець**: уточнює, що саме зробити команді.
> - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
> - Короткі можна склеювати: `-la` = `-l` і `-a`.
> - Символи `~` `|` `#` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1; `|` - Shift і клавіша `\`; `#` - Shift і 3 (в українській розкладці там №)).

### Коротко (5 хв)

| Команда | Що робить |
|---|---|
| `mkdir ЛР4` | створити теку |
| `mkdir -p labs/ЛР4/data` | створити з усіма проміжними, без помилки якщо вже є |
| `touch main.py` | створити порожній файл (або оновити час зміни) |

> **Нове тут:**
>
> - `mkdir` - створює нову теку. Назва: make directory - «зробити теку». `-p` (`--parents`) - створює й усі проміжні теки шляху; тека вже є - без помилки (parents - «батьківські»).

> - `cp` - копіює файл або теку. Назва: copy - «копіювати». `-r` (`--recursive`) - копіювати теку разом з усім, що всередині; те саме -R (recursive - «рекурсивно», углиб).
> - `mv` - переносить або перейменовує файл чи теку. Назва: move - «перемістити».
> - `rm` - видаляє файли назавжди, без кошика. Назва: remove - «прибрати, видалити». `-r` (`--recursive`) - видаляти теки разом з усім, що всередині; `-i` - питати про кожен файл перед видаленням (interactive - «з питаннями»).
> - `rmdir` - видаляє порожню теку. Назва: remove directory - «прибрати теку».
>
> **Як читати:**
>
> - Слово з мінусом (як `-p` тут) - **прапорець**: уточнює, що саме зробити команді.
> - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
> - Короткі можна склеювати: `-rf` = `-r` і `-f`.
> - Символи `~` `*` `#` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1; `#` - Shift і 3 (в українській розкладці там №)).
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

**Шаблони (wildcards):** `*` - будь-які символи, `?` - один символ.
`ls *.py` - усі файли Python, `cp *.py backup/` - скопіювати всі.

> **Нове тут:**
>
> - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки). `*.py` - лише .py файли: bash сам замінює `*.py` на список таких файлів.
> - `*` (asterisk) - будь-які символи в назві; bash сам замінює `*` на список файлів.

**Головне правило:** у Linux **нема кошика**. `rm` стирає назавжди. Тому:

1. Спершу `ls` з тим самим шаблоном - подивись, що саме видалиш:
   ```bash
   ls *.png        # бачу 3 картинки - ок
   rm *.png
   ```

   > **Нове тут:**
   >
   > - `#` (hash) - коментар: далі до кінця рядка bash не читає.

2. Не використовуй `rm -rf`, поки не розумієш кожну букву. `-r` - теки з усім вмістом,
   `-f` - не питати і не скаржитись. Один зайвий пробіл після тильди (між `~` і `/тека`) - і замість
   однієї теки стирається вся домашня тека. (Це приклад словами, такого не вводь.)
3. Ніколи не запускай `rm` з `sudo` (виконати як адміністратор, день 04), якщо не розумієш навіщо.
4. Важливе - в git (день 9), тоді навіть видалене можна повернути.
5. `cp` і `mv` **мовчки перезаписують** файл з тим самим ім'ям. Додавай `-i`: `cp -i`, `mv -i` - спитає.

   > **Нове тут:**
   >
   > - `rm`: `-f` (`--force`) - не питати і не лаятись, якщо файлу нема (force - «силоміць»).
   > - `cp`: `-i` (`--interactive`) - спитати перед тим, як перезаписати файл, що вже є.
   > - `mv`: `-i` (`--interactive`) - спитати перед тим, як затерти файл з такою самою назвою.

бери в лапки: `cp "Лабораторна 4.pdf" ЛР4/`.

> **Нове тут:**
>

## Тема 3. День 3: Переглянути і редагувати: nano і VS Code

> - `wc` - рахує рядки, слова, символи. Назва: word count - «підрахунок слів»; рахує ще рядки й байти. `-l` (`--lines`) - лише кількість рядків.
>
> **Як читати:**

## Тема 4. День 4: Права і sudo

**Навіщо:** розуміти «Permission denied», запускати свої скрипти і не ламати систему через `sudo`.

### Коротко (5 хв)

**Хто ти:** `whoami` → `evgen`. `id` → твої групи (є `sudo` - значить, можеш бути адміністратором).

**Права файлу** - у `ls -l`:

> **Нове тут:**
>
> - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки). `-l` - докладний список: права, власник, розмір у байтах, дата зміни (long - «довгий»).
>
> **Як читати:**
>
> - Слово з мінусом (як `-l` тут) - **прапорець**: уточнює, що саме зробити команді.
> - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
> - Короткі можна склеювати: `-ld` = `-l` і `-d`.
> - Символи `~` `>` `#` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1; `#` - Shift і 3 (в українській розкладці там №)).
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

```text
-rwxr-xr--  1 evgen evgen  512 Nov 17 10:00 run.sh
│└┬┘└┬┘└┬┘    │     │
│ │  │  │     │     └ група
│ │  │  │     └────── власник
│ │  │  └ інші (others):   r--  лише читати
│ │  └─── група (group):   r-x  читати і запускати
│ └────── власник (user):  rwx  читати, писати, запускати
└──────── тип: - файл, d тека, l посилання
```

r = read (читати), w = write (змінювати), x = execute (запускати; для теки - заходити в неї).

**Числа замість букв:** r = 4, w = 2, x = 1, додаєш для кожної трійки.
`rwx` = 4+2+1 = 7, `r-x` = 4+1 = 5, `r--` = 4. Тому:
- `chmod 755 run.sh` → rwxr-xr-x (скрипт: усі можуть запускати, змінює лише власник);
- `chmod 644 lab.py` → rw-r--r-- (звичайний файл).

> **Нове тут:**
>
> - `chmod` - змінює права файлу: хто може читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. `755` - rwxr-xr-x: 7 = rwx (4+2+1) тобі, 5 = r-x (4+1) групі й іншим; для скриптів і тек - усі читають і запускають, змінюєш лише ти; `644` - rw-r--r--: 6 = rw- (4+2) тобі, 4 = r-- групі й іншим; звичайний файл - ти змінюєш, інші лише читають.

**Простіше буквами:** `chmod +x run.sh` - дозволити запуск, `chmod -w file` - заборонити зміну.

> **Нове тут:**
>
> - `chmod`: `+x` - `+` - додати право, `x` (execute - «виконувати») - запускати файл як програму; без u/g/o - власнику, групі й іншим; `-w` - це НЕ прапорець, а права: забрати w (змінювати) - файл стане лише для читання.

**Запуск свого скрипта:** `./run.sh` (`./` = «з цієї теки»). Без `chmod +x` буде «Permission denied».
Можна і без прав: `bash run.sh`, `python3 lab.py`.

> **Нове тут:**
>
> - `bash` - програма, що читає й виконує твої команди; `bash файл.sh` - з файлу. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»).
> - `python3` - запускає Python: твій файл `.py`, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.

**sudo - «зробити від імені адміністратора (root)».** `sudo apt install ...` спитає **твій** пароль
Ubuntu (символи не видно). Пароль памʼятається ~15 хв.

> **Нове тут:**
>
> - `sudo` - виконує одну команду як адміністратор; спитає твій пароль (видно зірочки). Назва: superuser do - «зроби як суперкористувач» (адміністратор).
> - `apt install` - ставить програму з інтернету; на «Бажаєте продовжити? [Y/n]» - Enter. Назва: `apt` - Advanced Package Tool - «розширений інструмент для пакетів (програм)».

Правила:
- `sudo` - лише для системного: `apt`, файли поза домашньою текою.
- Свої файли (`~/...`) **ніколи** не чіпай через `sudo`: файли стануть власністю root, і потім
  без `sudo` їх не зміниш. Ознака: у `ls -l` власник `root`.
- `sudo pip install` - не роби. Python-пакети для лаб - у venv (день 8).

> **Нове тут:**
>
> - `pip install` - ставить бібліотеку Python (лише у venv). Назва: `pip` - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».

**Особливість WSL:** файли на `/mnt/c` і `/mnt/d` показують права як `rwxrwxrwx` - це диск Windows,
справжні права там вирішує Windows. `chmod` на них зазвичай нічого не змінює.

## Тема 5. День 5: Пакети: apt

### Коротко (5 хв)

`apt` - менеджер пакетів Ubuntu. Пакет = програма або бібліотека.

> **Нове тут:**
>
> - `pip install` - ставить бібліотеку Python (лише у venv). Назва: `pip` - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».

## Тема 6. День 6: Процеси

**Навіщо:** програма з нескінченним циклом (у лабах буває) - її треба вміти зупинити, а не закривати вікно.

### Коротко (5 хв)

Процес = запущена програма. У кожного є номер **PID**.

| Команда / клавіші | Що робить |
|---|---|
| Ctrl+C | зупинити програму, що працює зараз у терміналі |
| Ctrl+D | «кінець вводу»: вийти з `python3` без аргументів, закрити `input()` |
| Ctrl+Z | **призупинити** (не зупинити!) і повернути термінал |
| `jobs` | що призупинено або працює у фоні в цьому терміналі |
| `fg` | повернути призупинене на передній план |
| `bg` | продовжити призупинене у фоні |
| `команда &` | одразу запустити у фоні |
| `ps` | процеси цього терміналу |
| `pgrep -af python` | усі процеси python: PID і команда |
| `ps aux \| grep python` | те саме по-старому (останній рядок - сам grep, його не чіпай) |
| `top` (вийти `q`) або `htop` | живий список: хто їсть процесор і память |
| `kill PID` | попросити процес завершитись |
| `kill -9 PID` | вбити без питань (якщо `kill` не допоміг) |
| `pkill назва` | вбити за назвою програми. Обережно: `pkill python` вбʼє ВСІ python, і ті, що працюють для VS Code |
| `free -h`, `df -h` | скільки памʼяті, скільки місця на диску |

> **Нове тут:**
>
> - `python3` - запускає Python: твій файл `.py`, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
> - `jobs` - показує програми, запущені у фоні чи призупинені в цьому вікні. Назва: jobs - «задачі».
> - `fg` - повертає задачу з фону у вікно. Назва: foreground - «передній план».
> - `bg` - продовжує призупинену (Ctrl+Z) програму у фоні. Назва: background - «задній план, фон».
> - `ps` - показує запущені програми (процеси) та їхні номери (PID). Назва: process status - «стан процесів». `aux` - без дефіса (старий стиль BSD): a - усіх користувачів, u - з власником і %CPU/%MEM, x - і без термінала.
> - `pgrep` - знаходить номери (PID) запущених програм за назвою. Назва: process grep - «grep по процесах». `-a` (`--list-full`) - друкувати поруч з PID повну команду (list full - «повний список»); `-f` (`--full`) - шукати слово в усьому командному рядку, а не лише в назві програми (full - «повний»).
> - `|` (pipe) - вивід лівої команди йде на вхід правої.
> - `grep` - шукає рядки з текстом (у файлах або те, що прийшло через `|`). Назва: g/re/p з редактора ed: global regular expression print - «скрізь знайти шаблон, надрукувати».
> - `top` - живий список програм, що працюють зараз (вийти - q). Назва: top - «верх».
> - `htop` - живий кольоровий список запущених програм; вийти - F10. Назва: h + top: h - Hisham, імʼя автора; top - старший список процесів.
> - `kill` - надсилає програмі сигнал (команду) «зупинись» за її номером PID. Назва: kill - «вбити». `PID` - номер процесу (запущеної програми) з `pgrep -af назва` або `ps aux` (другий стовпець); `-9` - сигнал номер 9, SIGKILL: система вбиває програму одразу, вона не встигне зберегти файли - лише якщо звичайний kill не допоміг.
> - `pkill` - завершує запущені програми за назвою (усі, що підійшли). Назва: process kill - «вбити процес» (за назвою, а не за номером).
> - `free` - показує памʼять: скільки зайнято і доступно. Назва: free - «вільна» (скільки вільної памʼяті). `-h` (`--human`) - зручні одиниці Ki, Mi, Gi замість кілобайтів (human - «для людини»).
> - `df` - показує вільне місце на дисках. Назва: disk free - «вільне на диску». `-h` (`--human-readable`) - розміри в K, M, G замість кілобайтних блоків (human-readable).
>
> **Як читати:**
>
> - Слово з мінусом (як `-h` тут) - **прапорець**: уточнює, що саме зробити команді.
> - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
> - Короткі можна склеювати: `-af` = `-a` і `-f`.
> - Символи `~` `|` `>` `&` `#` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1; `|` - Shift і клавіша `\`; `#` - Shift і 3 (в українській розкладці там №)).
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

Ubuntu також сама вимикається за кілька секунд, коли закриті всі її вікна - тоді все, що в ній працювало, теж зупиняється.

## Тема 7. День 7: Пайпи, перенаправлення, grep

**Навіщо:** знайти, де в лабах функція, зберегти вивід у файл, порахувати рядки - однією командою.

**Перенаправлення:**

| Запис | Що робить |
|---|---|

> - `grep` - шукає рядки з текстом (у файлах або те, що прийшло через `|`). Назва: g/re/p з редактора ed: global regular expression print - «скрізь знайти шаблон, надрукувати».
>
> **Як читати:**
>
> - Слово з мінусом (як `-l` тут) - **прапорець**: уточнює, що саме зробити команді.

**grep - знайти рядки з текстом:**

| Команда | Що |
|---|---|
| `grep "def " lab.py` | рядки з `def ` |
| `grep -n` | з номерами рядків |
| `grep -i` | без різниці великі/малі |
| `grep -r "turtle" .` | у всіх файлах теки і підтек |
| `grep -c` | лише кількість рядків |
| `grep -v` | рядки, де цього **нема** |

> **Нове тут:**
>
> - `grep`: `-n` (`--line-number`) - показати номер рядка перед кожним збігом (line number - «номер рядка»); `-i` (`--ignore-case`) - без різниці між великими й малими літерами (ignore case - «не зважати на регістр»); `-r` (`--recursive`) - шукати в усіх файлах теки і підтек (recursive - «рекурсивно», углиб); `.` - з -r: шукати в поточній теці і всіх підтеках; `-c` (`--count`) - не показувати рядки, а лише порахувати, скільки їх зі збігом (count - «порахувати»); `-v` (`--invert-match`) - навпаки: рядки, де шаблону НЕМА (invert - «перевернути»).

**Як перевіряти doctest у лабах.** У заготовках викладача в кінці файлу стоїть `doctest.testmod()`.

| Команда | Коли |
|---|---|
| `python lab4.py` | як задумав викладач: `testmod()` у файлі проганяє doctest. Тиша = все пройшло, `***Test Failed***` = ні. Далі програма працює як звичайно (питає `input()`, малює) |
| `python lab4.py -v` | те саме з подробицями (`-v` бачить `testmod()`), унизу `Test passed.` |
| `python -m pytest --doctest-modules -q lab4.py` | надійна перевірка: `1 passed` або `FAILED` і код помилки (зручно в скриптах) |
| `perevir lab4.py` | наша команда: doctest (через pytest) + flake8 + mypy |

> **Нове тут:**
>
> - `perevir` - перевіряє лабу всіма інструментами одразу (doctest, стиль, типи).

**Пастка: не запускай `python -m doctest lab4.py` для таких файлів.** Коли в файлі є `doctest.testmod()`
не під `if __name__ == "__main__":`, команда `-m doctest` змушує його перевіряти ще й сам модуль doctest, і ти
побачиш чужу помилку `1 of 21 in __main__.DebugRunner ***Test Failed***`, хоча твій код правильний.
`python -m doctest` годиться лише для файлів, де `testmod()` нема або він під `if __name__ == "__main__":`.

Стиль: `flake8 --max-line-length=78 lab4.py` (викладач просив рядки до 78), `mypy lab4.py` (типи, знаходить
`str` замість `int`), `black -l 78 lab4.py` (сам переформатує файл, перед цим зроби коміт або копію).

> **Нове тут:**
>
> - `flake8` - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. `--max-line-length` - найбільша довжина рядка; викладач хоче 78.

Вимоги викладача (з файлу «Вимоги викладача»): лаба зарахована, коли проходять **усі doctest**;
функція повертає через `return`, а не друкує; код - у наданій функції, назви і doctest не міняти;
перед здачею flake8, pycodestyle, mypy, ruff або black.

**Якщо в лабі є `input()` на верхньому рівні файлу** (як у твоїй ЛР3), то pytest скаже «reading from stdin»
(а `perevir` підкаже, що робити). Тоді: `printf "5\n" | python lab.py` - `testmod()` усередині спрацює, а ввід
піде з printf.

> **Нове тут:**
>

> - `"..."` (double quotes) - усе між лапками - одне слово, навіть з пробілами.

**turtle (ЛР4) у WSL:** на Windows 11 і Windows 10 збірки 19044+ (з WSL з Microsoft Store) вікно відкривається
як звичайне вікно Windows. Наприкінці потрібен `turtle.done()`, інакше вікно одразу закриється (так і в методичці ЛР4).

Кириличні назви файлів `git status` може показувати як `\320\233\320\240...`. Лікується один раз:
`git config --global core.quotepath false` (скрипт установки це вже зробив).

### Типові помилки

- `Author identity unknown` при коміті - не зроблено `git config --global user.name/email`.
- `git commit` без `-m` - відкриється редактор (nano або vim). З vim вийти: Esc, потім `:q!` і Enter.
- Забув `git add` - коміт «nothing to commit» або без потрібного файлу. Дивись `git status`.
- `git init` у домашній теці `~` - тоді git бачить усе підряд. Роби в теці конкретної лаби.
- Додав `.venv` у git - тисячі файлів. Спершу `.gitignore`.
- `git restore` назавжди скасовує **незакомічені** зміни файлу. Перед ним глянь `git diff`.

### Самоперевірка

1. Яка послідовність команд зберігає зміни у git?
2. Як подивитися, що змінилося з останнього коміту?
3. Ти зіпсував `lab.py` і ще не комітив. Як повернути?
4. Навіщо `.gitignore` і що в нього писати для Python?
5. Що означає `Author identity unknown`?

<details markdown="1"><summary>Відповіді</summary>

1. `git add файл` (або `git add .`), потім `git commit -m "опис"`.
2. `git diff` (а `git status` - які файли).
3. `git restore lab.py` - файл стане таким, як в останньому коміті.
4. Щоб git не зберігав зайве: `.venv/`, `__pycache__/`, картинки-результати.
5. git не знає імені та пошти автора. `git config --global user.name "Твоє Імʼя Прізвище"` і `user.email "..."`.

</details>

## Тема 10. День 10: Свій bash-скрипт

**Навіщо:** команди, які вводиш щоразу перед здачею лаби, - в один файл і запускати одним словом.

### Коротко (5 хв)

Bash-скрипт - текстовий файл з командами, по одній на рядок. Те саме, що вводиш руками.

```bash
#!/bin/bash
# перший рядок (shebang): яким інтерпретатором запускати
# усе після # - коментар

name="Студент"                 # змінна: БЕЗ пробілів навколо =
echo "Привіт, $name"         # $name - взяти значення

echo "Перший аргумент: $1"   # $1, $2 - те, що написали після назви скрипта
echo "Усього аргументів: $#"

if [ -f "$1" ]; then         # -f: такий файл існує
    echo "Файл $1 є"
else
    echo "Файлу $1 нема"
fi

for f in *.py; do            # цикл по всіх .py у теці
    echo "Знайшов: $f"
done
```

> **Нове тут:**
>
> - `#` (hash) - коментар: далі до кінця рядка bash не читає.
> - `"..."` (double quotes) - усе між лапками - одне слово, навіть з пробілами.
> - `echo` - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.
> - `$ЗМІННА` (dollar) - бере значення змінної (назви, під якою bash тримає текст).
> - `[` - перевіряє умову: чи є тека, чи рівні числа тощо. Назва: [ - друга назва команди test («перевірити»); ] лише закриває умову. `-f` - правда, якщо є такий звичайний файл (file - «файл»); `]` - закриває умову, обовʼязково останнім словом і через пробіл.
> - `;` (semicolon) - розділяє команди в рядку, виконує всі по черзі.
> - `*` (asterisk) - будь-які символи в назві; bash сам замінює `*` на список файлів.
>
> **Як читати:**
>
> - Слово з мінусом (як `-f` тут) - **прапорець**: уточнює, що саме зробити команді.
> - Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
> - Короткі можна склеювати: `-la` = `-l` і `-a`.
> - Символи `~` `|` `>` `&` `*` `#` набирай в англійській розкладці (`~` - Shift і клавіша ліворуч від 1; `|` - Shift і клавіша `\`; `#` - Shift і 3 (в українській розкладці там №)).
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

| Перевірка в `[ ]` | Що означає |
|---|---|
| `-f файл` | файл існує |
| `-d тека` | тека існує |
| `-z "$x"` | рядок порожній |
| `"$a" = "$b"` | рядки рівні |
| `$n -gt 5` | число більше 5 (`-lt` менше, `-eq` дорівнює) |

`$?` - код завершення останньої команди: 0 = успіх, не 0 = помилка. `set -e` на початку скрипта -
зупинитись на першій помилці.

> **Нове тут:**
>
> - `set` - вмикає суворий режим: скрипт зупиняється на першій помилці. Назва: set - «встановити» (налаштування самого bash). `-e` - зупинити скрипт, щойно якась команда впала (errexit - «вийти при помилці»).

**Запуск:** `bash skrypt.sh` або `chmod +x skrypt.sh` і `./skrypt.sh`.

> **Нове тут:**
>
> - `bash` - програма, що читає й виконує твої команди; `bash файл.sh` - з файлу. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»).
> - `chmod` - змінює права файлу: хто може читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. `+x` - `+` - додати право, `x` (execute - «виконувати») - запускати файл як програму; без u/g/o - власнику, групі й іншим.

**Alias** - коротке імʼя для команди, у `~/.bashrc`: `alias ll='ls -la'`. Після правки `source ~/.bashrc`.
Так зроблені наші `univer` і `perevir` (подивись: `tail -n 25 ~/.bashrc`).

> **Нове тут:**
>
> - `alias` - дає коротке імʼя (аліас) довгій команді. Назва: alias - «псевдонім, інше імʼя».
> - `'...'` (single quotes) - текст буквально: `$`, `*` і пробіли всередині - звичайні символи.
> - `source` - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». `~/.bashrc` - перечитати свої налаштування після правки, без нового вікна.
> - `~` (tilde) - твоя домашня тека, /home/evgen.
> - `tail` - показує останні рядки (файлу чи того, що прийшло через `|`). Назва: tail - «хвіст». `-n` (`--lines`) - скільки останніх рядків показати: `-n 3`, коротко `-3` (lines - «рядки»).

### Руками (10 хв): скрипт «перевір усі лаби в теці»

```bash
cd ~/univer/praktyka
nano zdaty.sh
```

> **Нове тут:**
>
> - `cd` - переходить в іншу теку. Назва: change directory - «змінити теку».
> - `nano` - простий редактор файлів у терміналі. Назва: nano - жарт з одиницями: наступник редактора pico (піко < нано).

Надрукуй:
```bash
#!/bin/bash
# zdaty.sh - перевірити всі .py у теці перед здачею
# запуск: ./zdaty.sh ~/univer/labs/ЛР4

folder="${1:-.}"          # якщо теку не дали - поточна
source ~/univer/.venv/bin/activate

if [ ! -d "$folder" ]; then
    echo "Нема теки $folder"
    exit 1
fi

ok=0
bad=0
for f in "$folder"/*.py; do
    if python -m pytest --doctest-modules -q -p no:cacheprovider "$f" < /dev/null > /dev/null 2>&1 && flake8 --max-line-length=78 "$f" > /dev/null; then
        echo "ГОТОВО  $f"
        ok=$((ok + 1))
    else
        echo "ПРАВИТИ $f"
        bad=$((bad + 1))
    fi
done
echo "Готово: $ok, правити: $bad"
```

> **Нове тут:**
>
> - `$( )` (command substitution) - підставляє вивід команди в рядок.
> - `source`: `~/univer/.venv/bin/activate` - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
> - `[`: `-d` - правда, якщо є така тека (directory - «тека»); `!` - заперечення: [ ! -d тека ] - правда, якщо теки НЕМА.
> - `exit` - закінчує скрипт або закриває термінал; число - код виходу (0 - успіх). Назва: exit - «вихід». `1` - «щось не так» - найчастіший код помилки.
> - `python3 -m pytest` - проганяє тести (приклади `>>>`) і чесно каже: усе пройшло чи ні. Назва: py + test - «тести для Python». `--doctest-modules` - шукати doctest (приклади `>>>`) у файлах `.py`; без нього pytest шукає лише функції `test_`; `-q` (`--quiet`) - коротко: крапка за кожен тест і рядок підсумку «1 passed in 0.01s» (quiet - «тихо»); `-p` - увімкнути або вимкнути додаток pytest; `-p no:cacheprovider` - не створювати теку `.pytest_cache` (plugin - «додаток»).
> - `>` (redirect) - пише вивід у файл, старий вміст стирає.
> - `flake8` - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. `--max-line-length` - найбільша довжина рядка; викладач хоче 78.
> - `python3` - запускає Python: твій файл `.py`, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. `-m` - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. `python3 -m venv` (module - «модуль»).

Далі:
```bash
chmod +x zdaty.sh
./zdaty.sh ~/univer/labs/ЛР4      # kvadrat.py з дня 8 - ГОТОВО
./zdaty.sh /nema                   # Нема теки /nema
echo $?                            # 1 - скрипт повідомив про помилку
```

> **Нове тут:**
>
> - `./скрипт` - запускає програму за шляхом до її файлу, напр. `./файл.sh`. Назва: ./ - «звідси».

Хочеш запускати звідусіль словом `zdaty`: додай у кінець `~/.bashrc` рядок
`alias zdaty='~/univer/praktyka/zdaty.sh'` і виконай `source ~/.bashrc`.

### Типові помилки

- `name = "Студент"` з пробілами - bash думає, що `name` це команда: `name: command not found`.
- `$1` без лапок: шлях з пробілом розвалиться на два аргументи. Пиши `"$1"`, `"$f"`.
- `[` без пробілів: `if [-f "$1"]` - помилка. Потрібно `if [ -f "$1" ]`.
- Скрипт, збережений з CRLF (Блокнот Windows) → `$'\r': command not found`. День 3.
- Забув `chmod +x` → `Permission denied`. Або запускай `bash zdaty.sh`.
- Лаба з `input()` на верхньому рівні вийде «ПРАВИТИ» (pytest не дає їй читати клавіатуру) - таку перевір
  руками: `printf "5\n" | python лаба.py`, як у дні 8.

  > **Нове тут:**
  >
  > - `printf` - друкує текст; `\n` у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  > - `|` (pipe) - вивід лівої команди йде на вхід правої.
