### Завдання 1. Робоче місце для нової лаби за 5 хвилин

Викладач дав заготовку `lab5.py` (вона в тебе в «Завантаженнях» Windows). Треба: тека для лаби в Linux,
git з `.gitignore`, заготовка всередині, перевірка doctest і перший коміт «Заготовка».

<details markdown="1"><summary>Розвʼязок</summary>

```bash
mkdir -p ~/univer/labs/ЛР5
cd ~/univer/labs/ЛР5
ls /mnt/c/Users                              # дізнатись своє імʼя Windows
cp /mnt/c/Users/IMYA/Downloads/lab5.py .      # IMYA - твоє імʼя Windows (без апострофа!), крапка = сюди
git init
printf '.venv/\n__pycache__/\n*.png\n' > .gitignore
univer                                        # увімкнути venv (перейде в ~/univer)
cd -                                          # назад у ЛР5
python lab5.py                                # заготовка: doctest падають - функції ще порожні, це нормально
git add .
git commit -m "Заготовка"
git log --oneline
```

> **Нове тут:**
>
> - `mkdir` - створює нову теку. Назва: make directory - «зробити теку». `-p` - створює і всі проміжні теки шляху; якщо тека вже є - мовчить, без помилки.
> - `cd` - переходить в іншу теку. Назва: change directory - «змінити теку». `-` - туди, де був перед цим (і друкує цей шлях); ще раз cd - - назад.
> - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки).
> - `cp` - копіює файл або теку. Назва: copy - «копіювати». `.` - «сюди», у поточну теку: cp ~/Завантаження/lab1.py .
> - `git init` - робить теку репозиторієм git (створює .git). Назва: init - від initialize, «почати, підготувати».
> - `printf` - друкує текст за шаблоном; \n - Enter. Назва: print formatted - «надрукувати за шаблоном».
> - `univer` - переходить у ~/univer і вмикає venv. Назва: наша назва: «універ» - тека ~/univer для навчання.
> - `python3` - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
> - `git add` - додає зміни файлу в наступний коміт (індекс). Назва: add - «додати» (в індекс, тобто в наступний коміт). `.` - усе в поточній теці і підтеках; спершу глянь git status, щоб не додати зайве.
> - `git commit` - зберігає знімок змін з індексу в історію. Назва: commit - «зафіксувати»: зберегти знімок змін в історію. `-m` - повідомлення коміту одразу в команді; без -m відкриється nano.
> - `git log` - показує історію комітів, новий зверху. Назва: log - «журнал»: історія комітів. `--oneline` - по рядку на коміт: 7 знаків хешу і перший рядок повідомлення.
> - `~` - домашня тека /home/evgen. Назва: tilde («тильда») - домашня тека.
> - `'...'` - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».
> - `>` - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.
> - `"..."` - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».
> - `#` - коментар: далі до кінця рядка bash не читає. Назва: hash («решітка») - коментар.
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).
Чому так: заготовку комітимо до правок, щоб завжди можна було побачити `git diff`, що саме ти змінив,
і повернутись до оригіналу (вимога викладача - не міняти назви, параметри і doctest заготовки).

### Завдання 2. Огляд усіх лаб однією-двома командами

У теці з лабами (`~/univer/labs` або `~/univer/prog/Лабораторні`) дізнайся:
а) які файли використовують `doctest`; б) скільки функцій у кожному `.py`;
в) скільки рядків довші за 78 символів (викладач за це чіпляється) у кожному файлі.

<details markdown="1"><summary>Розвʼязок</summary>

```bash
cd ~/univer/labs
grep -rl "import doctest" --include="*.py" .          # а) лише імена файлів
grep -c "^def " *.py                                   # б) файл:кількість (функції верхнього рівня)
univer; cd -
flake8 --select=E501 --max-line-length=78 *.py | cut -d: -f1 | sort | uniq -c   # в)
```

> **Нове тут:**
>
> - `grep` - знаходить рядки з текстом у файлах. Назва: g/re/p з редактора ed: «знайти регулярний вираз у всьому файлі і надрукувати». `-r` - шукати в усіх файлах теки і підтек (recursive); `-l` - лише назви файлів, де є збіг (list); `--include` - з -r: шукати лише у файлах за шаблоном, --include="*.py"; `.` - з -r: шукати в поточній теці і всіх підтеках; `-c` - лише порахувати рядки зі збігом у кожному файлі (count).
> - `flake8` - перевірка стилю і зайвого коду (команда з venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. `--select` - перевіряти лише ці коди помилок, напр. --select E501 - лише задовгі рядки; `--max-line-length` - найбільша довжина рядка; викладач хоче 78.
> - `cut` - вирізає з рядків потрібні стовпці. Назва: cut - «вирізати»: взяти шматок кожного рядка. `-f` - які поля взяти: -f1 або -f1,6,7 або -f2-4.
> - `sort` - впорядковує рядки. Назва: sort - «сортувати, впорядкувати».
> - `uniq` - склеює однакові сусідні рядки (з -c - рахує). Назва: unique - «єдиний, неповторний»: прибрати повтори. `-c` - писати перед рядком, скільки разів він ішов підряд.
> - `*` - шаблон: будь-які символи в назві файлу. Назва: asterisk («зірочка») - шаблон «будь-які символи».
> - `;` - розділяє команди в рядку, виконує всі по черзі. Назва: крапка з комою - роздільник команд.
> - `|` - передає вивід однієї команди на ввід іншій. Назва: pipe - «труба» (пайп), вертикальна риска.
Пояснення в): flake8 друкує `файл:рядок:колонка: E501 line too long`, `cut -d: -f1` лишає імʼя файлу,
`sort | uniq -c` рахує, скільки разів кожне імʼя. Якщо файл не надрукувався - довгих рядків нема.
Напр. на твоєму ПК у `ЛР2_завдання3_body_moving.py` один такий рядок (19, 192 символи) - це рядок doctest
з довгим очікуваним результатом. Doctest викладача не міняй; якщо треба, спитай, чи це рахується.

</details>

### Завдання 3. Скрипт «зібрати лабу на здачу»

Викладач просить папку з назвою «прізвище, ім'я, група, рік». Напиши `zibraty.sh`: бере теку лаби, перевіряє
кожен `.py` (doctest + flake8 78), і якщо **всі** готові - копіює їх у теку `Прізвище_Імʼя_Група_2026`
і робить zip-архів, усередині якого саме ця тека з файлами. Якщо хоч один не готовий - нічого не збирає і пише, який саме.

<details markdown="1"><summary>Розвʼязок</summary>

```bash
#!/bin/bash
# zibraty.sh - зібрати лабу на здачу
# запуск: ./zibraty.sh ~/univer/labs/ЛР4

lab="$1"
if [ ! -d "$lab" ]; then
    echo "Дай теку лаби: ./zibraty.sh ~/univer/labs/ЛР4"
    exit 1
fi
source ~/univer/.venv/bin/activate

bad=0
for f in "$lab"/*.py; do
    if ! python -m pytest --doctest-modules -q -p no:cacheprovider "$f" < /dev/null > /dev/null 2>&1; then
        echo "doctest не проходить: $f"
        bad=1
    fi
    if ! flake8 --max-line-length=78 "$f" > /dev/null; then
        echo "flake8 має зауваження: $f"
        bad=1
    fi
done
if [ "$bad" = 1 ]; then
    echo "Не збираю - спершу виправ."
    exit 1
fi

name=$(basename "$lab")                       # ЛР4
out="$HOME/univer/zdacha/$name/Прізвище_Імʼя_Група_2026"
mkdir -p "$out"
cp "$lab"/*.py "$out"/
cd "$HOME/univer/zdacha/$name"
python -m zipfile -c "${name}.zip" "Прізвище_Імʼя_Група_2026"
echo "Готово: $HOME/univer/zdacha/$name/${name}.zip"
```

> **Нове тут:**
>
> - `[` - перевіряє умову: код 0 - так, 1 - ні. Назва: [ - друга назва команди test («перевірити»); ] лише закриває умову. `-d` - правда, якщо є така тека (directory); `!` - заперечення: [ ! -d тека ] - правда, якщо теки НЕМА; `]` - закриває умову, обовʼязково останнім словом і через пробіл; `=` - рядки однакові: `[ "$a" = "$b" ]`; `!=` - різні.
> - `echo` - друкує текст і значення змінних. Назва: echo - «луна»: повторює те, що йому дали.
> - `exit` - виходить зі скрипта або термінала з кодом. Назва: exit - «вихід». `1` - «щось не так» - найчастіший код помилки.
> - `source` - виконує файл у поточному bash (venv, ~/.bashrc). Назва: source - «джерело»: виконати команди з файлу-джерела. `~/univer/.venv/bin/activate` - увімкнути venv для лаб; вимкнути - deactivate.
> - `basename` - дає назву файлу без шляху. Назва: base name - «основна назва»: остання частина шляху.
> - `python3`: `-m` - запусти модуль як програму: python3 -m pytest, python3 -m venv, python3 -m pdb.
> - `python3 -m zipfile` - робить і розпаковує .zip засобами Python. Назва: zipfile - модуль стандартної бібліотеки Python, запущений як програма (-m). `-c` - створити архів з файлів і тек (теки - з усім вмістом).
> - `$ЗМІННА` - підставляє значення змінної. Назва: dollar («долар») - «значення змінної».
> - `2>&1` - помилки йдуть разом зі звичайним виводом. Назва: «потік 2 туди ж, куди потік 1»: помилки разом зі звичайним виводом.
> - `<` - подає файл програмі замість клавіатури. Назва: input redirect - «ввід з файлу».
> - `$( )` - підставляє вивід команди в рядок. Назва: command substitution - «підстановка команди».
Запуск: `chmod +x zibraty.sh`, потім `./zibraty.sh ~/univer/labs/ЛР4`. Архів відкрити в Провіднику:
`cd ~/univer/zdacha/ЛР4 && explorer.exe .` (саме так, з `cd`: Linux-шлях аргументом Провідник не розуміє).

Що тут нового: `basename` бере останню частину шляху; `$HOME` - те саме, що `~`, але працює в лапках;
`python -m zipfile -c` робить zip без встановлення програми `zip`, але кладе в архів лише ОСТАННЮ теку
шляху. Тому скрипт заходить (`cd`) туди, де лежить `Прізвище_Імʼя_Група_2026`, і пакує саме її - так назва
теки в архіві збережеться (перша версія цього розвʼязку губила її, знайшла перевірка).
Doctest тут через pytest (`python -m pytest --doctest-modules`), а не `python -m doctest` - день 8, «пастка».
Увага: лабу з `input()` на верхньому рівні pytest не перевірить (не дає читати клавіатуру) - вона піде в
«doctest не проходить»; таку перевір руками з вводом, як у дні 8.

</details>
