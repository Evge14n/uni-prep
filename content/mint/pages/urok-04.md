### Крок 3. Дістати заготовки з `.ipynb`

`.ipynb` - це JSON (текстовий формат запису даних: списки `[...]` і пари «назва: значення» у `{...}`; Python читає
його модулем `json`): текст і код лежать у «клітинках». Дві короткі функції bash: `klityny` показує список
клітинок, `klitynka` друкує одну клітинку. Скопіюй обидва рядки в термінал (вставка - Ctrl+Shift+V):

```bash
klityny() { python3 -c 'import json, sys; [print(i, c["cell_type"], "".join(c["source"])[:45].split("\n")[0]) for i, c in enumerate(json.load(open(sys.argv[1]))["cells"])]' "$1"; }
klitynka() { python3 -c 'import json, sys; print("".join(json.load(open(sys.argv[1]))["cells"][int(sys.argv[2])]["source"]))' "$1" "$2"; }
```

Подивись, які клітинки є:

```bash
klityny Лабораторна_робота_1_Пайтон,_2026_2027.ipynb
```

```text
0 markdown # Лабораторна робота 1
1 markdown ## Теоретична частина
2 markdown ## Практична частина
3 markdown ### **Завдання 1. Операції з цифрами тризначн
4 code import doctest
5 markdown ### **Завдання 2. Визначення тривалості космі
6 code import doctest
7 markdown ### **Завдання 3. Формування суми покупки дос

```

Клітинки `code` 4, 6, 8 - це заготовки трьох завдань. Знак `>` пише вивід команди у файл:


### Крок 4. Відкрий файл у nano і подивись на будову

```bash
nano lr1_1.py
```

| Клавіші nano | Що роблять |
|---|---|
| Ctrl+O, потім Enter | зберегти |
| Ctrl+X | вийти (якщо не зберіг - спитає: Y зберегти, N ні) |
| Ctrl+K / Ctrl+U | вирізати рядок / вставити |
| Ctrl+W | пошук |
| Ctrl+/ | перейти до рядка за номером (зручно, коли Python каже «line 39») |
| Alt+U | скасувати останню дію |

Будова файлу, яку чекає викладач (заготовка вже так зроблена, ти дописуєш лише позначене):

```text
import doctest                                   ← як у заготовці


def number_operations(number: int) -> str:      ← назву і параметри НЕ міняти
    """
    опис і doctest викладача                     ← НЕ міняти жодного символу
    """
    твій код: обчислення                         ← пишеш ти
    return результат                             ← один рядок-результат


number = int(input("Enter number: "))           ← введення: пишеш ти (int, бо input дає str)

print(number_operations(number))                ← виклик із заготовки, обгорнутий у print

doctest.testmod()                                ← як у заготовці
```

Дві речі в заготовці треба знати:

- у завданнях 1 і 2 викладач викликає функцію без `print` - результат тоді нікуди не виводиться. Умова каже
  «вивести», тому обгорни виклик у `print(...)`, як у заготовці завдання 3;
- `doctest.testmod()` стоїть унизу файлу, без `if __name__ == "__main__":`. У ЛР1 так і залиш: `if`
  заборонений, а викладач дав саме таку заготовку.

Відступ усередині функції - 4 пробіли (з Кроку 0 Tab сам ставить 4 пробіли).

### Крок 5. Перший запуск - побач, що все червоне, і це нормально

Збережи і вийди (Ctrl+O, Enter, Ctrl+X). Запусти заготовку, поки ти ще нічого не дописав:

```bash
python3 lr1_1.py
```

```text
NameError: name 'number' is not defined
```

Python дійшов до рядка `number_operations(number)`, а змінної `number` ще нема - бо ще нема введення.
Допиши рядок з `input` і `print(...)` навколо виклику (як у схемі вище). Функцію поки не чіпай. Запусти знову.
Програма чекає числа - набери `127` і Enter. Або подай число одразу, без набору, через `printf`:

```bash
printf "127\n" | python3 lr1_1.py
```

```text
Enter number: None
**********************************************************************
File "/home/evgen/univer/labs/lr1/lr1_1.py", line 13, in __main__.number_operations
Failed example:
    number_operations(124)
Expected:
    'The sum of digits of the number 124 is 7;\nthe absolute value of the difference of the number and reversed number is 297;\nthe fraction of the number 124 and the sum of its digits is 17.714.'
Got nothing
```

і в кінці:

```text
1 items had failures:
   5 of   5 in __main__.number_operations
***Test Failed*** 5 failures.
```

Як це читати:

- `Enter number: ` - підказка з твого `input`. Число прийшло з `printf`, тому на екрані його нема, і текст
  програми йде в тому самому рядку - так і має бути;
- `None` - функція ще нічого не повертає (`return` нема), а `print` надрукував це «нічого»;
- `File "/home/evgen/..."` - повний шлях до файлу; у тебе замість `evgen` буде твій логін;
- `Failed example` - який виклик з doctest не пройшов, `line 13` - де він у файлі;
- `Expected` - що мало бути, `Got` - що вийшло насправді (`Got nothing` = функція повернула `None`);
- `5 of 5` - не пройшли всі 5 прикладів. Твоя мета - щоб цей звіт зник.

Це і є «спершу тест, потім код» (про це говорив викладач): doctest уже написані, ти дописуєш функцію, доки
вони не позеленіють.

**Завдання 1.**

- Ідея: цифри дістають арифметикою, без перетворення на рядок. Остання цифра - `% 10`, число без останньої

- «Навпаки» - це нове число з тих самих цифр: кожна цифра множиться на свій розряд (100, 10, 1).

- Без `if` Python рахує всі частини виразу, навіть для «поганого» числа. Перевір руками `printf "0\n"`: якщо

```python
eggs = 40
boxes_12 = 2

```

## Передбач, потім запусти

Спершу скажи (або запиши) відповідь, потім запусти рядок у терміналі.

1. Скільки буде остача і ціла частка для відʼємного числа?

```bash
python3 -c 'print(-124 % 10, -124 // 100)'
```

<details markdown="1"><summary>Відповідь</summary>

```text
6 -2
```

Не `4` і не `-1`: у Python `//` округлює вниз (до мінус нескінченності), а `%` має знак дільника.
Тому з відʼємним числом «цифри» виходять дивні - ось чому завдання 1 спершу перевіряє, чи число додатне.
</details>

2. `round` чи формат?

```bash
python3 -c 'print(round(44.0, 3), f"{44.0:.3f}")'
```

<details markdown="1"><summary>Відповідь</summary>

```text
44.0 44.000
```

`round` змінює число, а нулі в кінці число не зберігає. Формат `:.3f` керує тим, як число **показати** -
три знаки завжди. Doctest для 792 чекає `44.000`.
</details>

3. Що дасть рядок, помножений на умову?

```bash
python3 -c 'print(repr("Correct" * (7 > 3)), repr("Correct" * (7 < 3)))'
```

<details markdown="1"><summary>Відповідь</summary>

```text
'Correct' ''
```

`True` поводиться як 1, `False` як 0. Рядок × 1 = той самий рядок, рядок × 0 = порожній рядок. Це прийом
з с. 7-8 замість `if`.
</details>

4. Що виведе програма, якщо ввести 5?

```bash
printf "5\n" | python3 -c 'x = input("x = "); print(x * 3)'
```

<details markdown="1"><summary>Відповідь</summary>

```text
x = 555
```

`input` завжди повертає рядок. `"5" * 3` - це рядок, повторений тричі, а не 15. Тому `int(input(...))`.
</details>

5. Чому в doctest `\n`, а на екрані перенос рядка?

```bash
python3 -c 'print(repr("a\nb")); print("a\nb")'
```

<details markdown="1"><summary>Відповідь</summary>

```text
'a\nb'
a
b
```

Doctest показує результат функції так, як його показує інтерактивний Python - через `repr`: у лапках і з `\n`.
`print` друкує той самий рядок «по-людськи». Тому твоя функція повертає рядок з `\n`, а doctest порівнює
його `repr`.
</details>

## Коли помиляється doctest викладача

Викладачі просили: знайдеш помилку в doctest - надішли їм список. Як відрізнити «у мене баг» від «у doctest
помилка»: **перерахуй `Expected` руками**. Якщо очікуваний результат суперечить самій умові - це doctest.

**Завдання 3, приклади 2 і 3.** Код, що чесно робить «від найбільшого номіналу, `min()` на кожному кроці»,
проходить приклади 1 і 4 і падає на 2 і 3:

```text
4 tests in 2 items.
2 passed and 2 failed.
***Test Failed*** 2 failures.
```

Перевір арифметикою сам `Expected` з doctest:

```text
Приклад 2: ціна 1245, Expected: 500×2 + 100×2 + 50×1 + 20×2 + 10×0 + 5×1 + 1×0
         = 1000 + 200 + 50 + 40 + 0 + 5 + 0 = 1295 грн  > 1245, а залишок 0?
         Узяли на 50 грн більше, ніж треба. Умова: «не перевищує суму, яку ще треба сплатити».

Приклад 3: ціна 137, Expected: 50×2 + 20×1 + 10×1 + 5×0 + 1×2 = 132 грн,
         137 - 132 = 5, а Expected каже «Remaining amount: 0 UAH.»
```

Якщо у твоєму `Got` для прикладу 2 стоїть `50: 0 banknotes`, а для прикладу 3 - `Remaining amount: 5 UAH.`,
а всі інші приклади проходять - код правильний, помилка в doctest. Не підганяй код під помилковий doctest і
не міняй doctest сам: напиши викладачу ці два розрахунки.

**Файл `lab1_doctests.py` з чату, завдання 1** (його краще не брати, Крок 3):

- рядок з `return` - недописана чернетка, файл не запускається:

```text
SyntaxError: f-string: valid expression required before '}'
```

- doctest для 124 і 792 розірвані через `\` на два рядки. Навіть з правильним кодом doctest падає:

```text
ValueError: line 11 of the docstring for __main__.number_operations has inconsistent leading whitespace: "the fraction of the number 124 and the sum of its digits is 17.714.'"
```

У `.ipynb` і PDF ці doctest цілі, в один рядок - тому заготовки беремо звідти.

**Дрібниці в заготовках:** у завданнях 1 і 2 виклик функції без `print` (нічого не виводиться); рядки doctest
довші за 78 символів (п. 12 вище); у docstring завдання 1 «порожні» рядки з пробілами (flake8 `W293`) - їх
прибирає black, doctest від цього не змінюються.

## Перевір перед здачею

Для кожного файлу - той самий набір. Приклад для `lr1_1.py`:

```bash
cd ~/univer/labs/lr1
source ~/univer/.venv/bin/activate
printf "127\n" | python3 lr1_1.py -v | tail -n 3
printf "127\n" | python3 -m pytest --doctest-modules -q -s lr1_1.py
python3 -m black -l 78 lr1_1.py
python3 -m flake8 --max-line-length=78 lr1_1.py
python3 -m pycodestyle --max-line-length=78 lr1_1.py
python3 -m ruff check lr1_1.py
python3 -m mypy lr1_1.py
```

Що має бути (вивід з тестової Mint 22.3, на правильному коді):

```text
5 passed and 0 failed.
Test passed.
...
1 passed in 0.02s
...
reformatted lr1_1.py
...
lr1_1.py:14:79: E501 line too long (198 > 78 characters)
lr1_1.py:17:79: E501 line too long (199 > 78 characters)
lr1_1.py:26:79: E501 line too long (198 > 78 characters)
...
All checks passed!
Success: no issues found in 1 source file
```

- `1 passed` у pytest - весь docstring з усіма прикладами пройшов (pytest рахує docstring як один тест).
  Час (`0.02s`) у тебе буде інший;
- black пише `reformatted`, якщо щось поправив, або `1 file left unchanged`, якщо нічого;
- `E501` лише в рядках 14, 17, 26 - це doctest викладача (п. 12 «Типових помилок»). У `lr1_2.py` таких рядків
  пʼять (12, 15, 18, 21, 24), у `lr1_3.py` - пʼять (15 - опис функції, 18, 21, 24, 27). Будь-який інший номер
  рядка - вже твій, виправ;
- pycodestyle показує ті самі `E501`, ruff - `All checks passed!`, mypy - `Success`.

Для інших файлів зміни лише `printf`: `printf "93784\n"` для `lr1_2.py`, `printf "534\n1\n3\n2\n3\n5\n2\n10\n"`
для `lr1_3.py`. У `lr1_3.py` pytest покаже `1 failed` - через два doctest викладача (див. розділ вище); переконайся,
що падають рівно приклади 2 і 3 з тим самим `Got`.

Заборонені конструкції - груба перевірка (команда шукає рядки, які **починаються** з цих слів; коментарі з `#` не
рахуються, а `if` усередині рядка, наприклад `x if y else z`, вона пропустить - тож це підказка, а не доказ).
Порожній вивід = добре:

```bash
grep -nE '^\s*(if|elif|else|for|while)\b' lr1_1.py lr1_2.py lr1_3.py
```

Або все одразу: `perevir lr1_1.py 127` (скорочення з `ustanovka-mint.sh`, урок 03): відповіді на `input()` пишеш
після назви через пробіл, кожна - окремий рядок вводу (для `lr1_3.py` - `perevir lr1_3.py 534 1 3 2 3 5 2 10`).
Він проганяє doctest (через pytest), black, flake8, pycodestyle, ruff і mypy. black він лише перевіряє
(`black: оформлення ок`), а виправляє `python3 -m black -l 78 файл.py`. Без відповідей perevir скаже
`doctest: файл питає input() при запуску. Дай відповіді після назви: perevir lr1_1.py 5`. Ті самі три `E501` він
покаже двічі - від flake8 і від pycodestyle.

Останнє - людське: кожен рядок свого коду ти маєш уміти пояснити (викладач питає). Імена змінних - англійські
і зрозумілі. Функція повертає рядок через `return`.

## Як роблять профі

- **Захист `if __name__ == "__main__":`.** У звичайних проєктах введення і `doctest.testmod()` ховають під
  цю перевірку - тоді файл можна імпортувати (pytest, інші модулі) без запитання `input()`. Викладач сам показує
  це на с. 10 (приклад з `%%writefile`). Але в ЛР1 `if` заборонений, тому лишай заготовку як є; у наступних лабах
  можна спитати викладача. https://docs.python.org/3/library/__main__.html
- **pytest як «суддя».** `pytest --doctest-modules` збирає doctest з усіх файлів і дає код виходу, який
  розуміють скрипти й GitHub Actions. https://docs.pytest.org/en/stable/how-to/doctest.html
- **ruff замість купи інструментів.** `ruff check` замінює flake8 і частину pylint, а `ruff format` задуманий
  як «drop-in replacement for Black» (так пише документація ruff). Викладач поки хоче всі пʼять інструментів -
  жени всі. https://docs.astral.sh/ruff/formatter/
- **Типи + mypy.** Анотації (`number: int`, `-> str`) і mypy ловлять половину дурних помилок до запуску
  (п. 4 «Типових помилок»). https://mypy.readthedocs.io/en/stable/
- **Маленькі коміти.** Одне завдання = один коміт з людським повідомленням. Урок 24 - як вивантажити на GitHub.
