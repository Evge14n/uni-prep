## Коротко

**`.ipynb`** - файл Jupyter. Усередині це текст у форматі JSON (JSON - простий текстовий запис даних: списки в
`[...]`, пари «ключ: значення» в `{...}`). Там лежить список «комірок» (cells), частина з них - текст умови, частина -
код. Python читає JSON модулем `json`, тож комірку з кодом можна витягти однією командою - функцією `klitynka` з
уроку 04.

| Що | Команда |
|---|---|
| список комірок / одна комірка у файл | `klityny файл.ipynb`, `klitynka файл.ipynb 4 > lr5_1.py` (крок 2) |
| запустити тести файлу (у ЛР5 вони багатослівні) | `python3 lr5_1.py \| tail -n 3` |
| коротко: скільки функцій пройшли | `python3 -m pytest --doctest-modules -q lr5_1.py` |
| обмежити час запуску | `timeout 60 python3 lr5_3.py` (через 60 с зупинить, код виходу 124) |
| перевірити, що нема `**` і `factorial` | `grep -n "\*\*\|factorial" lr5_1.py` - має нічого не надрукувати |

Головна пастка ЛР5: у кожній заготовці викладача останній рядок - `doctest.testmod(verbose=True)` **на верхньому рівні**
файлу. Через це команда `python3 -m doctest lr5_1.py` спершу тестує... сам модуль doctest і друкує
`***Test Failed*** 1 failures.` про клас `DebugRunner`, якого в тебе нема. Тому в ЛР5 перевіряй `python3 lr5_1.py`
або pytest, а `python3 -m doctest` не бери. Деталі - у «Типових помилках».

Обмеження з умови (с. 5): у функціях завдання 1 **не можна** вкладених циклів (і явних, і прихованих, як `sum(...)`
у тілі циклу), піднесення до степеня `**` і функції факторіала. Усе - через **коефіцієнт переходу**: наступний доданок
= попередній × q (теорія, с. 1-2; див. курс Python, тека `Курс/` на ПК, уроки 06 і 07).

## Передбач, потім запусти

**1.** Що надрукує (так форматує результат кожна заготовка завдання 1)?

```python
print(f"{2.0:.5}", f"{0.0355964:.5}", f"{-2.0877e-09:.5}", f"{123456.0:.5}")
```

<details markdown="1"><summary>Відповідь</summary>

```text
2.0 0.035596 -2.0877e-09 1.2346e+05
```

`:.5` без літери - це **5 значущих цифр** (а не 5 знаків після коми). Великі й малі числа самі переходять у запис з `e`.
Тому порівнювати з тестом треба лише рядок, який повертає `return f"{result:.5}"` - не змінюй цей рядок.
</details>

**2.** Межі float. Що надрукує?

```python

```

<details markdown="1"><summary>Відповідь</summary>

```text
inf 0.0 nan
```

Переповнення дає `inf` (нескінченність), втрата значущості - `0.0`, а `inf / inf` - `nan` («не число»). Саме так
ламаються «наївні» версії, а в `calculate_d` для великих n легко отримати `'nan'` замість відповіді (див. «Типові помилки»).
</details>

**3.** Відʼємний нуль. Тест `taylor_sin(180, 1e-5)` чекає `'sin(180) = -0.00000 ...'`. Що надрукує?

```python

```

<details markdown="1"><summary>Відповідь</summary>

```text

```

Крихітне відʼємне число після округлення лишається «відʼємним нулем». Тест чекає саме мінус, бо сума ряду для 180°
вийшла трохи меншою за нуль. Знак залежить від того, **які доданки ти включив у суму** - якщо в тебе `0.00000` без
мінуса, а в тесті з мінусом (або навпаки), перевір, чи не додаєш ти зайвий доданок.
</details>

**5.** Не з ЛР5, просто цикл з лічильником. Що надрукує?

```python

    count += 1
    step = step / 2

```

<details markdown="1"><summary>Відповідь</summary>

```text

```

**Крок 5. Підказки до завдання 1** (розвʼязок твій; функції - див. «Курс/ДОВІДНИК-ФУНКЦІЙ.md»: `range()`, `abs()`,
f-рядок, `math.factorial()` - лише для наївних версій).

- Знайди q_k = a_k / a_(k-1) на папері, як у прикладі теорії (с. 2). Степінь з показником, що росте (k², 2k - 1),
  теж тримай окремою змінною і множ на сталий множник щокроку - це не вкладений цикл.
- Порядок множень має значення: проміжне число може вилетіти за 1,8·10³⁰⁸ або впасти нижче 5·10⁻³²⁴, хоча відповідь
  помірна. Пробуй тримати проміжний результат «посередині»: чергуй множення і ділення.
- `calculate_d`: спершу нове b_k, потім a_k (бо a_k бере **нове** b_k - теорія, с. 2). Потрібні лише два попередні
  a і одне попереднє b - списки не треба.

Приклад на **іншій** задачі: один доданок ряду для eˣ, a_k = xᵏ / k!. Наївно і через коефіцієнт переходу (на кроці
`step` множимо на `base / step`; `base` - це x). Наївна версія з `**` і `factorial` - лише для порівняння, у ЛР5 так
не можна:

```python
import math


def exp_term_naive(k: int, base: float) -> float:
    """base^k / k! напряму.

    >>> exp_term_naive(3, 2.0)
    1.3333333333333333
    """
    return base**k / math.factorial(k)


def exp_term(k: int, base: float) -> float:
    """base^k / k! через коефіцієнт переходу base / step.

    >>> exp_term(3, 2.0)
    1.3333333333333333
    >>> exp_term(200, 100.0)
    1.2679769534809638e+25
    """
    term = 1.0
    for step in range(1, k + 1):
        term *= base / step
    return term


for k in (100, 150, 160, 200):
    try:
        print(k, exp_term_naive(k, 100.0))
    except OverflowError as err:
        print(k, "OverflowError:", err)
```

Вивід циклу внизу:

```text
100 1.0715102881254669e+42
150 1.7502762069260153e+37
160 OverflowError: (34, 'Numerical result out of range')
200 OverflowError: (34, 'Numerical result out of range')
```

Відповідь 10²⁵ цілком «влазить» у float, але наївна версія падає вже на k = 160: 100¹⁶⁰ = 10³²⁰ - більше за межу.
Так само (з `try`/`except` і циклом по n чи x) шукай області для пункту б).

**Пункт в), графіки часу.** Каркас на іншому прикладі: час циклу проти `sum()`. Для ЛР5 підстав
`measure_average_time` з умови і свої функції; відношення часів - третій графік:

```python
import time

import matplotlib.pyplot as plt


def measure(func, n, runs=20):
    start = time.perf_counter()
    for _ in range(runs):
        func(n)
    return (time.perf_counter() - start) / runs


def sum_loop(n):
    total = 0
    for number in range(n):
        total += number
    return total


sizes = [1000, 2000, 4000, 8000]
times_loop = [measure(sum_loop, n) for n in sizes]
times_builtin = [measure(lambda size: sum(range(size)), n) for n in sizes]
plt.semilogy(sizes, times_loop, "o-", label="цикл")
plt.semilogy(sizes, times_builtin, "s-", label="sum()")
plt.xlabel("n")
plt.ylabel("середній час, с")
plt.legend()
plt.savefig("chas.png")
```

```bash
xdg-open chas.png
```

> **Нове тут:**
>
> - `xdg-open` - відкриває файл у його звичайній програмі. Назва: XDG (X Desktop Group, нині freedesktop.org) + open - «відкрити».

## Що не так у файлі викладача

Викладач просив надсилати знайдені помилки в doctest. Усе нижче перевірено запуском у тестовій Mint 22.3 незалежною
програмою (вона лежить окремо, не в уроці):

1. **Формула a) у тексті (с. 5)** - `n² + n!`, у докстрінгу і тестах - `(n² + n)!`. Тести рахують за докстрінгом:
   `calculate_a(2, 1.5)` = 1,5⁸ / 6! = `'0.035596'` (з `n² + n!` було б 1,5⁸ / 6 ≈ 4,27).
2. **Формула d) у тексті** - `5ᵏ` у чисельнику, у докстрінгу - `x^(k²)`. Тести - за докстрінгом: `calculate_d(1, 2.0)`
   → `'2.0'` (з 5ᵏ було б `'5.0'`).
3. **`calculate_a(100, 200.0)` → `'0.0'`.** Справжнє значення ≈ 10⁹⁹⁶¹ - у float не вміщається. `'0.0'` виходить лише
   за певного порядку множень і ділень (проміжний результат «тоне» в нуль). Тест перевіряє поведінку float, а не
   математику.
4. **`calculate_b(1000, 0.503795)` → `'-0.63211'`.** Математично доданок при k = 1000 ≈ 10⁷¹⁶, сума величезна. Тест
   проходить, бо в рекурентному способі доданки дорогою стають `0.0` і далі лишаються нулем.
5. **Знаків після коми в `taylor_sin`.** Текст (с. 11): «порядок ε плюс один знак» (ε = 0,001 → 4 знаки). Тести:
   рівно порядок ε (`taylor_sin(5.7, 0.001)` → `'0.099'`, 3 знаки; ε = 10⁻⁴ → `'0.9992'`, 4 знаки). Роби як у тестах.
6. **`pi_gregory(6)` ... `(10)`.** Сума вказаної в тесті кількості членів не дає очікуваного значення: 500 000 членів
   дають 3.141591 (π - 2·10⁻⁶), тест чекає `3.141592`; для 5 000 000 - 3.1415925 проти `3.1415926`. Для n = 1 ... 5
   усе збігається.
7. **`pi_wallis`.** Кількість членів у тестах (15, 157, 1570, 15707, 157079, ...) - це рівно ⌊π/2 · 10ⁿ⌋. Природне
   правило «зупинись, коли |2P - π| < 10⁻ⁿ» (по одному множнику 2/1, 2/3, 4/3, ...) дає 15, 156, 1570, 15708, 157079:
   для n = 2 і n = 4 на одиницю інше. Спитай, яке правило зупинки мав на увазі викладач.
8. **Заготовки `calculate_c`, `calculate_d` і наївні**: `-> float`, а повертають `str` (див. mypy вище).

## Як роблять профі

- **Логарифми замість добутків.** Для величезних факторіалів і степенів у науці рахують `math.lgamma(k + 1)`
  (логарифм k!) і `k * math.log(x)`, а число відновлюють `exp` лише в кінці. Так не буває ні переповнення, ні нулів
  (у ЛР5 так не можна - там вчать коефіцієнт переходу, але ідея та сама: не дати проміжному числу втекти).
- **`math.fsum`** - сума з точною компенсацією похибок округлення; **`decimal`** і **`fractions`** - коли float не
  вистачає (документація Python, модулі `math`, `decimal`).
- **Порівняння float** у тестах - через допуск (`math.isclose`, `pytest.approx`), а не текстом. Тести викладача
  порівнюють текст, тому знак нуля й останній знак важать.
- **Довгі тести позначають** (у pytest - мітка `slow`) і запускають окремо, а не щоразу.
- **Блокноти в звичайні файли** конвертують командою `jupyter nbconvert --to script` (потрібен Jupyter) або
  інструментом `jupytext`; наша функція `klitynka` робить те саме для однієї комірки.
