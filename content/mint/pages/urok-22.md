## Коротко

Термінал і nano - урок 03. Тут - те, з чого складаються команди.

**Змінні.**

```text
name="Прізвище"            без пробілів навколо =
echo "$name"            "..." - підставить значення:   Прізвище
echo '$name'            '...' - буквально, як написано: $name
echo "Сьогодні $(date +%A)"   $(команда) - підставити вивід команди
```

Правило: змінну **завжди** бери в подвійні лапки `"$x"`. Без лапок пробіл у значенні розбиває його на два слова.

**Змінні оточення** (environment) - ті, що успадковують програми, запущені з термінала: `HOME`, `PATH`, `USER`.
Звичайна змінна живе лише в цьому bash; `export x` робить її змінною оточення. Подивитись: `printenv HOME`, усі -
`env`. Python читає їх через `os.environ`.

**PATH** - список тек через `:`, де bash шукає команди. Набрав `flake8` - bash іде по теках PATH зліва направо
і запускає перший знайдений файл.

```bash
echo "$PATH" | tr ":" "\n"
```

> **Нове тут:**
>
> - `echo` - друкує текст і значення змінних. Назва: echo - «луна»: повторює те, що йому дали.
> - `tr` - замінює окремі символи в тексті. Назва: translate - «перекласти»: замінити одні символи іншими.
> - `"..."` - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».
> - `$ЗМІННА` - підставляє значення змінної. Назва: dollar («долар») - «значення змінної».
>
> Усе про кожну команду - у довіднику «05_Програмування/КОМАНДИ - довідник.md» (на сайті - вкладка «Команди»).

Перші рядки - на кшталт `/home/evgen/.local/bin`, `/usr/local/sbin`, `/usr/local/bin`, `/usr/sbin`, `/usr/bin`.
**`~/.local/bin`** - туди ставлять свої команди `pipx` і `uv` (урок 02). У Mint її додає файл `~/.profile`, але
**лише якщо тека вже була в момент входу в систему**. Тому після першого `pipx install` нова команда може «не
знаходитись», поки не вийдеш із сеансу і не зайдеш знову (або `source ~/.profile`).

**Де команда?**

| Команда | Відповідь |
|---|---|
| `type cd` | `cd is a shell builtin` - вбудована в bash |
| `type ll` | ``ll is aliased to `ls -alF'`` - аліас (скорочення) |
| `type python3` | `python3 is /usr/bin/python3` - файл |
| `command -v python3` | лише шлях - зручно в скриптах |
| `which python3` | теж шлях, але вбудовані і аліаси не бачить (`which cd` - порожньо) |

**Довідка: `--help` і `man`.** Майже кожна команда має коротку довідку `команда --help` і повну сторінку
посібника `man команда`:

```bash
grep --help | head -3
man grep
man -k crontab
```

```text
Usage: grep [OPTION]... PATTERNS [FILE]...
Search for PATTERNS in each FILE.
Example: grep -i 'hello world' menu.h main.c
```

> **Нове тут:**
>
> - `grep` - знаходить рядки з текстом у файлах. Назва: g/re/p з редактора ed: «знайти регулярний вираз у всьому файлі і надрукувати». `--help` - коротка довідка про всі прапорці; українською, якщо система українська.
> - `head` - показує перші рядки файлу. Назва: head - «голова»: початок файлу.
> - `man` - відкриває повний посібник до команди. Назва: manual - «посібник». `-k` - шукати команди, в назві чи короткому описі яких є слово (як apropos).
> - `|` - передає вивід однієї команди на ввід іншій. Назва: pipe - «труба» (пайп), вертикальна риска.

Якщо Mint українською, `--help` теж українською (`Використання: grep [ПАРАМЕТР]... ШАБЛОНИ [ФАЙЛ]...`);
англійською - `LC_ALL=C grep --help`. `man` відкриває сторінку в переглядачі `less`: **пробіл** - сторінка вниз,
`b` - вгору, **`/слово`** і Enter - шукати, `n` - наступний збіг, **`q`** - вийти. Сторінка йде розділами: NAME (що
це), SYNOPSIS (як викликати; у `[ ]` - необовʼязкове), DESCRIPTION (усі параметри), EXAMPLES (є не завжди).
`man -k слово` шукає команди за словом в описі. Номер у дужках, як `crontab(5)`, - розділ посібника: `man 5 crontab`
- формат файлу, `man crontab` - сама команда. (Сторінки `man` - з пакетів man-db і manpages, вони є на ISO 22.3;
у тестовій Mint їх нема, тому вигляд сторінок там не перевірено.)

**Аліаси і `~/.bashrc`.** `~/.bashrc` - файл, який bash читає при кожному новому вікні термінала. У Mint він уже
має аліаси `ll` (`ls -alF`), `la`, `l` і читає ще файл `~/.bash_aliases`, якщо той є - свої аліаси пиши туди.
Після правки - `source ~/.bashrc` або нове вікно.

**Історія.** ↑ - попередня команда. **Ctrl+R** і почни набирати - пошук в історії (ще Ctrl+R - старіша, Enter -
виконати, Esc - взяти в рядок). `!!` - уся попередня команда: `sudo !!` = «те саме, але з sudo». У Mint історія
тримає 1000 команд (`HISTSIZE=1000` у `~/.bashrc`), а команда, що починається з **пробілу**, не запамʼятовується.

**Потоки і перенаправлення.** У програми три потоки: ввід (stdin, 0), вивід (stdout, 1), помилки (stderr, 2).

| Запис | Що робить |
|---|---|
| `команда > файл` | вивід у файл (файл **перезаписується**) |
| `команда >> файл` | дописати в кінець |
| `команда 2> файл` | лише помилки у файл |
| `команда > файл 2>&1` | і вивід, і помилки в один файл (або коротко `&> файл`) |
| `команда < файл` | ввід з файлу замість клавіатури |
| `к1 \| к2` | вивід к1 стає вводом к2 (пайп) |
| `к1 \|& к2` | те саме разом з помилками |
| `команда \| tee файл` | і на екран, і у файл |
| `> /dev/null` | викинути вивід |

**Фільтри** - команди, які беруть текст і віддають текст, тому їх ставлять у пайпи:

| Команда | Що робить |
|---|---|
| `grep "текст" файл` | рядки з текстом. `-n` номери, `-i` без різниці великі/малі, `-v` рядки БЕЗ тексту, `-c` скільки, `-w` ціле слово, `-l` лише імена файлів, `-r` у всіх підтеках, `-E` розширені регулярні вирази, `--include="*.py"` лише такі файли |
| `find . -name "*.py"` | знайти файли за назвою; `-type d` теки, `-mtime -1` змінені за останню добу, `-exec команда {} +` - виконати для знайдених |
| `xargs команда` | рядки з входу → аргументи команди |
| `sort`, `sort -rn` | впорядкувати; `-n` як числа, `-r` навпаки |
| `uniq -c` | склеїти **сусідні** однакові рядки і порахувати (тому спершу `sort`) |
| `wc -l` | скільки рядків (`-m` символів) |
| `cut -d: -f1` | взяти 1-ше поле, поля розділені `:` |
| `head -n 5`, `tail -n 5` | перші / останні 5 рядків; `tail -f файл` - стежити за файлом наживо (Ctrl+C) |
| `sed -n '2,3p'` | надрукувати рядки 2-3 |
| `sed 's/старе/нове/'` | замінити (перше входження в рядку; `g` в кінці - усі) |
| `awk '{ print $1 }'` | надрукувати перше «слово» рядка; `-F:` - розділювач `:` |

**Регулярні вирази** (шаблони для grep, sed): `^` початок рядка, `$` кінець, `.` будь-який символ, `*` попереднє
0 і більше разів, `[0-9]` одна цифра, `.\{79,\}` - 79 і більше будь-яких символів (з `-E`: `.{79,}`).

**Код виходу** `$?`: 0 - успіх, не 0 - помилка. `к1 && к2` - к2 лише якщо к1 успішна; `к1 || к2` - лише якщо
к1 впала.

> **Нове тут:**

> - `ls` - показує, що лежить у теці. Назва: list - «список» (вмісту теки).

2. Що надрукує кожен рядок?

```bash
x=5
bash -c 'echo "x=$x"'
export x
bash -c 'echo "x=$x"'
```

> **Нове тут:**
>
> - `bash` - оболонка, що виконує команди; bash файл.sh запускає скрипт. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»). `-c` - виконати команди з рядка в новому bash: bash -c 'echo привіт'.
> - `export` - робить змінну видимою для запущених програм. Назва: export - «вивезти, експортувати»: передати змінну програмам-нащадкам.
> - `'...'` - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».

<details markdown="1"><summary>Відповідь</summary>

```text
x=
x=5
```

`bash -c` - нова програма. Звичайну змінну вона не бачить, змінну оточення (після `export`) - бачить. Так само і
Python через `os.environ`.

</details>

3. Файлу `nema.py` нема. Що буде на екрані і що у файлі `out.txt`?

```bash
python3 nema.py > out.txt
cat out.txt
```

> **Нове тут:**
>
> - `python3` - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
> - `cat` - показує вміст файлу. Назва: concatenate - «зчепити»: склеює кілька файлів в один вивід.
> - `>` - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.

<details markdown="1"><summary>Відповідь</summary>

Помилка - на екрані, `out.txt` - **порожній**: `>` перенаправляє лише stdout, а помилки йдуть у stderr. Щоб
зловити і помилки: `python3 nema.py > out.txt 2>&1`. Тоді в `out.txt` буде (шлях у тебе свій):

```text
python3: can't open file '/home/evgen/univer/praktyka/bash22/nema.py': [Errno 2] No such file or directory
```

</details>

4. У `lr2/mayatnyk.py` рядок 5 - docstring українською на 71 символ. Хтось шукає довгі рядки через awk:

```bash

```

> **Нове тут:**
>
> - `awk` - бере з рядків потрібні стовпці (поля). Назва: awk - перші літери авторів: Aho, Weinberger, Kernighan (Bell Labs, 1977).

<details markdown="1"><summary>Відповідь</summary>


Рядок надрукувався, хоча в ньому 71 символ. У Mint `awk` - це **mawk**, і `length` рахує **байти**, а кожна

символи: `grep -n '.\{79,\}' lr2/mayatnyk.py` - тиша, довгих рядків нема.

</details>

**Крок 3. Своя команда в `~/.local/bin`.**

```bash
mkdir -p ~/.local/bin
printf '#!/bin/bash\necho "Привіт з ~/.local/bin"\n' > ~/.local/bin/pryvit
chmod +x ~/.local/bin/pryvit
```

> **Нове тут:**
>
> - `chmod` - змінює права файлу: читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. `+x` - дозволити запуск (x); у Mint - усім трьом: власнику, групі й іншим.

Тепер набери `pryvit`. Якщо тека `~/.local/bin` щойно зʼявилась, її ще нема в PATH - bash скаже
`pryvit: command not found`. Тоді:

```bash
source ~/.profile
type pryvit
```

> **Нове тут:**
>
> - `source` - виконує файл у поточному bash (venv, ~/.bashrc). Назва: source - «джерело»: виконати команди з файлу-джерела. `~/.profile` - перечитати PATH, напр. щоб зʼявилась ~/.local/bin (урок 22).
> - `type` - каже, що це за команда і де вона. Назва: type - «тип»: що це за команда.

і знову `pryvit`:

```text
pryvit is /home/evgen/.local/bin/pryvit
Привіт з ~/.local/bin
```

Так само поводяться команди від `pipx install`. (Якщо тека вже була, `pryvit` спрацює одразу.)

**Крок 4. Свій аліас.**

```bash
echo "alias gst='git status'" >> ~/.bash_aliases
source ~/.bashrc
type gst
alias ll
```

```text
gst is aliased to `git status'
alias ll='ls -alF'
```

> **Нове тут:**
>
> - `source`: `~/.bashrc` - перечитати налаштування після правки (аліаси, функції).
> - `type`: `gst` - перевірити свій аліас (урок 22).
> - `alias` - дає коротке імʼя довгій команді. Назва: alias - «псевдонім, інше імʼя». `ll` - alias ll - показати, на що замінюється ll (у Mint - ls -alF з ~/.bashrc).
> - `>>` - дописує вивід у кінець файлу. Назва: append - «дописати» в кінець файлу.

Назву аліасу перевір заздалегідь: `type назва` має відповісти `not found`. Інакше аліас сховає справжню програму
(наприклад, `gs` - це Ghostscript, програма для PDF, і з аліасом `gs` її вже не запустиш).

**Крок 5. grep по всіх лабах.**

```bash
grep -rn "print(" .
grep -rni "print(" .
grep -rc "def " --include="*.py" .
grep -rl "import" .
grep -v "^$" lr1/kolo.py
```

> **Нове тут:**
>
> - `grep`: `-r` - шукати в усіх файлах теки і підтек (recursive); `-n` - показати номер рядка перед кожним збігом (line number); `.` - з -r: шукати в поточній теці і всіх підтеках; `-i` - без різниці між великими й малими літерами (ignore case); `-c` - лише порахувати рядки зі збігом у кожному файлі (count); `--include` - з -r: шукати лише у файлах за шаблоном, --include="*.py"; `-l` - лише назви файлів, де є збіг (list); `-v` - навпаки: рядки, де шаблону НЕМА (invert).

Справжній вивід перших двох (порядок файлів у тебе може бути інший):

```text
./lr2/mayatnyk.py:9:print("T =", period(1.0))
./lr2/mayatnyk.py:10:print("готово")
./lr2/chernetka.py:3:# тут print( лише в коментарі
./lr1/kolo.py:5:print(area(2))
./lr2/mayatnyk.py:9:print("T =", period(1.0))
./lr2/mayatnyk.py:10:print("готово")
./lr2/chernetka.py:2:Print(x)
./lr2/chernetka.py:3:# тут print( лише в коментарі
./lr1/kolo.py:5:print(area(2))
```

Формат: `файл:рядок:текст`. З `-i` знайшовся ще `Print(x)` (велика літера). `-c` дасть `./lr1/kolo.py:1`
тощо, `-l` - лише `./lr2/mayatnyk.py`, а `grep -v "^$"` покаже файл без порожніх рядків.

**Крок 6. find і xargs.**

```bash
find . -name "*.py"
find . -name "*.py" -mtime -1
find . -name "*.py" -exec wc -l {} +
find . -name "*.py" | xargs grep -c "print"
```

> **Нове тут:**
>
> - `find` - шукає файли за назвою, часом чи власником. Назва: find - «знайти». `-name` - за назвою, шаблон у лапках: -name "*.py"; великі й малі літери різні; `.` - шукати тут і в усіх підтеках; `-mtime` - за днем зміни: -mtime -1 - змінені менше доби тому (modification time).
> - `wc` - рахує рядки, слова, символи. Назва: word count - «підрахунок слів»; рахує ще рядки й байти. `-l` - лише кількість рядків (lines).
> - `xargs` - робить з рядків входу аргументи команди. Назва: extended arguments - «розширені аргументи»: рядки з входу стають аргументами.

Справжній вивід третьої команди:

```text
 10 ./lr2/mayatnyk.py
  3 ./lr2/chernetka.py
  5 ./lr1/kolo.py
 18 total
```

`-mtime -1` - змінені за останню добу (зараз - усі три). `{}` - місце для знайдених файлів, `+` - віддати всі
разом однією командою.

**Крок 7. Пайпи: порахувати і впорядкувати.**

```bash
grep -rhoE '[A-Za-z_]+\(' --include='*.py' . | sort | uniq -c | sort -rn
grep -rn "print(" . | cut -d: -f1 | sort | uniq -c
```

```text
      4 print(
      2 period(
      2 area(
      1 sqrt(
      1 Print(
      1 ./lr1/kolo.py
      1 ./lr2/chernetka.py
      2 ./lr2/mayatnyk.py
```

> **Нове тут:**
>
> - `grep`: `-h` - не писати назву файлу перед рядком (це НЕ довідка); `-o` - друкувати лише знайдений шматок, а не весь рядок (only); `-E` - розширені регулярні вирази: |, +, {79,} без зворотних рисок.
> - `sort` - впорядковує рядки. Назва: sort - «сортувати, впорядкувати». `-r` - навпаки: від більшого до меншого; `-n` - як числа: 9 менше за 10 (без -n - як текст, і 10 іде перед 9).
> - `uniq` - склеює однакові сусідні рядки (з -c - рахує). Назва: unique - «єдиний, неповторний»: прибрати повтори. `-c` - писати перед рядком, скільки разів він ішов підряд.
> - `cut` - вирізає з рядків потрібні стовпці. Назва: cut - «вирізати»: взяти шматок кожного рядка. `-f` - які поля взяти: -f1 або -f1,6,7 або -f2-4.

Перше - які функції викликаються найчастіше (`-o` друкує лише знайдений шматок, `-h` - без імені файлу). Друге -
скільки `print(` у кожному файлі.

> **Нове тут:**
>
> - `tee` - показує вивід і одночасно пише у файл. Назва: tee - трійник у трубах (літера T): потік іде у два боки.
> - `sed` - друкує потрібні рядки або замінює текст. Назва: stream editor - «потоковий редактор»: править текст, що тече крізь нього. `-n` - не друкувати всі рядки, лише ті, що позначені командою p.

`sed` без `-i` лише показує результат, файл не міняє. `sed -i` міняє файл на місці - перед ним зроби копію
(`sed -i.bak ...` лишить `файл.bak`) або коміт у git.

**Крок 9. Код виходу, && і ||.**

```bash
grep -q "def" lr1/kolo.py; echo $?
grep -q "class" lr1/kolo.py; echo $?
python3 lr1/kolo.py > /dev/null && echo "працює" || echo "впало"
python3 lr2/chernetka.py > /dev/null 2>&1 && echo "працює" || echo "впало"
python3 lr2/chernetka.py |& tail -n 1
```

```text
0
1
працює
впало
NameError: name 'Print' is not defined. Did you mean: 'print'?
```

> **Нове тут:**
>
> - `grep`: `-q` - нічого не друкувати, лише код виходу: 0 - знайшов, 1 - ні (quiet).
> - `;` - розділяє команди в рядку, виконує всі по черзі. Назва: крапка з комою - роздільник команд.
> - `||` - друга команда - лише якщо перша впала. Назва: «або»: друга команда - лише якщо перша впала.
> - `2>&1` - помилки йдуть разом зі звичайним виводом. Назва: «потік 2 туди ж, куди потік 1»: помилки разом зі звичайним виводом.

## Типові помилки

Якщо Mint українською, bash і find пишуть українською - у дужках (справжній запуск з перекладом
`language-pack-uk-base`). Англійський текст для пошуку: `LC_ALL=C команда`. Помилки Python (`NameError` тощо)
завжди англійською.

- **`name = "Прізвище"`** з пробілами → `name: command not found` (`name: команду не знайдено`): bash думає, що
  `name` - це команда.
- **`grep print( lr1/kolo.py`** без лапок → ``syntax error near unexpected token `('``
  (`синтаксична помилка коло неочікуваної лексеми «(»`) - дужки для bash особливі. Шаблон завжди в лапках:
  `grep "print(" lr1/kolo.py`.
- **`python3 lab.py > lab.py`** - **стирає код**: `>` спершу обнуляє файл. Вивід - в інший файл.
- **`>` замість `>>`** - старий вміст пропав.
- **`uniq -c` без `sort`** - рахує лише сусідні однакові рядки, числа виходять дивні.
- **`awk 'length > 78'`** з українським текстом - хибні результати (mawk рахує байти, передбачення 4).
  Для довжини рядків - `grep '.\{79,\}'`.
- **`find . -name *.py`** без лапок: якщо в поточній теці є `.py`-файли, bash сам підставить їх імена, і find
  шукатиме не те (або скаже `paths must precede expression`, українською `шляхи мають передувати виразу`).
  Шаблон - у лапках: `-name "*.py"`.
- **Імена файлів з пробілами + xargs** розвалюються на шматки. Тоді `find ... -print0 | xargs -0 ...` або
  `find ... -exec ... {} +`.
- **Нова команда в `~/.local/bin` «не знаходиться»** - тека додалась у PATH лише при наступному вході (крок 3).
- **`sudo` не бачить твоїх аліасів і `~/.local/bin`** - у sudo свій, безпечний PATH. Свої команди від root не запускай.

## Як роблять профі

- **Маленькі команди + пайпи.** Філософія Unix: кожна програма робить одне, а пайпи їх зʼєднують. Курс MIT
  «Missing Semester» (2020, лекція Data Wrangling) будує на цьому цілу лекцію; Cambridge Unix Tools - теж.
- **ripgrep (`rg`) і fd** - швидші сучасні замінники grep і find, самі пропускають `.venv` і те, що в
  `.gitignore`. У репозиторії Mint є (`sudo apt install ripgrep fd-find`, команда fd там зветься `fdfind`). Але
  grep і find є всюди, тому вчимо спершу їх.
- **Аліаси - лише для себе.** У скриптах (урок 23) пишуть повні команди: аліасів там нема.
- **Перевірка рядка перед запуском** - explainshell.com розбирає будь-яку команду по шматках.

## Самоперевірка

1. Чим відрізняються `echo "$name"` і `echo '$name'`?
2. Навіщо `export` і як перевірити, що змінна стала змінною оточення?
3. Як одним рядком знайти в усіх `.py` поточної теки і підтек рядки з `print(` з номерами рядків?
4. Ти поставив програму через `pipx`, а `bash` пише `command not found`. Чому і що зробити?
5. Чому `python3 lab.py > out.txt` не зберіг текст помилки, і як зберегти і вивід, і помилки?

<details markdown="1"><summary>Відповіді</summary>

1. У подвійних лапках `$name` замінюється значенням (`Прізвище`), в одинарних - друкується буквально `$name`.
2. Щоб змінну бачили програми, запущені з цього bash (Python, інший bash). Перевірка:
   `bash -c 'echo "$x"'` або `printenv x`.
3. `grep -rn --include="*.py" "print(" .`
4. pipx кладе команди в `~/.local/bin`, а `~/.profile` додає цю теку в PATH лише якщо вона була при вході.
   Вийти з сеансу і зайти знову (або `source ~/.profile`). Перевірка: `type назва`.
5. `>` перенаправляє лише stdout, а помилки йдуть у stderr. Треба `python3 lab.py > out.txt 2>&1` (або `&> out.txt`).

</details>
