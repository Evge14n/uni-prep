## Загальна математика turtle (одна сторінка, потрібна майже в кожному завданні)

**1) Поворот - це кут ЗОВНІШНІЙ, а не внутрішній.**
Черепашка йде вздовж сторони. На вершині вона повертає на стільки, на скільки
треба відхилитися від прямого руху. Якщо внутрішній кут фігури β, поворот:

```
поворот = 180° - β
```

Квадрат: β = 90° → поворот 90°. Правильний трикутник: β = 60° → поворот 120° (не 60!).
Ромб 60°/120°: на гострій вершині поворот 120°, на тупій - 60°.

**2) Обійти будь-яку замкнену опуклу фігуру = повернутися сумарно на 360°.**
Тому в правильному n-кутнику кожен поворот 360°/n (п'ятикутник: 72°).

**3) Розета з n однакових фігур:** намалював фігуру, повернувся на 360°/n, і так n разів.

```
36 кіл   → 360 / 36 = 10°
24 ромби → 360 / 24 = 15°
72 квадрати → 360 / 72 = 5°
```

Щоб це працювало, після кожної фігури черепашка має стояти ТАМ САМО і дивитися ТУДИ САМО,
де почала. Коло (`circle`) і замкнений багатокутник саме так і закінчуються.

**4) Циклічні кольори:** `colors[i % len(colors)]`. Остача від ділення ходить по колу:

```
i            : 0 1 2 3 4 5 6 7 8 ...
i % 4        : 0 1 2 3 0 1 2 3 0 ...
```

**5) Групи по 12, 20, 24:** цілочисельне ділення `i // 20` дає номер групи:

```
i       : 0 ... 19 | 20 ... 39 | 40 ... 59
i // 20 :    0     |     1     |     2
```

Звідси `2 + i // 20` = 2, 3, 4 без жодного `if`. Але й через `if i < 20: ... elif ...` - теж правильно.

**6) Градуси → радіани** (для `math.sin`, `math.cos`): `math.radians(кут)`.

```
радіани = градуси · π / 180       90° → π/2 ≈ 1,5708
```

`math.cos(90)` - це косинус 90 РАДІАН (≈ -0,448), а не 0. Найчастіша помилка в 1.8.

**7) Полярні координати → звичайні:**

```
x = r · cos θ
y = r · sin θ
```

**8) Заливка.** `begin_fill()` ... малюєш ЗАМКНЕНИЙ контур ... `end_fill()`.
Колір заливки - `fillcolor("gold")`, або одразу обидва: `color("blue", "gold")` (лінія, заливка).

**9) Швидко і без стрілки:** `speed(0)` - НА ПОЧАТКУ (до циклу), `hideturtle()` - в кінці
(або теж на початку, тоді стрілку не видно взагалі). `speed(0)` після циклу нічого не дає.

**10) Перейти без лінії:** `penup()` → `goto(x, y)` → `pendown()`. Саме в такому порядку.
Забув `pendown()` - далі нічого не малюється. Забув `penup()` - через екран тягнеться зайва лінія.

## 1.1 Правильна зірка `draw_star(n, length, k=2)`

### Що має вийти
Рисунок 1 (перший зліва вгорі): семикутна зірка {7/2} на БІЛОМУ тлі, контур синій,
промені залиті золотим. Центр (семикутник посередині) лишився БІЛИМ - це нормально,
так і на рисунку (пояснення нижче). Вікно 600 × 600.

### Математика простими словами
Уяви 7 точок на колі, як цифри на годиннику. Звичайний семикутник: з'єднуєш кожну
з НАСТУПНОЮ (крок k = 1). Зірка: з'єднуєш через одну (крок k = 2): 0 → 2 → 4 → 6 → 1 → 3 → 5 → 0.

Кут повороту з умови:

```
          360° · k
angle = ──────────
             n

n = 7, k = 2:   angle = 360 · 2 / 7 = 720 / 7 ≈ 102,857°
n = 5, k = 2:   angle = 720 / 5 = 144°   (класична п'ятикутна зірка)
n = 7, k = 1:   angle = 360 / 7 ≈ 51,43°  (звичайний семикутник)
```

Чому так: за весь обхід зірки {n/k} черепашка обертається не на 360°, а на k · 360°
(для k = 2 - два повні оберти). Ділиш на n поворотів - отримуєш кут.

**НСД (gcd).** Якщо `gcd(n, k) = 1`, усі n вершин в одному контурі - одна зірка одним розчерком.
Якщо `gcd(n, k) > 1`, контур замикається раніше. Приклад n = 6, k = 2: gcd = 2, кут 120°,
черепашка намалює ТРИКУТНИК і далі піде по ньому вдруге (а не «зірку Давида» з двох трикутників).
Тому умова і просить вивести попередження.

```
from math import gcd
gcd(7, 2) = 1   → все добре
gcd(6, 2) = 2   → попередження
gcd(8, 2) = 2   → попередження (вийде квадрат)
gcd(8, 3) = 1   → одна зірка {8/3}
```

**Чому центр білий.** Контур зірки сам себе перетинає. Tk (на ньому працює turtle) заливає
за правилом «парне/непарне»: точка всередині, якщо промінь з неї перетинає контур непарну
кількість разів. Центр обведений двічі → парно → не заливається. На рисунку викладача так само.

### План
1. `import turtle`, `from math import gcd`.
2. Функція `draw_star(n, length, k=2)`: порахувати кут, перевірити gcd і, якщо треба, `print(...)` попередження.
3. Колір лінії і заливки, `begin_fill()`.
4. Цикл з n ітерацій: вперед на `length`, поворот на кут.
5. `end_fill()`.
6. Поза функцією: вікно 600 × 600, виклик `draw_star(7, 150, 2)`, `turtle.done()`.

Вікно потрібного розміру задає `turtle.setup(ширина, висота)`.
Поворот у зірці - `right` чи `left`, не важливо (буде дзеркальна зірка). Важливо, щоб кут був з формули.


</details>

<details markdown="1"><summary>Рівень 2</summary>

```
turn_angle = 360 * k / n
```
і перевірка `if gcd(n, k) != 1:` → `print("Увага: ...")`.


</details>

Для doctest можна винести `star_turn_angle(n, k) -> float` (рядок `360 * k / n`)

### Типові помилки
- `360 / n * k` і `360 * k / n` - однаково. А от `360 // n * k` - ЦІЛОЧИСЕЛЬНЕ ділення,
  для n = 7 дасть 51 · 2 = 102 замість 102,857, і зірка НЕ замкнеться (буде щілина).
- Цикл `range(k * n)` або `range(360)` замість `range(n)` - зайві обходи.
- `begin_fill()` після циклу - нічого не заллється.
- Попередження через `return "..."` замість `print` - умова каже вивести в консоль.
- `turtle.setup(600, 600)` після малювання - вікно вже відкрилось іншого розміру. Ставити на початку.

## 1.3 Квадратна кольорова спіраль (60 відрізків)

### Що має вийти
Рисунок 3: чорне тло, квадратна спіраль, що розкручується від центру. Кожна сторона одного
кольору: верхні горизонталі золоті, праві вертикалі малинові, нижні салатові, ліві блакитні.
Зовнішні витки товщі (лінія 2 → 3 → 4).

### Математика простими словами
Довжина відрізка номер i (рахуємо з 0):

```
length = 10 + 4 · i

i = 0  → 10
i = 1  → 14
i = 59 → 10 + 236 = 246
```

Поворот праворуч 90° після кожного - тому спіраль іде за годинниковою стрілкою.
Оскільки кольорів 4 і кут 90° (4 повороти = повний оберт), кожен напрям завжди має свій колір:
відрізок 0 (вправо) золотий, 1 (вниз) малиновий, 2 (вліво) салатовий, 3 (вгору) блакитний, 4 (знов вправо) золотий...

Товщина за номером:

```
i = 0 ... 19  → pensize(2)
i = 20 ... 39 → pensize(3)
i = 40 ... 59 → pensize(4)
```

Або `if` / `elif` / `else`, або формулою `2 + i // 20` (див. загальну математику, п. 5).

Довжину можна або рахувати формулою від i, або тримати змінну і додавати 4 після кожного кроку
(умова каже саме «після кожного кроку збільшуйте на 4» - другий спосіб ближчий до тексту).

### План
1. Тло, `speed(0)`, список кольорів `["gold", "crimson", "lime", "cyan"]`
   (саме ці 4 назви стоять у теорії ЛР4, стор. 4; салатовий = lime, блакитний = cyan).
2. `segment_length = 10`.
3. Цикл на 60: товщина за номером, колір `colors[i % len(colors)]`, `forward(segment_length)`,
   `right(90)`, `segment_length += 4`.
4. `hideturtle()`, `done()`.

Що змінюється від кроку до кроку: довжина, колір, товщина. Що не змінюється: кут.


</details>

<details markdown="1"><summary>Рівень 2</summary>

```

```


</details>

<details markdown="1"><summary>Рівень 3</summary>

Для doctest: `segment_pen_size(0)` → `2`, `segment_pen_size(20)` → `3`, `segment_pen_size(59)` → `4`.

- Межі груп: `if i < 20 ... elif i < 40 ... else` - правильно. `if i <= 20` - 21 відрізок у першій групі.
- `left(90)` замість `right(90)` - спіраль у інший бік (дзеркально). Умова каже праворуч.

- Колір за `segment_length % 4` замість номера - кольори «поїдуть» (10, 14, 18 ... усі дають остачу 2).

## 1.4 Оптична квітка з 24 ромбів

### Що має вийти
Рисунок 4: чорне тло, 24 ромби зі спільною вершиною в центрі, розкладені по колу.
Верхня половина блакитна (cyan), нижня помаранчева (orange). У центрі сходяться ГОСТРІ кути
ромбів (60°), тому там густо.

### Математика простими словами
Ромб - чотири однакові сторони по 100. Кути 60° і 120° чергуються. Черепашка повертає на
ЗОВНІШНІЙ кут (180° - внутрішній):

```
внутрішній 120° → поворот 60°
внутрішній 60°  → поворот 120°

сума поворотів: 60 + 120 + 60 + 120 = 360°  → ромб замкнувся, черепашка в початку
```

Порядок: вперед 100, ліворуч 60, вперед 100, ліворуч 120, вперед 100, ліворуч 60, вперед 100, ліворуч 120.
Останній поворот 120° відбувається в початковій вершині - отже там внутрішній кут 60°, гострий.
Так і на рисунку. (Якщо почати з повороту 120°, у центрі будуть тупі кути - теж «квітка», але рідша, не як на рисунку.)

Розета: 24 ромби, 360 / 24 = 15° між ними.
Кольори: ромби 0-11 cyan, 12-23 orange. Перші 12 · 15° = 180° - півкола, тому половина квітки одного кольору.

### План
1. Тло, `speed(0)`.
2. (Добре для оцінки) функція `draw_rhombus(side_length)` - малює один ромб, повертається в початок.
3. Цикл на 24: колір (`cyan`, якщо номер < 12, інакше `orange`), ромб, `left(15)`.
4. `hideturtle()`, `done()`.

## 1.5 Павутинка: 6 променів і 7 шестикутників

### Що має вийти
Рисунок 5: чорне тло, 6 тонких сірих променів з центру (горизонтальний і два похилі, разом
«сніжинка»), поверх них 7 вкладених шестикутників з вершинами вгорі й унизу. П'ять внутрішніх
білі тонкі, два зовнішні жовті товсті.

### Математика простими словами
Промені: 6 штук, між ними 360 / 6 = 60°. Кожен промінь - «вперед 150, назад 150, повернути на 60».
Назад - щоб повернутися в центр, не піднімаючи пера (лінія просто пройде двічі по тому самому місцю).

Шестикутник через `circle(size, steps=6)`: черепашка малює «коло» з 6 відрізків, тобто
правильний шестикутник, вписаний у коло радіуса size. Центр кола - на size ЛІВОРУЧ від черепашки.
Тому якщо поставити черепашку в (0, -size) і направити праворуч (heading 0), центр буде в (0, 0).
Саме це умова й каже: «розпочинаючи з точки (0, -size)».

```
радіуси: 20, 40, 60, 80, 100, 120, 140   (7 штук, крок 20)
номер:    0   1   2   3    4    5    6
          └──── білі, товщина 1 ────┘ └ жовті, 3 ┘
```

### План
1. Тло, `speed(0)`.
2. Промені: колір `gray`, цикл на 6 (вперед, назад, ліворуч 60).
3. Цикл по радіусах: `penup`, `goto(0, -size)`, `setheading(0)`, `pendown`, колір і товщина за номером, `circle(size, steps=6)`.
4. `hideturtle()`, `done()`.

### Підказки
<details markdown="1"><summary>Рівень 1</summary>

Радіуси можна взяти списком `[20, 40, ...]` або `range(20, 141, 20)` - 141, бо кінець не входить.


</details>

<details markdown="1"><summary>Рівень 2</summary>

Перехід до старту кожного шестикутника:
```

turtle.setheading(0)
turtle.pendown()
```


</details>

<details markdown="1"><summary>Рівень 3</summary>

    else:
        ...
    (перехід у (0, -size), як вище)

<details markdown="1"><summary>Рівень 1</summary>

## 1.8 Математична троянда r = 180 · cos(15θ)

### Що має вийти
Рисунок 8: чорне тло, квітка з 15 вузьких пелюсток. Біля центру лінії пурпурові (magenta),
на кінцях пелюсток блакитні (cyan). Товщина 2.

### Математика простими словами
Це крива в полярних координатах: для кожного кута θ рахуєш відстань від центру r.

```
r = 180 · cos(15θ)

θ = 0°  → cos 0° = 1       → r = 180   (кінчик пелюстки праворуч)
θ = 6°  → cos 90° = 0      → r = 0     (повернулися в центр)
θ = 12° → cos 180° = -1    → r = -180  (від'ємний r = точка в ПРОТИЛЕЖНИЙ бік)
```

Тобто одна пелюстка - це 12° кута. Від'ємний r малює пелюстку з протилежного боку,
тому за 0° ... 180° усі 15 пелюсток уже намальовані, а 180° ... 360° проходить по них удруге
(для непарного числа 15 так завжди). Нічого не ламається - просто лінія двічі.

Перехід у звичайні координати:

```
x = r · cos θ
y = r · sin θ
```

Радіани: `theta = math.radians(angle)`. І ще: всередині `cos(15θ)` теж радіани - якщо theta вже
в радіанах, то `math.cos(15 * theta)` правильно.

Колір: `abs(r) > 100` → cyan, інакше magenta. Беремо МОДУЛЬ, бо r буває від'ємним,
а пелюстка при r = -150 така ж довга, як при r = 150.

### План
1. Тло, `speed(0)`, `pensize(2)`, `import math`.
2. Перша точка (θ = 0): порахувати x, y, `penup`, `goto`, `pendown`.
3. `for angle in range(1, 361)`: theta у радіанах, r, x, y, колір за |r|, `goto(x, y)`.
4. `hideturtle()`, `done()`.

### Підказки
<details markdown="1"><summary>Рівень 1</summary>

Крок 1° достатній: на пелюстку припадає 12 точок, виходить гладко.


</details>

<details markdown="1"><summary>Рівень 2</summary>

```
theta = math.radians(angle)
radius = 180 * math.cos(15 * theta)
```


</details>

<details markdown="1"><summary>Рівень 3</summary>

```
for angle in range(...):
    theta = ...
    radius = ...
    point_x = radius * math.cos(theta)
    point_y = ...
    if abs(radius) > 100:
        turtle.pencolor("cyan")
    else:
        ...
    turtle.goto(point_x, point_y)
```


</details>

### Типові помилки
- `math.cos(angle)` без `radians` - вийде хаотична «зірка» з ламаних ліній, бо 1, 2, 3 ... сприймаються як радіани (1 рад ≈ 57°).
- Не підняли перо перед першою точкою - з центру (0, 0) до (180, 0) тягнеться зайва лінія. На рисунку її теж можна не помітити, бо вона лягає на пелюстку, але правильно - `penup`.
- `if radius > 100` без `abs` - половина пелюсток (з від'ємним r) буде повністю пурпурова.
- `range(360)` - не дійде до 360° і може лишитися щілина. `range(361)` або `range(1, 361)` після першої точки.

## 1.11 Пейзаж через декомпозицію

### Що має вийти
Рисунок на стор. 17 праворуч: персикове небо смугами, жовте сонце, помаранчеві гори позаду,
теракотові ближче, пурпурова вода, темно-фіолетові скелі спереду зліва і справа, 8 птахів-«галочок».

### Що головне в цьому завданні
Тут оцінюють не точність гір до пікселя, а СТРУКТУРУ:
1. Функція `draw_polygon(t, points, color)` - одна на всі фігури. Приймає черепашку, список
   точок `[(x, y), ...]` і колір, малює залитий багатокутник.
2. Функція `draw_bird(t, x, y, size)` - птах із двох дуг `circle(radius, extent)`.
3. Малювати ВІД ЗАДНЬОГО ПЛАНУ ДО ПЕРЕДНЬОГО (Z-index з теорії, стор. 6): небо → сонце →
   далекі гори → ближні гори → вода → передній план → птахи. Що намальоване пізніше, лежить зверху.
4. `speed(0)`, `hideturtle()`.
5. Об'єктний стиль: `screen = turtle.Screen()`, `t = turtle.Turtle()` (функції приймають `t`).

### Як отримати координати гір (найбільша робота)
Відкрий картинку з умови в Paint: унизу вікна Paint показує координати курсора в пікселях.
Пройдись по вершинах гори і випиши точки. Але в Paint (0, 0) - ЛІВИЙ ВЕРХНІЙ кут і y росте ВНИЗ,
а в turtle (0, 0) - центр і y вгору. Переведення (картинка 783 × 526):

```
x_turtle = x_paint - 392
y_turtle = 263 - y_paint
```

Зручно зробити маленьку функцію, яка це рахує, і писати точки прямо з Paint.
Вікно того ж розміру: `screen.setup(784, 526)`.

### Птах з двох дуг
`t.circle(radius, extent)` малює ДУГУ: шматок кола на extent градусів. Додатний radius -
дуга вигинається ліворуч, від'ємний - праворуч.
Птах на рисунку - як «галочка» з вигнутими крилами: дві дуги виходять з нижньої точки вгору-вліво і вгору-вправо.

```
ліве крило:  з нижньої точки, напрям 145° (вгору-вліво), circle(size, 40)
праве крило: з тієї ж точки,  напрям 35° (вгору-вправо),  circle(-size, 40)
```

Між крилами - `penup`, `goto` назад у нижню точку, `pendown`. Товщина 3-5, колір темно-коричневий.

### План
1. `screen`, `t`, розмір вікна, `t.speed(0)`, `t.hideturtle()`.
2. `draw_polygon`: `penup` → `goto(перша точка)` → `pendown` → `color` → `begin_fill` → `goto` по всіх
   інших → `goto(перша)` (замкнути!) → `end_fill`.
3. Небо - 2-3 прямокутники різного відтінку через ту ж `draw_polygon`.
4. Сонце - `begin_fill`, `circle(44)`, `end_fill` (почати з точки на 44 нижче центру, як у 1.5).
5. Гори, вода, передній план - по одному виклику `draw_polygon` зі своїм списком точок.
6. Список птахів `[(x, y, size), ...]` і цикл з `draw_bird`.

## Завдання 2. Інтерактивний годинник

### Що має вийти
Рисунок стор. 18: зліва аналоговий (біле тло, коло з 60 поділками, 12 жирних, три стрілки:
годинна товста коротка, хвилинна довша, секундна червона тонка). Справа цифровий
(чорне тло, великі зелені цифри HH:MM:SS і дата). Числа 1-12 умова теж вимагає (на рисунку їх нема).

### Що потрібно (за умовою)
1. Аналоговий режим: циферблат, 12 поділок + числа, 3 стрілки різні товщиною, довжиною, кольором.
2. Ліва кнопка миші - аналоговий / цифровий. Права - показати / сховати дату з днем тижня.
3. Мінімум 3 теми, Up/Right - наступна, Down/Left - попередня. Тема міняє фон, циферблат, кожну стрілку, текст.
4. На 00 секунд - спалах (фон іншим кольором).
5. Без миготіння: `screen.tracer(0)` + `screen.update()` + `screen.ontimer(...)`.

### Математика стрілок (найважливіше)
Кут на годиннику рахуємо від 12 ЗА годинниковою стрілкою.

```
секундна:  6° за секунду                         (360 / 60)
хвилинна:  6° за хвилину + 0,1° за секунду        (6 / 60 = 0,1)
годинна:   30° за годину + 0,5° за хвилину        (360 / 12 = 30,  30 / 60 = 0,5)
           + 0,5/60 ° за секунду

кут_год = (hours % 12) · 30 + minutes · 0,5 + seconds · 0,5 / 60
кут_хв  = minutes · 6 + seconds · 0,1
кут_сек = seconds · 6
```

Перевірка на числах: 15:30:00 → годинна (3 · 30) + 30 · 0,5 = 90 + 15 = 105° (між 3 і 4, як і має бути о пів на четверту).

Це і є «розширені формули з урахуванням хвилин і секунд» з умови (теорія стор. 7-8:
Δθ = 6°, 1 крок = 0,1°).

А turtle рахує напрям від осі x ПРОТИ годинникової. Переведення:

```
heading = 90 - кут_годинника

12 год (0°)  → heading 90  (вгору)
3 год (90°)  → heading 0   (праворуч)
6 год (180°) → heading -90 (вниз)
```

Числа 1-12 на колі (теорія стор. 7): для числа k кут годинника k · 30, у математичному куті

```
φ = 90° - k · 30°
x = R · cos φ,   y = R · sin φ      (φ - у радіани!)
```

### Архітектура (8 кроків з теорії, стор. 10)
1. Імпорти: `turtle`, `math`, `datetime`.
2. `screen = turtle.Screen()`, `screen.tracer(0)`, `t = turtle.Turtle()`, `t.hideturtle()`.
3. Змінні стану: `is_digital_mode = False`, `show_date = False`, `theme_index = 0`, список тем.
4. Функції малювання: `draw_face`, `draw_hand`, `draw_analog`, `draw_digital`.
5. Обробники: `handle_left_click(x, y)`, `handle_right_click(x, y)`, `next_theme()`, `prev_theme()` - всередині `global`.
6. Реєстрація: `screen.onclick(..., btn=1)`, `screen.onclick(..., btn=3)`, `screen.listen()`, `screen.onkey(...)` для 4 клавіш.
7. `main_loop()`: `t.clear()` → намалювати все → `screen.update()` → `screen.ontimer(main_loop, 100)`.
8. Виклик `main_loop()` один раз і `screen.mainloop()`.

## Завдання 3. Пружні зіткнення: стіна - мала кулька - велика кулька

### Що має вийти
1. Програма питає m, M, L, v і перевіряє, що це додатні числа.
2. Подієве моделювання (БЕЗ кроку dt!): рахуємо, КОЛИ буде наступне зіткнення, і одразу переносимо кульки туди.
3. Кількість зіткнень N і шлях малої кульки S до ОСТАННЬОГО удару об стіну.
4. Анімація turtle: стіна, дві кульки, напрям руху (стрілки), бажано швидкості.
5. Графіки matplotlib: S(m), S(M), S(L), S(v) - по 20+ точок кожен; N(M/m) - широкий діапазон.
6. Фізичний аналіз - відповіді на 8 питань.

### Фізика простими словами
Стіна в x = 0. Мала кулька стартує з x = L/2 і летить до стіни зі швидкістю -v.
Велика стоїть у x = L.

Між зіткненнями сил немає, тому рух рівномірний: `x(t) = x0 + v·t`.

**Коли вдариться об стіну** (лише якщо летить вліво, v_m < 0):
```
x_m + v_m · t = 0   ⇒   t = -x_m / v_m
```
**Коли наздожене велику** (лише якщо v_m > v_M, тобто відстань скорочується):
```
x_m + v_m·t = x_M + v_M·t   ⇒   t = (x_M - x_m) / (v_m - v_M)
```
Наступна подія - та, в якої t менший.

**Після удару об стіну:** `v_m = -v_m` (модуль той самий, знак інший).
**Після зіткнення кульок** (формули з теорії, стор. 11):
```
       (m - M)·v_m + 2M·v_M              2m·v_m + (M - m)·v_M
u_m = ──────────────────────      u_M = ──────────────────────
              m + M                             m + M
```
Перевір на числах: m = M = 1, v_m = 2, v_M = 0 → u_m = 0, u_M = 2 (обмін швидкостями, як у більярді).

**Коли кінець:** мала летить вправо, але не швидше за велику: `0 ≤ v_m ≤ v_M` - вона вже не наздожене,
а стіна позаду. Велика весь час тільки віддаляється (її штовхають лише зліва).

**Шлях** - сума модулів: `S = S + |v_m| · t` на кожному етапі. Але умова каже рахувати S до
ОСТАННЬОГО удару об стіну (стор. 20), тому запам'ятовуй S щоразу при ударі об стіну.

### План (функції)
1. `read_positive(prompt)` - `while True` + `try/except ValueError` + перевірка `> 0`.
2. `elastic_velocities(m1, m2, v1, v2)` → `(u1, u2)`, з doctest (рівні маси - обмін).
3. `next_event(x_m, v_m, x_M, v_M)` → `(час, "wall" / "balls" / "none")`.
4. `simulate(m, M, L, v)` → словник: список подій `(t, x_m, v_m, x_M, v_M)`, S, N.
5. `animate(...)` - turtle: `tracer(0)`, кульки - `turtle.Turtle(shape="circle")` з `shapesize`,
   на кожному кадрі позиції з рівномірного руху між подіями, `ontimer`.
6. `plot_dependencies(...)` - 4 графіки `plt.subplot(2, 2, k)` + окремий N(r) у log-log.
7. `main()`.

### Що вийде на графіках і чому (для фізичного аналізу)
1. **S(v) - горизонтальна пряма.** Найважливіше пояснення. Усі моменти зіткнень пропорційні 1/v,
   а місця зіткнень від v не залежать: швидша кулька проходить ТОЙ САМИЙ маршрут, просто швидше
   (як той самий фільм, прокручений швидше). Шлях - це довжина маршруту, тому не змінюється.
2. **S(L) - пряма через нуль.** Якщо всі відстані збільшити вдвічі, вся картина зіткнень просто
   масштабується, кількість і порядок ударів ті самі → S ∝ L.
3. **S(m) і S(M) залежать лише від відношення r = M/m** (формули швидкостей містять тільки відношення мас).
   Більше r → більше відскоків між стіною і великою кулькою → більше S. Мала кулька ЛЕГША →
   шлях ДОВШИЙ. Графіки «сходинками», бо N ціле: поки N не змінюється, S майже стоїть, при зміні N - стрибок.
   Якщо m ≥ M - лише один удар об стіну, S = L/2.
4. **N(r).** Моделювання дає (перевірено для r від 1 до 10⁶):
```
N ≈ (π / 2) · √(M / m)       точніше N = ⌈ π / (2·arctg√(m/M)) ⌉
r = 100   → N = 16
r = 10⁴   → N = 158
r = 10⁶   → N = 1571  (= 1570,8 → цифри π!)
```
   Це відома задача «більярд Гальперіна» (G. Galperin, Regular and Chaotic Dynamics, 2003):
   там велика кулька НАЛІТАЄ на малу, і N дає цифри π (r = 100 → 31, r = 10⁴ → 314).
   У нашій ЛР велика спочатку стоїть, тому зіткнень приблизно вдвічі менше: π/2 · √r.
   Звідки π: якщо ввести координати √m·x_m і √M·x_M, енергія стає «довжиною вектора»,
   кожне зіткнення - віддзеркалення, і кулька «ходить» у куті з кутом arctg√(m/M). Скільки
   віддзеркалень влазить у 90° - стільки й зіткнень. (Глибоко пояснювати на захисті не обов'язково, але це сильний аргумент.)
5. **M = m:** після удару об стіну мала наздоганяє велику, вони обмінюються швидкостями,
   мала зупиняється. N = 2, S = L/2.
6. **M ≫ m:** велика майже не зрушує з місця при кожному ударі, мала відскакує майже з тією ж
   швидкістю, ходить туди-сюди дуже багато разів. N росте як √(M/m), S теж росте (швидше за √r).
7. **Стіна не змінює енергію:** модуль швидкості той самий (u = -v), а E = mv²/2 залежить від v²,
   тобто від модуля. Стіна нескінченно масивна (M → ∞ у формулі), вона нічого не забирає.
8. **Кульки обидві міняють швидкість:** за 3-м законом Ньютона сили однакові й протилежні, а
   маси скінченні, тому імпульс передається - і він, і енергія зберігаються лише СУМАРНО.

### Типові помилки
- Крок `dt` замість подій - умова прямо забороняє («Не використовуйте ... фіксованим малим кроком часу dt»).
- Ділення на нуль: `t = (x_M - x_m) / (v_m - v_M)`, коли швидкості рівні. Рахувати лише коли `v_m > v_M`.
- `x_m < x_M` в умові кінця: після зіткнення кульки в ОДНІЙ точці (x_m == x_M), і така умова дасть нескінченний цикл.
- S рахують до кінця моделювання, а умова - до останнього удару об СТІНУ (для M = 4 це 25, а «повний» шлях 75).
- `float(input())` без `try` - при вводі «abc» програма падає. Умова вимагає перевірку.
- Графік без підписів осей і заголовка - умова їх вимагає (`plt.xlabel`, `plt.ylabel`, `plt.title`).
- Анімація і matplotlib обидва на Tk: показуй графіки ПІСЛЯ того, як закриєш вікно turtle (`turtle.done()` повертає керування, коли вікно закрите).
