Підказка 1 - з чого почати

Спершу заготовка в main і push - щоб обидва клони почали з одного місця. Свою гілку okruhlennia створи одразу після push, ще до того, як одногрупник щось зробить - так буває в житті: ви почали паралельно.

Підказка 2 - чому doctest падає в кожного

Перший тест shliakh(0, 2, 3) ловить формулу (без / 2 вийде 18), другий shliakh(0.1, 0, 3) ловить округлення (без round вийде 0.30000000000000004). Тож у кожного з вас падає рівно один тест - «чужа» частина. Це нормально: готово буде лише тоді, коли обидві правки зійдуться в одному рядку.

Підказка 3 - як розвʼязати конфлікт PR

Кнопка на сайті не завжди може розвʼязати конфлікт, а в терміналі - завжди. Забери свіжий main з GitHub (git fetch) і злий його у свою гілку: git merge origin/main. Далі - як в уроці 08: маркери, nano, doctest, git add, git commit, git push. PR оновиться сам - він показує гілку, а не окремі коміти.

Підказка 4 - який рядок лишити

Ні «свій», ні «чужий»: у кожному лише одна з двох правок. Потрібен третій рядок, де є і / 2, і round(..., 2).
