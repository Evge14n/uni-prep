Linux за 10 днів по 15 хв

Щоб писати і запускати лаби з Python в Ubuntu (WSL) на ноутбуці. День = одна тема: 5 хв прочитати, 10 хв зробити руками в терміналі, 5 питань самоперевірки. Усі вправи «Руками» прогнано скриптом у справжній Ubuntu 24.04 (87 перевірок, 17.11.2026).

Тема 0. Встановлення: Ubuntu, VS Code, усе для лаб

Крок 0. Що таке WSL, коротко

WSL - це справжня Ubuntu всередині Windows. Не віртуалка з окремим вікном, а термінал: відкрив «Ubuntu» з меню Пуск - і ти в Linux. Файли Windows там теж видно (диск C: це /mnt/c).

Крок 1. Перевір версію Windows (1 хв)

Win + R → winver → Enter. Дивись рядок «Збірка ОС» (OS Build).

  • Windows 11 - усе працює, включно з вікнами turtle.
  • Windows 10, збірка 19044 або більша (19045 теж) - усе працює, включно з вікнами turtle (потрібен свіжий WSL: wsl --update, крок 2). → Перевірено на твоєму ПК 17.11.2026: Windows 10 збірка 19045, WSL 3.0.5, вікно Tk у WSL відкривається.
  • Windows 10, збірка від 19041 до 19043 - Ubuntu встановиться, але вікна (turtle) з Linux не відкриються. Тоді або онови Windows (Параметри → Оновлення), або turtle-лабу запускай звичайним Python у Windows (крок 6).
  • Менше 19041 - спершу онови Windows.

Джерела: Microsoft, «Install WSL» (Windows 10 2004+, збірка 19041+) і «Run Linux GUI apps with WSL» («Windows 10 Build 19044+ or Windows 11»), learn.microsoft.com, перевірено 17.11.2026.

Крок 2. Встановити Ubuntu (10-20 хв, більшість - чекати)

  1. Пуск → набери PowerShell → правою кнопкою → «Запуск від імені адміністратора».
  2. Введи і натисни Enter: wsl --install Ставить WSL і Ubuntu (Ubuntu - за замовчуванням).
  3. Перезавантаж ноутбук, коли попросить.
  4. Після перезавантаження відкриється вікно Ubuntu (або відкрий «Ubuntu» з меню Пуск). Воно попросить: - username - ім'я в Linux, маленькими латинськими, без пробілів, напр. evgen; - password - пароль. Коли друкуєш, нічого не видно, навіть зірочок. Це нормально. Запам'ятай його: він потрібен для sudo (день 4).
  5. Побачиш рядок типу evgen@NOUT:~$ - ти в Linux.

Якщо wsl --install пише, що WSL уже є, - просто відкрий «Ubuntu» з меню Пуск. Якщо Ubuntu нема в меню: wsl --install -d Ubuntu в адмінському PowerShell.

Одразу після встановлення (у звичайному PowerShell):

wsl --update
wsl --version

wsl --update ставить найновіший WSL з Microsoft Store - саме він уміє відкривати вікна (turtle) на Windows 10. wsl --version має показати кілька рядків (WSL version, WSLg version). Якщо пише, що такої команди нема, - WSL старий, повтори wsl --update.

Крок 3. Встановити VS Code з розширеннями (5 хв)

  1. Скачай VS Code з https://code.visualstudio.com і встав у Windows (не в Ubuntu). У майстрі встановлення залиш галочку «Add to PATH» - без неї не працюватиме code . з Ubuntu.
  2. Відкрий VS Code → ліворуч значок «Extensions» (чотири квадратики) → встанови: - WSL (від Microsoft, id ms-vscode-remote.remote-wsl); - Python (від Microsoft, id ms-python.python).
  3. Закрий і заново відкрий вікно Ubuntu (щоб воно побачило code).
  4. Після першого code . з Ubuntu (крок 5) зайди в Extensions: біля Python буде кнопка «Install in WSL: Ubuntu» - натисни. Розширення з Windows саме в Ubuntu не працює, без цього не буде вибору інтерпретатора і підказок.

Крок 4. Усе для лаб одним скриптом (5-20 хв)

У вікні Ubuntu по черзі (після кожного рядка Enter):

cd ~
wget -O ustanovka.sh https://evge14n.github.io/uni-prep/files/ustanovka.sh
less ustanovka.sh
bash ustanovka.sh
  • wget скачує файл (-O ustanovka.sh - зберегти саме під цим імʼям, навіть якщо скачуєш удруге), less показує, що в ньому (гортати стрілками, вийти - q). Завжди дивись, що за скрипт, перш ніж запускати.
  • bash ustanovka.sh попросить пароль Ubuntu (символи не видно). Перший раз оновлення йде довго. Не закривай вікно, поки не з'явиться «Готово» - якщо закрити посередині, Ubuntu обірве встановлення (див. «Якщо щось пішло не так»).

Що робить скрипт (той самий файл лежить у Linux\ustanovka.sh): 1. Оновлює Ubuntu (apt update, apt upgrade). 2. Ставить python3, venv, pip, python3-tk (для turtle), pytest, flake8, git, nano, tree. 3. Робить теку ~/univer і в ній віртуальне середовище .venv з pytest, flake8, black, pycodestyle, ruff, mypy, matplotlib, numpy (те, що просить викладач). 4. Робить теку ~/univer/labs для лаб і ~/univer/praktyka для вправ курсу. 5. Додає дві команди: univer (перейти в ~/univer і увімкнути venv) і perevir файл.py (doctest + flake8 + mypy одним махом).

Потім один раз скажи git, хто ти:

git config --global user.name "Твоє Імʼя Прізвище"
git config --global user.email "твоя@пошта"

Крок 5. Перевір, що все працює (2 хв)

Закрий і знову відкрий Ubuntu, потім:

univer
python --version
type perevir
code .
  • univer - рядок почнеться з (.venv). Це значить, що venv увімкнено.
  • python --version - Python 3.12.x.
  • type perevir - перший рядок «perevir is a function». Як нею користуватись - день 8.
  • code . - відкриється VS Code, внизу ліворуч зелене «WSL: Ubuntu». Перший раз довантажує сервер у Ubuntu, це хвилина.

Перевірка turtle (вікно має з'явитися на 2 секунди):

python -c "import turtle; turtle.forward(100); turtle.left(90); turtle.forward(50); import time; time.sleep(2)"

Крок 6. Де тримати лаби і як віддати файл

Рекомендую: лаби в Linux, у ~/univer/labs/ЛР4 і т. д. Там усе працює найшвидше (Microsoft прямо радить тримати файли проєкту у файловій системі WSL, а не в /mnt/c).

  • Відкрити теку лаби у Провіднику Windows (щоб скинути файл викладачу, на флешку, у Moodle): cd ~/univer/labs/ЛР4 explorer.exe . Крапка в кінці обов'язкова. Адреса в Провіднику буде \\wsl.localhost\Ubuntu\home\evgen\....
  • Забрати файл з Windows у Linux (напр. заготовку з «Завантажень»): cp /mnt/c/Users/IMYA/Downloads/lab4.py ~/univer/labs/ЛР4/ Замість IMYA - імʼя Windows-користувача (подивись: ls /mnt/c/Users). Апостроф у команду не пиши: bash сприйме його як лапку і чекатиме продовження (рядок >; вийти - Ctrl+C).

Якщо лаби вже лежать у теці Windows і хочеш працювати прямо там - можна. Тоді один раз:

NO_APT=1 bash ustanovka.sh "C:\Users\IMYA\Documents\Програмування"

(NO_APT=1 - не оновлювати Ubuntu вдруге), і в ~/univer/prog буде посилання на цю теку. Працює, просто повільніше на великих теках.

ЛР4 (turtle) і цей курс не сперечаються. Розбір ЛР4 (Лабораторні\ЛР4\) радить для turtle звичайний Python у Windows - це найпростіше і точно працює. У WSL turtle теж працює, якщо wsl --version друкує рядок WSLg version (крок 2) і стоїть python3-tk (його ставить ustanovka.sh). Обирай будь-що; Linux у цьому курсі - для решти: перевірки perevir, git, скрипти.

Turtle (ЛР4), якщо вікно не з'явилося (стара збірка Windows 10, крок 1): той самий файл запускай звичайним Python у Windows - відкрий його у VS Code без WSL (File → Open Folder на Windows-теці) або в IDLE і натисни Run. Код однаковий, різниця лише де запускаєш.

Тема 1. День 1: Термінал і де які файли

Навіщо: у терміналі ти пишеш команду, Enter - Linux виконує. Усе інше в курсі на цьому стоїть.

Коротко (5 хв)

Відкрий «Ubuntu» з меню Пуск. Бачиш рядок-запрошення:

evgen@NOUT:~$
 │     │   │ └ $ - чекаю команду (у root тут #)
 │     │   └── ~ - де ти зараз (~ = твоя домашня тека)
 │     └────── ім'я комп'ютера
 └──────────── ім'я користувача

Як влаштовані файли. У Windows є диски C:, D:. У Linux одне «дерево», корінь - /.

/                      корінь
├── home/evgen/        твоя домашня тека, вона ж ~
│   └── univer/        лаби (зробив скрипт установки)
├── mnt/c/             диск C: Windows
├── mnt/d/             диск D: Windows (якщо є)
├── usr/bin/           програми (python3, git, ls)
└── tmp/               тимчасове, чиститься
  • Шлях абсолютний починається з /: /home/evgen/univer.
  • Відносний - від того місця, де ти зараз: univer/labs.
  • . - ця тека, .. - тека вище, ~ - домашня.
  • Великі й малі літери різні: Lab.py і lab.py - два різні файли.
  • Роздільник /, а не \ як у Windows.

Команди дня:

Команда Що робить
pwd де я (print working directory)
ls що тут лежить
ls -la детально (-l), з прихованими (-a, імена з крапкою)
cd тека зайти в теку
cd .. на рівень вище
cd або cd ~ додому
cd - туди, де був перед цим
clear або Ctrl+L очистити екран
команда --help коротка довідка
man команда повна довідка (вийти - q)

Дві клавіші, що економлять години: - Tab - дописує назву файлу чи теки. Набери cd uni і Tab - стане cd univer/. Два Tab підряд - покаже варіанти. Особливо рятує з кириличними назвами. - Стрілка ↑ - попередня команда. Ctrl+R - пошук по історії.

Скопіювати і вставити у вікні Ubuntu: виділи мишкою і натисни Enter (або Ctrl+Shift+C) - скопійовано; вставити - права кнопка миші або Ctrl+Shift+V. (Ctrl+C без виділення - це не «копіювати», а «зупинити програму», день 6. У новому Windows Terminal Ctrl+C з виділеним текстом копіює.)

cd univer
pwd                      # /home/evgen/univer

pwd                      # знову /home/evgen
cd /mnt/c/Users

cd ~

Відкрий свою домашню теку в Провіднику Windows:

cd ~
explorer.exe .

Завдання: не дивлячись нижче, дійди до теки ~/univer/labs двома способами: одним абсолютним шляхом і кроками cd по одній теці.

Типові помилки

  • cd Univer → «No such file or directory». Регістр! Тека univer. Тисни Tab, а не вгадуй.
  • cd C:\Users - так у Linux не буде. Правильно cd /mnt/c/Users.
  • Назва з пробілом: cd Мої документи - Linux бачить два слова. Треба cd "Мої документи" або cd Мої\ документи (Tab сам поставить \).
  • Працювати з лабами в /mnt/c/... можна, але повільно. Лаби тримай у ~/univer/labs.

Самоперевірка

  1. Ти в /home/evgen/univer/labs. Куди потрапиш після cd ../..?
  2. Чим відрізняються ls і ls -a?
  3. Як у Linux називається диск D: Windows?
  4. Що означає ~ у шляху?
  5. Ти набрав cd lab і Tab нічого не дописав. Чому так може бути?
Відповіді
  1. /home/evgen. Кожне .. - на теку вище: labs → univer → evgen.
  2. ls -a показує ще й приховані файли, чиї імена починаються з крапки (.bashrc, .venv), і . та ...
  3. /mnt/d.
  4. Твоя домашня тека, /home/evgen.
  5. Такої теки тут нема (можливо, вона в іншому місці або називається з великої), або є кілька варіантів на lab... - тоді другий Tab покаже їх список.

Тема 2. День 2: Створити, скопіювати, видалити безпечно

Навіщо: щоб робити теки для лаб, копії перед правками і не стерти потрібне.

Коротко (5 хв)

Команда Що робить
mkdir ЛР4 створити теку
mkdir -p labs/ЛР4/data створити з усіма проміжними, без помилки якщо вже є
touch main.py створити порожній файл (або оновити час зміни)
cp a.py b.py копія файлу
cp -r ЛР3 ЛР3-копія копія теки з усім вмістом (-r = рекурсивно)
mv a.py b.py перейменувати
mv a.py labs/ перемістити в теку
rm файл видалити файл
rm -r тека видалити теку з усім вмістом
rmdir тека видалити лише порожню теку (безпечний варіант)
rm -i файл спитає «remove?» перед кожним видаленням

Шаблони (wildcards): * - будь-які символи, ? - один символ. ls *.py - усі файли Python, cp *.py backup/ - скопіювати всі.

Головне правило: у Linux нема кошика. rm стирає назавжди. Тому:

  1. Спершу ls з тим самим шаблоном - подивись, що саме видалиш: ls *.png # бачу 3 картинки - ок rm *.png
  2. Не використовуй rm -rf, поки не розумієш кожну букву. -r - теки з усім вмістом, -f - не питати і не скаржитись. Один зайвий пробіл після тильди (між ~ і /тека) - і замість однієї теки стирається вся домашня тека. (Це приклад словами, такого не вводь.)
  3. Ніколи не запускай rm з sudo, якщо не розумієш навіщо.
  4. Важливе - в git (день 9), тоді навіть видалене можна повернути.
  5. cp і mv мовчки перезаписують файл з тим самим ім'ям. Додавай -i: cp -i, mv -i - спитає.

Пробіли й кирилиця в назвах. Назви тек краще без пробілів: ЛР4, lab_4. Якщо пробіл є - бери в лапки: cp "Лабораторна 4.pdf" ЛР4/.

Руками (10 хв)

cd ~/univer/praktyka
mkdir -p den2/a/b
ls -R den2              # покаже дерево тек
touch den2/a/one.py den2/a/two.py den2/a/notes.txt
ls den2/a/*.py
cp den2/a/one.py den2/a/one_backup.py
mv den2/a/two.py den2/a/b/
mv den2/a/notes.txt den2/a/note.txt
tree den2               # гарне дерево
rm -i den2/a/one_backup.py     # відповідай y
rmdir den2/a/b          # помилка: тека не порожня - так і має бути
ls den2/a/b
rm den2/a/b/two.py
rmdir den2/a/b          # тепер вийшло
mkdir "моя тека"
ls
rmdir "моя тека"
cd den2/a
echo rm *.py            # echo лише ДРУКУЄ, на що розгорнеться шаблон: rm one.py
echo rm * .py           # з пробілом: rm note.txt one.py .py - тобто ВСЕ. Тому пробіл тут небезпечний
cd ~/univer/praktyka

Зроби теку для 4-ї лаби (знадобиться в дні 8):

mkdir -p ~/univer/labs/ЛР4

Типові помилки

  • rm -rf /mnt/d/... - стирає файли Windows назавжди, теж без кошика. З /mnt/c і /mnt/d - лише копіювати.
  • mkdir ЛР 4 створює дві теки: ЛР і 4.
  • cp тека нова без -r → «-r not specified; omitting directory».
  • mv lab.py lab.py.bak і забув - потім шукаєш, «де файл». Для копії бери cp.
  • Шаблон з випадковим пробілом між * і .py видаляє все в теці. Перевірка без ризику - поставити echo перед командою: побачиш, які файли вона зачепила б.

Самоперевірка

  1. Чим mkdir -p a/b/c відрізняється від mkdir a/b/c?
  2. Як перейменувати lab.py на lab4.py?
  3. Чому rmdir безпечніший за rm -r?
  4. Що станеться після cp new.py old.py, якщо old.py вже є?
  5. Що зробила б команда rm з шаблоном * .py (з пробілом між зірочкою і .py) і як це перевірити без ризику?
Відповіді
  1. -p створює всі проміжні теки (a, a/b) і не скаржиться, якщо тека вже є. Без -p - помилка, якщо a/b нема.
  2. mv lab.py lab4.py.
  3. rmdir видаляє лише порожню теку, тому файли не загубиш. rm -r видаляє все всередині.
  4. old.py мовчки перезапишеться вмістом new.py. З cp -i спитало б.
  5. Пробіл робить з шаблону два аргументи: * (усі файли в теці) і .py. Видалила б усі файли. Перевірити: echo або ls з тим самим шаблоном перед rm, і писати *.py разом.

Тема 3. День 3: Переглянути і редагувати: nano і VS Code

Навіщо: швидко глянути файл, поправити рядок у терміналі, а лаби писати в нормальному редакторі.

Коротко (5 хв)

Подивитись файл:

Команда Що робить
cat файл вивести весь файл (для коротких)

Тема 4. День 4: Права і sudo

Навіщо: розуміти «Permission denied», запускати свої скрипти і не ламати систему через sudo.

Коротко (5 хв)

Хто ти: whoami → evgen. id → твої групи (є sudo - значить, можеш бути адміністратором).

Права файлу - у ls -l:

-rwxr-xr--  1 evgen evgen  512 Nov 17 10:00 run.sh
│└┬┘└┬┘└┬┘    │     │
│ │  │  │     │     └ група
│ │  │  │     └────── власник
│ │  │  └ інші (others):   r--  лише читати
│ │  └─── група (group):   r-x  читати і запускати
│ └────── власник (user):  rwx  читати, писати, запускати
└──────── тип: - файл, d тека, l посилання

r = read (читати), w = write (змінювати), x = execute (запускати; для теки - заходити в неї).

Числа замість букв: r = 4, w = 2, x = 1, додаєш для кожної трійки. rwx = 4+2+1 = 7, r-x = 4+1 = 5, r-- = 4. Тому: - chmod 755 run.sh → rwxr-xr-x (скрипт: усі можуть запускати, змінює лише власник); - chmod 644 lab.py → rw-r--r-- (звичайний файл).

Простіше буквами: chmod +x run.sh - дозволити запуск, chmod -w file - заборонити зміну.

Запуск свого скрипта: ./run.sh (./ = «з цієї теки»). Без chmod +x буде «Permission denied». Можна і без прав: bash run.sh, python3 lab.py.

sudo - «зробити від імені адміністратора (root)». sudo apt install ... спитає твій пароль Ubuntu (символи не видно). Пароль памʼятається ~15 хв.

Правила: - sudo - лише для системного: apt, файли поза домашньою текою. - Свої файли (~/...) ніколи не чіпай через sudo: файли стануть власністю root, і потім без sudo їх не зміниш. Ознака: у ls -l власник root. - sudo pip install - не роби. Python-пакети для лаб - у venv (день 8).

Особливість WSL: файли на /mnt/c і /mnt/d показують права як rwxrwxrwx - це диск Windows, справжні права там вирішує Windows. chmod на них зазвичай нічого не змінює.

Руками (10 хв)

whoami
id
cd ~/univer/praktyka
printf 'echo "Привіт з скрипта"\n' > run.sh
ls -l run.sh             # -rw-r--r-- : x нема
./run.sh                 # Permission denied
bash run.sh              # працює: bash сам читає файл
chmod +x run.sh
ls -l run.sh             # -rwxr-xr-x
./run.sh                 # тепер працює
chmod 600 run.sh
ls -l run.sh             # -rw------- : лише ти читаєш і пишеш
chmod 755 run.sh
sudo whoami              # спитає пароль, відповідь root
ls -l /etc/hostname      # власник root
echo test > /etc/test.txt          # Permission denied - система не твоя
ls -ld /mnt/c            # drwxrwxrwx - диск Windows

Типові помилки

  • sudo перед усім підряд «щоб не було помилок». Потім Permission denied уже на власних файлах. Виправити: sudo chown -R evgen:evgen ~/univer (повернути собі власність).
  • chmod 777 «щоб працювало». Це дозволяє всім усе. Для скрипта досить chmod +x (або 755).
  • Забув пароль Ubuntu. У PowerShell Windows: wsl -u root passwd evgen (замість evgen - твоє імʼя в Ubuntu, воно в рядку перед @) - задаси новий.
  • Запускаєш run.sh без ./ → «command not found». Поточна тека не шукається автоматично.

Самоперевірка

  1. Що означають права -rw-r--r--?
  2. Яким числом записати rwxr-xr-x?
  3. Чому ./script.sh пише «Permission denied», а bash script.sh працює?
  4. Чий пароль питає sudo у WSL?
  5. Чому не можна sudo nano ~/univer/labs/lab.py?
Відповіді
  1. Звичайний файл; власник читає і пише, група і всі інші лише читають.
  2. 755 (7 = 4+2+1, 5 = 4+1).
  3. У файлу нема права x. bash script.sh запускає bash, а він просто читає файл, тому x не потрібне.
  4. Твій пароль користувача Ubuntu (того, що задав при встановленні), не пароль Windows.
  5. Файл може стати власністю root (якщо nano створить його заново), і потім ти без sudo його не збережеш. Свої файли редагують без sudo.

Тема 5. День 5: Пакети: apt

Навіщо: у Linux програми не качають з сайтів, а ставлять однією командою з перевіреного сховища.

Коротко (5 хв)

apt - менеджер пакетів Ubuntu. Пакет = програма або бібліотека.

Команда Що робить
sudo apt update оновити список пакетів (нічого не ставить)
sudo apt upgrade поставити оновлення всього встановленого
sudo apt install tree встановити пакет
sudo apt remove tree видалити пакет
apt search turtle знайти пакет за словом
apt show python3-tk опис пакета
apt list --installed \| grep python3 що з python3 встановлено

Порядок завжди: спершу update, потім install або upgrade. Раз на тиждень - sudo apt update && sudo apt upgrade. && - «другу команду лише якщо перша пройшла без помилки».

Де шукати, чи програма є: which python3 → /usr/bin/python3. python3 --version - версія.

apt чи pip? - apt - для системи: python3, git, nano, python3-tk. - pip - для Python-бібліотек у venv твого проєкту: matplotlib, numpy, pytest (день 8). - pip install поза venv в Ubuntu 24.04 дає помилку externally-managed-environment. Це захист, щоб не зламати системний Python. Не обходь її прапорцем --break-system-packages - просто увімкни venv.

Руками (10 хв)

sudo apt update
apt list --upgradable           # що можна оновити
which tree
apt show tree | head -5
sudo apt install cowsay         # кумедна програма для тренування
/usr/games/cowsay "Привіт, Linux"
sudo apt remove cowsay
/usr/games/cowsay "ще є?"       # No such file or directory - видалено
dpkg -l python3-tk | tail -1    # ii = встановлено (його поставив ustanovka.sh)
deactivate 2>/dev/null         # вимкнути venv, якщо був увімкнений (рядок без (.venv))
pip install requests            # error: externally-managed-environment - так і треба (буває, думає кілька секунд)
python3 -m venv --help | head -3

Типові помилки

  • apt install без sudo → «Permission denied» / «are you root?».
  • install без update після довгої перерви → «Unable to locate package» або 404. Спершу sudo apt update.
  • Could not get lock /var/lib/dpkg/lock-frontend - інший apt уже працює (часто автооновлення у фоні). Зачекай кілька хвилин. Не видаляй lock-файли.
  • Закрив вікно Ubuntu посеред upgrade → наступного разу «dpkg was interrupted». Виправлення: sudo dpkg --configure -a. (Так сталося і в мене під час налаштування твого ПК 17.11.)
  • sudo pip install або --break-system-packages - ламає системний Python. Бібліотеки - у venv.

Самоперевірка

  1. Чим apt update відрізняється від apt upgrade?
  2. Як встановити програму htop?
  3. Що означає && у sudo apt update && sudo apt upgrade?
  4. Чому pip install numpy поза venv дає externally-managed-environment?
  5. Що робити, якщо бачиш «dpkg was interrupted»?
Відповіді
  1. update лише оновлює список доступних версій, upgrade реально ставить новіші версії встановлених пакетів.
  2. sudo apt update, потім sudo apt install htop.
  3. Друга команда виконається лише якщо перша завершилась успішно.
  4. Ubuntu захищає системний Python від сторонніх пакетів (правило PEP 668). Ставити треба у venv.
  5. sudo dpkg --configure -a - доналаштує обірвані пакети; потім повторити свою команду.

Тема 6. День 6: Процеси

Навіщо: програма з нескінченним циклом (у лабах буває) - її треба вміти зупинити, а не закривати вікно.

Коротко (5 хв)

Процес = запущена програма. У кожного є номер PID.

Команда / клавіші Що робить
Ctrl+C зупинити програму, що працює зараз у терміналі
Ctrl+D «кінець вводу»: вийти з python3 без аргументів, закрити input()
Ctrl+Z призупинити (не зупинити!) і повернути термінал
jobs що призупинено або працює у фоні в цьому терміналі
fg повернути призупинене на передній план
bg продовжити призупинене у фоні
команда & одразу запустити у фоні
ps процеси цього терміналу
pgrep -af python усі процеси python: PID і команда
ps aux \| grep python те саме по-старому (останній рядок - сам grep, його не чіпай)
top (вийти q) або htop живий список: хто їсть процесор і память
kill PID попросити процес завершитись
kill -9 PID вбити без питань (якщо kill не допоміг)
pkill назва вбити за назвою програми. Обережно: pkill python вбʼє ВСІ python, і ті, що працюють для VS Code
free -h, df -h скільки памʼяті, скільки місця на диску

Повністю вимкнути Ubuntu (все зависло): у PowerShell Windows wsl --shutdown. Ubuntu також сама вимикається за кілька секунд, коли закриті всі її вікна - тоді все, що в ній працювало, теж зупиняється.

Руками (10 хв)

cd ~/univer/praktyka
printf 'import time\nn = 0\nwhile True:\n    n += 1\n    time.sleep(1)\n    print(n)\n' > forever.py
cat forever.py
python3 forever.py       # рахує 1, 2, 3... Натисни Ctrl+C
                         # KeyboardInterrupt - це нормально, програму зупинено
python3 forever.py       # знову, а тепер Ctrl+Z
jobs                     # [1]+ Stopped
fg                       # знову рахує; Ctrl+C
python3 forever.py > /dev/null &     # у фоні, вивід викидаємо
jobs
pgrep -af forever        # PID і команда
kill %1                  # %1 - номер у jobs (або kill PID з pgrep)
jobs                     # Terminated
top                      # подивись, q - вийти
free -h
df -h ~

Типові помилки

  • Ctrl+Z замість Ctrl+C - програма «зникла», але висить у памʼяті. jobs покаже. Потім fg і Ctrl+C.
  • Закривати вікно хрестиком, щоб зупинити програму. Працює, але втрачаєш усе в терміналі.
  • kill -9 одразу. Спершу звичайний kill: програма встигне закрити файли.
  • Програма чекає input(), а тобі здається, що вона зависла. Курсор блимає на порожньому рядку - вона чекає вводу. Введи значення або Ctrl+D.
  • Ctrl+C у вікні терміналу без виділеного тексту - не «копіювати», а «зупинити». Як копіювати - день 1.

Самоперевірка

  1. Чим Ctrl+C відрізняється від Ctrl+Z?
  2. Програма в нескінченному циклі. Як зупинити, не закриваючи вікно?
  3. Як знайти PID усіх запущених python?
  4. Що робить & у кінці команди?
  5. Коли потрібен wsl --shutdown?
Відповіді
  1. Ctrl+C зупиняє програму (Python кидає KeyboardInterrupt). Ctrl+Z лише призупиняє: програма жива, її можна повернути fg.
  2. Ctrl+C. Якщо не реагує - в іншому вікні pgrep -af python і kill PID (у крайньому разі kill -9 PID).
  3. pgrep -af python (перше число в рядку - PID). Або ps aux | grep python (друга колонка; рядок з самим grep пропусти).
  4. Запускає команду у фоні, термінал одразу вільний.
  5. Коли зависла вся Ubuntu (не відповідає жодне вікно) або після зміни налаштувань WSL. Виконується в PowerShell Windows.

Тема 7. День 7: Пайпи, перенаправлення, grep

Навіщо: знайти, де в лабах функція, зберегти вивід у файл, порахувати рядки - однією командою.

Коротко (5 хв)

Перенаправлення:

Запис Що робить
команда > файл вивід у файл (файл перезаписується)
команда >> файл дописати в кінець файлу
команда 2> файл помилки (stderr) у файл
команда > файл 2>&1 і вивід, і помилки в один файл
команда < файл взяти ввід з файлу (замість клавіатури)
команда > /dev/null викинути вивід

Пайп | - вивід однієї команди стає входом наступної: ls | wc -l - скільки файлів; history | grep git - які git-команди я вводив.

grep - знайти рядки з текстом:

Команда Що
grep "def " lab.py рядки з def
grep -n з номерами рядків
grep -i без різниці великі/малі
grep -r "turtle" . у всіх файлах теки і підтек
grep -c лише кількість рядків
grep -v рядки, де цього нема

Інші корисні: wc -l (рядки), sort, uniq -c (порахувати однакові сусідні), head, tail, find . -name "*.py" (знайти файли за назвою).

Ввід для програми з input(). Програма питає число - можна подати без клавіатури:

printf "5\n" | python3 lab.py
printf "3\n4\n" | python3 lab.py      # два input() - два рядки
python3 lab.py < vvid.txt

Зручно, коли ганяєш ту саму перевірку багато разів.

Руками (10 хв)

cd ~/univer/praktyka
printf 'def area(r):\n    return 3.14 * r * r\n\n\ndef perimeter(r):\n    return 2 * 3.14 * r\n\nprint(area(2))\n' > geom.py
grep "def " geom.py
grep -n "def " geom.py
grep -c "def " geom.py               # 2
grep -v "^$" geom.py                 # без порожніх рядків
python3 geom.py > out.txt
cat out.txt
python3 geom.py >> out.txt
cat out.txt                          # два рядки
python3 nema.py 2> err.txt
cat err.txt                          # No such file or directory
ls / | wc -l
find ~/univer -name "*.py" -not -path "*/.venv/*" | head
printf 'name = input()\nprint("Привіт,", name)\n' > hi.py
printf "Євген\n" | python3 hi.py
history | grep cd | tail -5

Якщо на цьому ПК чи ноутбуці лаби лежать у ~/univer/prog або ~/univer/labs:

grep -rn "import doctest" ~/univer/labs
grep -rl "turtle" ~/univer/labs

Типові помилки

  • python3 lab.py > lab.py - стирає твій код: > спершу обнуляє файл. Вивід пиши в інший файл.
  • > замість >> - старий вміст пропав.
  • grep def без лапок і з пробілом: grep def area geom.py шукає «def» у файлах area і geom.py. Фраза з пробілом - у лапках: grep "def area" geom.py.
  • grep -r по всьому диску (/ чи /mnt/d) - дуже довго. Шукай у конкретній теці.

Самоперевірка

  1. Чим > відрізняється від >>?
  2. Як порахувати, скільки функцій (def) у файлі lab4.py?
  3. Як запустити lab.py, що питає одне число, і подати йому 10 без клавіатури?
  4. Що робить 2>?
  5. Чому python3 lab.py > lab.py - погана ідея?
Відповіді
  1. > перезаписує файл, >> дописує в кінець.
  2. grep -c "def " lab4.py.
  3. printf "10\n" | python3 lab.py (або echo 10 | python3 lab.py).
  4. Перенаправляє помилки (потік stderr) у файл.
  5. Перед запуском > очищає lab.py, тож Python запускає вже порожній файл, а код зник.

Як перевіряти doctest у лабах. У заготовках викладача в кінці файлу стоїть doctest.testmod().

Команда Коли
python lab4.py як задумав викладач: testmod() у файлі проганяє doctest. Тиша = все пройшло, ***Test Failed*** = ні. Далі програма працює як звичайно (питає input(), малює)
python lab4.py -v те саме з подробицями (-v бачить testmod()), унизу Test passed.
python -m pytest --doctest-modules -q lab4.py надійна перевірка: 1 passed або FAILED і код помилки (зручно в скриптах)
perevir lab4.py наша команда: doctest (через pytest) + flake8 + mypy

Пастка: не запускай python -m doctest lab4.py для таких файлів. Коли в файлі є doctest.testmod() не під if __name__ == "__main__":, команда -m doctest змушує його перевіряти ще й сам модуль doctest, і ти побачиш чужу помилку 1 of 21 in __main__.DebugRunner ***Test Failed***, хоча твій код правильний. python -m doctest годиться лише для файлів, де testmod() нема або він під if __name__ == "__main__":.

Стиль: flake8 --max-line-length=78 lab4.py (викладач просив рядки до 78), mypy lab4.py (типи, знаходить str замість int), black -l 78 lab4.py (сам переформатує файл, перед цим зроби коміт або копію).

Вимоги викладача (з файлу «Вимоги викладача»): лаба зарахована, коли проходять усі doctest; функція повертає через return, а не друкує; код - у наданій функції, назви і doctest не міняти; перед здачею flake8, pycodestyle, mypy, ruff або black.

Якщо в лабі є input() на верхньому рівні файлу (як у твоїй ЛР3), то pytest скаже «reading from stdin» (а perevir підкаже, що робити). Тоді: printf "5\n" | python lab.py - testmod() усередині спрацює, а ввід піде з printf.

turtle (ЛР4) у WSL: на Windows 11 і Windows 10 збірки 19044+ (з WSL з Microsoft Store) вікно відкривається як звичайне вікно Windows. Наприкінці потрібен turtle.done(), інакше вікно одразу закриється (так і в методичці ЛР4). Головне правило для turtle-лаби: малювання і turtle.done() - лише під if __name__ == "__main__":. Інакше перевірка doctest (pytest, perevir) відкриє вікно і чекатиме, поки ти його закриєш. Якщо вікна нема зовсім (стара Windows) - див. «00 - Почни тут», крок 6.

Тема 9. День 9: git

Навіщо: «збереження гри» для коду. Зламав лабу - повернувся до робочої версії за секунду.

Коротко (5 хв)

git запамʼятовує знімки (коміти) теки. Кожен коміт - стан усіх файлів у момент + підпис, що змінив.

правиш файли  →  git add  →  git commit  →  історія (git log)
(робоча тека)    (вибрав,      (знімок
                 що зберегти)   з підписом)
Команда Що робить
git init зробити теку репозиторієм (один раз)
git status що змінено, що вибрано для коміту
git add lab4.py вибрати файл у наступний коміт (git add . - усе)
git commit -m "Завдання 1 готове" зробити коміт з підписом
git log --oneline історія комітів
git diff що змінено з останнього коміту (вийти - q)

Тема 10. День 10: Свій bash-скрипт

Навіщо: команди, які вводиш щоразу перед здачею лаби, - в один файл і запускати одним словом.

Коротко (5 хв)

Bash-скрипт - текстовий файл з командами, по одній на рядок. Те саме, що вводиш руками.

#!/bin/bash
# перший рядок (shebang): яким інтерпретатором запускати
# усе після # - коментар

name="Євген"                 # змінна: БЕЗ пробілів навколо =
echo "Привіт, $name"         # $name - взяти значення

echo "Перший аргумент: $1"   # $1, $2 - те, що написали після назви скрипта
echo "Усього аргументів: $#"

if [ -f "$1" ]; then         # -f: такий файл існує
    echo "Файл $1 є"
else
    echo "Файлу $1 нема"
fi

for f in *.py; do            # цикл по всіх .py у теці
    echo "Знайшов: $f"
done
Перевірка в [ ] Що означає
-f файл файл існує
-d тека тека існує
-z "$x" рядок порожній
"$a" = "$b" рядки рівні
$n -gt 5 число більше 5 (-lt менше, -eq дорівнює)

$? - код завершення останньої команди: 0 = успіх, не 0 = помилка. set -e на початку скрипта - зупинитись на першій помилці.

Запуск: bash skrypt.sh або chmod +x skrypt.sh і ./skrypt.sh.

Alias - коротке імʼя для команди, у ~/.bashrc: alias ll='ls -la'. Після правки source ~/.bashrc. Так зроблені наші univer і perevir (подивись: tail -n 25 ~/.bashrc).

Руками (10 хв): скрипт «перевір усі лаби в теці»

cd ~/univer/praktyka
nano zdaty.sh

Надрукуй:

#!/bin/bash
# zdaty.sh - перевірити всі .py у теці перед здачею
# запуск: ./zdaty.sh ~/univer/labs/ЛР4

folder="${1:-.}"          # якщо теку не дали - поточна
source ~/univer/.venv/bin/activate

if [ ! -d "$folder" ]; then
    echo "Нема теки $folder"
    exit 1
fi

ok=0
bad=0
for f in "$folder"/*.py; do
    if python -m pytest --doctest-modules -q -p no:cacheprovider "$f" < /dev/null > /dev/null 2>&1 && flake8 --max-line-length=78 "$f" > /dev/null; then
        echo "ГОТОВО  $f"
        ok=$((ok + 1))
    else
        echo "ПРАВИТИ $f"
        bad=$((bad + 1))
    fi
done
echo "Готово: $ok, правити: $bad"

Типові помилки

  • name = "Євген" з пробілами - bash думає, що name це команда: name: command not found.

  • [ без пробілів: if [-f "$1"] - помилка. Потрібно if [ -f "$1" ].

  • Забув chmod +x → Permission denied. Або запускай bash zdaty.sh.
  • Лаба з input() на верхньому рівні вийде «ПРАВИТИ» (pytest не дає їй читати клавіатуру) - таку перевір руками: printf "5\n" | python лаба.py, як у дні 8.
