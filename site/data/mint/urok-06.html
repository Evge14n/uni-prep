Коротко

Чотири способи запустити pdb

Передбач, потім запусти

Відповіді - справжній вивід з кроків «Руками» нижче (номер кроку в дужках).

  1. У функції є змінна h (висота). Ти зупинився в pdb і набрав просто h, Enter. Що покаже pdb?
Відповідь

Довідку, а не висоту: h - це команда help (крок 6). Змінну з іменем команди треба писати через p h, а змінювати через !h = 0. Те саме з c, n, s, l, a, b, j, r, w, u, d, q. Ще одна причина давати змінним довгі імена, як вимагає викладач (height_m, а не h).

  1. Програма зупинена в table(). Набираєш !G = 1.62 (як на Місяці), потім p G. Далі u (вгору, у main) і знову p G. Що буде?
Відповідь

У table() - 1.62, у main - 9.81 (крок 5). !G = 1.62 створив нову локальну змінну G всередині table, а глобальна G, якою користується height(), не змінилась. Щоб змінити глобальну: !global G; G = 1.62.

  1. python3 -m pdb -c continue vymiry.py, програма падає, ти дивишся змінні і набираєш q. Ти вийшов з pdb?
Відповідь

Ні. pdb пише Post mortem debugger finished. ... will be restarted і запускає програму знову з першого рядка (крок 7). Треба ще раз q.

  1. У logging.basicConfig рівень DEBUG змінили на WARNING. Які рядки логу лишаться?
Відповідь

Лише WARNING і серйозніші (ERROR, CRITICAL). Рядки DEBUG і INFO зникнуть, а сам код міняти не треба (крок 10, за бажанням).

Тіло кинули вгору зі швидкістю 10 м/с, рахуємо висоту h = v0·t - g·t²/2 кожні 0.5 с. Набери (номери рядків важливі для точок зупинки, тому порожні рядки теж):

"""Тіло кинули вертикально вгору: таблиця висот."""
G = 9.81


def height(v0, t):
    h = v0 * t - G * t ** 2 / 2
    return round(h, 3)


def table(v0, dt, steps):
    rows = []
    for k in range(steps):
        t = k * dt
        h = height(v0, t)
        rows.append((t, h))
    return rows


def main():
    rows = table(10, 0.5, 5)
    for t, h in rows:
        print(f"t = {t:.1f} с   h = {h:6.3f} м")
    print("готово")


main()

(Короткі імена v0, t, h тут як у формулі; у лабі викладач хоче довші.) Спершу просто запусти:

import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(levelname)s %(funcName)s:%(lineno)d %(message)s",

def height(v0, t):
    h = v0 * t - G * t ** 2 / 2
    logging.debug(f"{t=} {h=:.3f}")
    if h < 0:
        logging.warning(f"тіло вже впало, {h=:.3f}")
    return round(h, 3)

    return rows

Типові помилки

  • Змінна з іменем команди (h, c, n, s, l, a, b...): pdb виконує команду. Пиши p h, !h = 0.
  • !G = 1.62 не змінює глобальну G - створює локальну. Треба !global G; G = 1.62.
  • commands з c і потім end → *** NameError: name 'end' is not defined: c уже закінчив список.
  • until «не вийшов» з циклу - на шляху стоїть точка зупинки. Прибери її (cl номер).
  • j у цикл → *** Jump failed: can't jump into the body of a for loop. Стрибати можна лише в межах поточної функції і не всередину циклу.
  • post-mortem q → програма знову з першого рядка. Так задумано (will be restarted), q ще раз.
  • p змінна → NameError у post-mortem - ти не в тій функції. w покаже стек, u/d - перейти.
  • breakpoint() у функції + pytest → OSError: pytest: reading from stdin while output is captured!, а perevir (урок 03) у цьому випадку пише «файл питає input()». Налагоджуй через python3 лаба.py, а перед здачею прибери breakpoint().
  • Номери рядків з'їхали - ти змінив файл, а pdb показує старі номери. Після правки - restart або вийти і запустити знову.
  • logging.basicConfig нічого не змінює - його треба викликати до першого logging.warning(...) / logging.debug(...). Перший такий виклик сам налаштовує logging (рівень WARNING), і пізніший basicConfig(level=logging.DEBUG) уже ігнорується: logging.debug("друге") після нього не друкується.

  • У 2025-2026 у великих проєктах налагоджують у редакторі (VS Code / PyCharm: точки зупинки мишкою, debugpy) - це урок 27, пізніше. Але pdb знає кожен, бо він є всюди: на сервері по ssh, у Docker, на чужому комп'ютері.
  • Python 3.14 додав python -m pdb -p PID - підключитись до програми, що вже працює (PEP 768), і підсвітку коду в pdb. У Mint 22 стоїть 3.12, там цього нема.

Самоперевірка

  1. Як зупинитись у циклі for k in range(1000) лише на k == 500, не натискаючи c 500 разів?
  2. Програма впала з ZeroDivisionError у функції mean. Опиши два способи подивитись значення змінних у момент падіння, не додаючи нічого в код.
  3. У функції є змінна c. Що станеться, якщо в pdb набрати c? Як подивитись значення змінної?
  4. У лабі два doctest впали по-різному: один - Expected: 'T = 2.006 с', Got: 'T = 2.01 с', другий - UNEXPECTED EXCEPTION: TypeError(...). Яким інструментом дивитись змінні в кожному випадку і чому не одним?
  5. Навіщо logging замість print, якщо обидва просто друкують текст? Назви дві переваги.
Відповіді
  1. Точка зупинки з умовою: b номер_рядка, k == 500 (або condition 1 k == 500 для вже поставленої точки). Ще варіант - ignore 1 500.
  2. python3 -m pdb -c continue файл.py - pdb сам зупиниться в місці падіння; або python3 -i файл.py, а після падіння import pdb; pdb.pm(). Далі p змінна, u, w.
  3. pdb виконає команду continue (поїде далі). Значення - p c, змінити - !c = ....
  4. Інше число (Expected/Got): breakpoint() перед return + python3 файл.py -v, на (Pdb) - p t (ввід для input() - руками). Виняток: python3 -m pytest --doctest-modules --pdb файл.py - зупиниться в місці падіння, там p length. --pdb при простому Expected/Got зупиняється всередині pytest, де твоїх змінних нема (крок 8).
  5. Можна вимкнути/увімкнути всі повідомлення одним рівнем (DEBUG → WARNING) без видалення рядків; у кожному рядку видно рівень, функцію і номер рядка; легко писати у файл; іде в stderr і не ламає doctest.
