Урок 12. ЛР7 у терміналі

← Усі уроки

Навіщо: у ЛР7 готового файлу з тестами нема - викладач вимагає, щоб ти сам розбив задачу на функції, написав заготовки з raise NotImplementedError і щонайменше 5 doctest-ів до кожної, а вже потім код. Тут - як робити це в терміналі по кроках і де в ЛР7 найчастіше ламається.

Коротко

Правила ЛР7 (с. 3-4) - це розробка через тести (test-driven): спершу опис і тести, потім код.

1. Коментар на початку файлу: список функцій і що кожна робить
2. Заготовка кожної функції: сигнатура з типами + докстрінг + raise NotImplementedError
3. Щонайменше 5 doctest у кожній: типові і граничні випадки (порожній вхід, мінімум, вироджене)
4. python3 -m doctest файл.py  → усі тести падають з NotImplementedError  (це нормально!)
5. Пишеш тіло однієї функції → її тести зеленіють → наступна

NotImplementedError - вбудований виняток «ще не написано». raise - інструкція «кинути виняток». Заготовка з ним одразу запускається, але кожен виклик чесно каже, що функції ще нема.

Умова коротко

Файл: Лабораторна робота 7 (Пайтон).pdf, 8 с. Теорія - с. 1-3: решето і зрізи del lst[s-1::s] (с. 1), вектори, скалярний, векторний і мішаний добутки (с. 1-2), прямокутний трикутник, паралелограм і прямокутник (с. 2), itertools.combinations (с. 3), вирівнювання f-рядками (с. 3), сідлові точки і добуток матриць (с. 3). Правила для кожного завдання - с. 3-4 (з прикладом заготовки digit_sum).

  • Завдання 1 (с. 4-5). Щасливі числа. Решето: з непарних чисел викреслюється кожне 3-тє, потім кожне 7-ме і т.д. Ввести N, повернути всі щасливі числа, менші за N. Вивід: по 5 у рядку, між рядками порожній рядок, вирівнювання праворуч, ширина стовпчика = кількість цифр N, між стовпчиками два пробіли. Приклад для N = 130 - с. 5.
  • Завдання 2 (с. 5-7). Точки в просторі. Найдальша пара і відстань; кількість вироджених трійок (на одній прямій); прямокутні трикутники з вершиною прямого кута; плоскі прямокутники (площа, периметр, найбільший). Перебір - лише itertools.combinations. Три режими: а) точки вводяться рядками до порожнього рядка; б) точки за формулами (k, -k², k³) і (-p³, p², -p), відсортовані за відстанню до початку координат; в) дослідження для N = 1 ... 4 з таблицею, прогнозом і графіками. Приклади - с. 6-7.
  • Завдання 3 (с. 7-8). Матриці. Ввести дві матриці, вивести добуток (або повідомлення, що не можна); індекси сідлових точок і «особливих» елементів - для добутку, а якщо його нема, для A. Індекси з нуля. Приклад - с. 8.

Теорія до ЛР7: списки, зрізи і del - курс Python (тека Курс/ на ПК), урок 08; кортежі, генератори і itertools - там же, урок 09.

Передбач, потім запусти

1. Зріз з кроком вилучає позиції, а не значення. Що надрукує?

letters = list("abcdefghij")
del letters[2::3]
print(letters)
Відповідь 
['a', 'b', 'd', 'e', 'g', 'h', 'j']

[2::3] - позиції 2, 5, 8 (рахуємо з нуля), тобто кожен 3-й елемент, починаючи з третього: c, f, i. Саме так на с. 1 описано del lst[s-1::s] - «кожен s-й з позиції s-1».

2. Вирівнювання праворуч. Що надрукує?

print("|".join(f"{number:>4}" for number in [5, 50, 500]))
Відповідь 
   5|  50| 500

:>4 - ширина 4, притиснути праворуч, зліва пробіли. Ширину можна взяти зі змінної: f"{number:>{width}}" (с. 3).

3. Що надрукує?

import math

print(0.1 + 0.2 == 0.3, math.isclose(0.1 + 0.2, 0.3))
Відповідь 
False True

float зберігає 0,1 і 0,2 з крихітною похибкою, і сума не точно 0,3. У режимі а) завдання 2 точки можуть бути дробовими - тоді «скалярний добуток = 0» перевіряй з допуском (math.isclose(..., 0, abs_tol=1e-9)), а не ==. У режимі б) координати цілі, і == 0 точне.

4. Скільки трійок з 6 точок і скільки четвірок зі 100?

import itertools
import math

print(len(list(itertools.combinations(range(6), 3))), math.comb(100, 4))
Відповідь 
20 3921225

C(6, 3) = 20, C(100, 4) = 3 921 225 - майже 4 мільйони (у PDF, с. 3, «близько 3 мільйонів»). Для режиму в) з N = 4 точок 18, четвірок C(18, 4) = 3060 - це швидко.

Назви функцій тут - лише приклад; декомпозицію вигадуєш сам, але кожна функція - одна задача. Функція, що друкує, погано тестується doctest-ом; краще хай повертає рядок, а друкує main.

Як тестувати введення. Функцію, що сама викликає input(), doctest перевірити не може: під час тесту вона чекатиме клавіатуру (pytest без -s падає з reading from stdin while output is captured). Тому ділимо на дві: чиста функція бере вже введений рядок і повертає число або кидає ValueError - її легко покрити 5 doctest-ами; а тонка main() лише робить input() і print - у ній нема чого тестувати. Приклад на іншій задачі (скільки квадратів надрукувати), файл kvadraty.py:

def parse_count(text: str) -> int:
    """Кількість з введеного рядка: ціле число, не менше 1.

    >>> parse_count("5")
    5
    >>> parse_count(" 12 ")
    12
    >>> parse_count("1")
    1
    >>> parse_count("0")
    Traceback (most recent call last):
    ...
    ValueError: потрібно ціле число від 1, а не 0
    >>> parse_count("п'ять")
    Traceback (most recent call last):
    ...
    ValueError: invalid literal for int() with base 10: "п'ять"
    """
    count = int(text)
    if count < 1:
        raise ValueError(f"потрібно ціле число від 1, а не {count}")
    return count


def main() -> None:
    count = parse_count(input("Скільки квадратів? "))
    for number in range(1, count + 1):
        print(number, number * number)


if __name__ == "__main__":
    import doctest

    doctest.testmod()
    main()

Крок 4. Підказки по завданнях (розвʼязок твій; функції - «Курс/ДОВІДНИК-ФУНКЦІЙ.md»: range(), sorted(), enumerate(), zip(), itertools.combinations(), math.sqrt(), f-рядок, str.join).

  • 1, решето. Рекомендації с. 5: список непарних до N, починай з позиції 1 (число 3), крок = число на поточній позиції, вилучай зрізом (Передбач №1), зупинись, коли крок більший за довжину списку. Граничні тести: що має вийти для N = 1 (менших чисел нема), N = 2, N = 4 (1 і 3)? Приклад з PDF для N = 130 перевірено незалежною програмою - він правильний, тож якщо в тебе інакше, шукай у себе.
  • 1, вивід. Ширина = len(str(N)) (с. 3), «два пробіли між стовпчиками» - це роздільник у join, порожній рядок між рядками чисел - теж роздільник, тільки між рядками.
  • 2, вектори. Кортеж не віднімається ((1, 2, 3) - (1, 1, 1) дає TypeError), тож напиши маленькі функції: різниця точок, скалярний добуток, векторний добуток - формули с. 1-2. Далі все складається з них: на одній прямій - векторний добуток нульовий; прямий кут у вершині V - скалярний добуток нуль; чотири точки в одній площині - мішаний добуток нуль; прямокутник - теорія с. 2 (діагоналі навпіл і рівні). Порівнюй квадрати відстаней - без кореня.
  • 2, приклади (с. 6-7) перевірено: режим б) для n1 = m1 = -1, n2 = m2 = 1 дає 8 вироджених трійок, 4 прямокутні трикутники, 1 прямокутник (S = 5.657, P = 9.657); таблиця для N = 1 ... 4 (точок 6, 10, 14, 18; трикутників 4, 4, 8, 8; прямокутників 1, 1, 1, 1) і приклад режиму а) - теж правильні. Порядок точок з однаковою відстанню в прикладі - як у списку до сортування: sorted у Python стійке. Стійке сортування - таке, що елементи з однаковим ключем (тут - однаковою відстанню) лишаються в тому порядку, в якому були до сортування.
  • 2, введення до порожнього рядка. Цикл while True: з line = input() і виходом, коли line порожній. Точка: x, y, z = map(float, line.split()) - якщо чисел не три, буде ValueError (нижче).
  • 3, матриці. Рядок матриці: [float(value) for value in input().split()], перевір довжину. Множити можна, коли стовпців A стільки, скільки рядків B (с. 3). Для «зліва всі менші, справа всі більші» зручні зрізи row[:j], row[j + 1:] і функція all(): для порожнього зрізу all() дає True - тому крайні елементи теж можуть бути особливими, як (1, 0) і (1, 2) у прикладі с. 8. Приклад с. 8 перевірено: A·B = [[19, 14], [43, 34]], сідлова точка [(1, 1)], особливих нема; для матриці [[1, 2, 3], [4, 5, 6]] особливі (1, 0), (1, 1), (1, 2), сідлова (1, 0).

Як роблять профі

  • TDD (test-driven development) - «червоний → зелений → рефакторинг»: тест падає, мінімальний код, тест проходить, потім чистиш код. Заготовка з NotImplementedError - перший, «червоний» крок.
  • Граничні випадки - у тести першими: порожній вхід, одна точка, однакові точки, нуль. Більшість помилок живе там.
  • Перевірка властивостей (property-based testing, бібліотека Hypothesis): замість 5 прикладів - сотні випадкових, і перевіряється правило, напр. «S прямокутника = добуток сусідніх сторін».
  • Обчислення з матрицями і векторами в науці роблять у NumPy (numpy.cross, numpy.dot, A @ B), але свої функції в ЛР7 - щоб розуміти формули.

Документація: itertools.combinations - https://docs.python.org/3/library/itertools.html#itertools.combinations ; NotImplementedError - https://docs.python.org/3/library/exceptions.html#NotImplementedError

Самоперевірка

  1. Навіщо писати заготовку з raise NotImplementedError і тести до того, як пишеш код?
  2. Що робить del lst[2::3] - вилучає числа 2, 5, 8 чи елементи на позиціях 2, 5, 8?
  3. Як перевірити, що три точки простору лежать на одній прямій, без кутів і коренів?
  4. Чому в режимі а) завдання 2 не можна перевіряти прямий кут через == 0, а в режимі б) можна?
  5. Чому крайній елемент рядка може бути «особливим», хоча зліва (чи справа) від нього нічого нема?
Відповіді
  1. Тести фіксують, що функція має робити, ще до коду; заготовка вже запускається, і видно, що саме не готове. Викладач прямо вимагає так (с. 3-4).
  2. Елементи на позиціях 2, 5, 8 (з нуля) - зрізи працюють за позиціями, а не за значеннями.
  3. Векторний добуток векторів AB і AC має бути нульовим вектором (с. 2) - лише множення і віднімання.
  4. У режимі а) координати можуть бути дробовими, і float дає крихітну похибку; у режимі б) координати цілі, обчислення точні.
  5. Умова «усі елементи зліва менші» для порожнього набору виконується (у Python all() порожнього - True); приклад с. 8 саме так і рахує (1, 0) і (1, 2).
