Урок 15. Права, sudo, користувачі і групи

← Усі уроки

Навіщо: розуміти «Permission denied», запускати свої скрипти, правильно користуватись sudo і не зламати домашню теку власністю root. Плюс - як дати собі доступ до Arduino чи осцилографа через USB (група dialout).

Коротко

Хто ти: whoami - твій логін, id - номер користувача (uid) і групи. Група sudo = тобі можна адмініструвати.

Права файлу видно в ls -l (або коротше - stat -c '%A %a %n' файл):

-rwxrwxr-x  1 evgen evgen  31 ... pryvit.sh
│└┬┘└┬┘└┬┘     │     │
│ │  │  │      │     └ група файлу
│ │  │  │      └────── власник
│ │  │  └ інші (others):  r-x  читати і запускати
│ │  └─── група (group):  rwx  читати, змінювати, запускати
│ └────── власник (user): rwx  читати, змінювати, запускати
└──────── тип: - файл, d тека, l посилання (урок 14)
Буква Для файлу Для теки
r (read) читати вміст бачити список файлів
w (write) змінювати створювати і видаляти файли в ній
x (execute) запускати як програму заходити в неї (cd)

Числа: r = 4, w = 2, x = 1, для кожної трійки додаєш:

rwx = 4+2+1 = 7      rw- = 4+2 = 6      r-x = 4+1 = 5      r-- = 4      --- = 0

755 = rwxr-xr-x   скрипт або тека: усі читають і запускають, змінюєш лише ти
644 = rw-r--r--   звичайний файл: ти змінюєш, інші читають
600 = rw-------   лише ти (ключі ssh, паролі)
700 = rwx------   тека лише для тебе
Команда Що робить
chmod +x run.sh дозволити запуск
chmod 644 lab.py права числом
chmod o-r zvit.txt забрати в інших (o) читання (r); u - власник, g - група
sudo chown evgen:evgen файл змінити власника і групу (лише через sudo)
umask які права «забирати» в нових файлів

umask у Mint = 0002. Тому нові файли виходять rw-rw-r-- (664), нові теки rwxrwxr-x (775): група теж може писати. Це не страшно - у кожного користувача Mint своя особиста група з тим самим імʼям (evgen), і в ній лише ти. А сама домашня тека має права rwxr-x--- (750) - інші користувачі ноутбука в неї не зайдуть.

sudo - «виконати від імені адміністратора (root)». - Питає твій пароль (той, з яким входиш у Mint), не окремий пароль root. У Mint при наборі друкуються зірочки * (так налаштовано в Mint, файл /etc/sudoers.d/0pwfeedback), а passwd і текстовий вхід не показують нічого - це нормально. - Після правильного пароля 15 хвилин не питає знову. sudo -k - «забути» пароль одразу (наприклад, перед тим як відійти від ноутбука). - sudo -l - що тобі дозволено. Члени групи sudo можуть усе: у /etc/sudoers рядок %sudo ALL=(ALL:ALL) ALL. - root - окремий всемогутній користувач. Входити ним у Mint не треба: адмін-дії роблять через sudo по одній команді, і кожна записується в журнал. - Віконні адмін-програми Mint («Джерела програмного забезпечення», «Користувачі та групи», «Керування системою») самі питають пароль у вікні через pkexec. Їх запускають з меню, не через sudo.

Користувачі і групи - де записані:

Файл Що там Хто читає
/etc/passwd користувачі: логін, uid, домашня тека, оболонка усі
/etc/group групи і хто в них усі
/etc/shadow хеші паролів лише root (і група shadow)
Команда Що робить
id, groups мій uid і групи
sudo adduser gost новий користувач gost (спитає пароль і дані)
sudo usermod -aG dialout "$USER" додати себе в групу dialout (-a обовʼязково), потім вийти і зайти
passwd змінити свій пароль

Те саме мишкою: меню → «Користувачі та групи» (Users and Groups) - спитає пароль, далі кнопка «Додати», вкладка «Групи», «Тип обліківки»: «Адміністратор» або «Стандарт».

Особливі права - щоб не лякатись літер t і s. Справжній вивід з Mint 22.3:

ls -ld /tmp
ls -l /usr/bin/passwd

drwxrwxrwt 6 root root 4096 Nov 18 10:49 /tmp
-rwsr-xr-x 1 root root 64152 May 30  2024 /usr/bin/passwd
  • t у кінці (sticky bit) на /tmp: писати можуть усі, але видалити файл може лише його власник.
  • s на місці x власника (SUID): програма працює з правами власника файлу (root). Так passwd може записати твій новий пароль у /etc/shadow, куди тобі самому не можна. Самому ставити SUID не треба ніколи.

Передбач, потім запусти

Усе в практичній теці з «Руками» (крок 2). Вивід нижче - з тестової Mint англійською; якщо Mint у тебе українською, Permission denied буде Відмовлено у доступі.

  1. Які права будуть після цього?
touch zvit.txt
chmod 640 zvit.txt
stat -c '%A' zvit.txt
Відповідь 
-rw-r-----

6 = rw- (ти), 4 = r-- (група), 0 = --- (інші).

  1. Файл pryvit.sh щойно створено (без chmod +x). Що вийде з кожної команди?
./pryvit.sh
bash pryvit.sh
Відповідь 
bash: ./pryvit.sh: Permission denied
Привіт з скрипта

./pryvit.sh - «запусти цей файл як програму», а права x нема. bash pryvit.sh - запускається bash, а він просто читає файл, для цього досить r.

  1. Чи прочитаєш ти файл паролів?
cat /etc/shadow
Відповідь 
cat: /etc/shadow: Permission denied

Права -rw-r-----, власник root, група shadow. Ти ні те, ні інше. І це правильно: там хеші паролів усіх користувачів.

  1. Файл створено через sudo. Чи допишеш ти в нього рядок без sudo?
sudo touch korin.txt
echo "рядок" >> korin.txt
Відповідь 
bash: korin.txt: Permission denied

sudo touch створив файл від імені root: власник root, права rw-r--r--, тобі лише читати. Ось так sudo «псує» файли у твоїй теці. Лікування - крок 5.

Руками

Крок 1. Хто я.

whoami
id
groups
umask

Справжній вивід з тестової Mint 22.3. На ноутбуці uid буде, найімовірніше, 1000, а груп більше: інсталятор Mint (пакет ubiquity 24.04.3+mint19 з ISO, шаблон passwd/user-default-groups) додає першого користувача ще в adm cdrom dip lpadmin plugdev sambashare debian-tor libvirtd users - у ті з них, що є в системі (останніх двох на свіжій Mint нема). Група adm дає читати системні журнали без sudo (урок 20). На ноутбуці не перевірено - глянь свій groups.

evgen
uid=1001(evgen) gid=1001(evgen) groups=1001(evgen),27(sudo)
evgen sudo
0002

Головне - є група sudo. Без неї sudo не працюватиме.

Крок 2. Свій скрипт.

mkdir -p ~/univer/praktyka/u15
cd ~/univer/praktyka/u15
printf 'echo "Привіт з скрипта"\n' > pryvit.sh
stat -c '%A %a %n' pryvit.sh
chmod +x pryvit.sh
stat -c '%A %a %n' pryvit.sh
./pryvit.sh

-rw-rw-r-- 664 pryvit.sh
-rwxrwxr-x 775 pryvit.sh
Привіт з скрипта

+x додав x усім трьом. Спробуй числами і подивись stat після кожної:

touch zvit.txt
chmod 755 pryvit.sh
chmod 600 zvit.txt
chmod 644 zvit.txt
chmod o-r zvit.txt
stat -c '%A %a %n' pryvit.sh zvit.txt

-rwxr-xr-x 755 pryvit.sh
-rw-r----- 640 zvit.txt

Крок 3. Право x у теки.

mkdir sekret
chmod 600 sekret
cd sekret
chmod 700 sekret

cd скаже bash: cd: sekret: Permission denied: без x у теку не зайти, навіть власнику. chmod 700 повертає вхід.

Крок 4. sudo.

sudo whoami
sudo -k

Спершу спитає [sudo] password for evgen: - набери свій пароль (буде видно зірочки) і Enter. Відповідь - root. Ще раз sudo whoami протягом 15 хвилин - пароль не питає. Після sudo -k - питає знову. Подивись, що тобі можна:

sudo -l

Серед рядків буде (ALL : ALL) ALL - усе, бо ти в групі sudo. Ще два рядки (root) NOPASSWD: ... - це Mint дозволяє Диспетчеру оновлень без пароля оновлювати кеш (mint-refresh-cache) і перевіряти блокування dpkg.

Крок 5. Як sudo псує файли в домашній теці і як це лікувати.

sudo touch korin.txt
stat -c '%A %U %G %n' korin.txt
sudo chown "$USER:$USER" korin.txt
stat -c '%A %U %G %n' korin.txt
echo "рядок" >> korin.txt

-rw-r--r-- root root korin.txt
-rw-r--r-- evgen evgen korin.txt

$USER - це твій логін, bash підставить його сам. Після chown файл знову твій і дописується без sudo. Цілу теку повертають з -R (рекурсивно): sudo chown -R "$USER:$USER" ~/univer.

Крок 6. Файли користувачів.

stat -c '%A %U %G %n' /etc/passwd /etc/group /etc/shadow
grep "^$USER:" /etc/passwd | cut -d: -f1,6,7

-rw-r--r-- root root /etc/passwd
-rw-r--r-- root root /etc/group
-rw-r----- root shadow /etc/shadow
evgen:/home/evgen:/bin/bash

У /etc/passwd поля розділені :, ми вирізали (cut) 1-ше (логін), 6-те (домашня тека) і 7-ме (оболонка). Пароля там нема - лише x, а сам хеш - у /etc/shadow.

Крок 7. Група для пристроїв (Arduino, осцилограф, будь-що через USB-COM). Порт /dev/ttyUSB0 чи /dev/ttyACM0 належить групі dialout (так каже правило udev у Mint: KERNEL=="tty[A-Z]*[0-9]|...", GROUP="dialout"). Без неї програма скаже Permission denied на порт. Додай себе:

getent group dialout
sudo usermod -aG dialout "$USER"

Тепер вийди з сеансу і зайди знову (або перезавантаж) - групи оновлюються лише при вході. Перевір: groups - у списку зʼявився dialout.

Крок 8. Як Mint запускає свої адмін-вікна.

grep Exec /usr/share/applications/mintsources.desktop

Exec=pkexec mintsources

Пункт меню «Джерела програмного забезпечення» запускає програму через pkexec - вікно саме попросить пароль. Так само «Користувачі та групи». Відкрий їх з меню і подивись (нічого не міняй).

Крок 9. Змінити системний файл правильно (на майбутнє, коли урок скаже «допиши в /etc/...»):

sudo -e /etc/hosts

sudo -e відкриває копію файлу в nano від твого імені, а після збереження сам кладе її на місце від root. Вийдеш без змін (Ctrl+X) - побачиш sudo: /etc/hosts unchanged. Так не треба запускати редактор від root.

Крок 10. Прибрати за собою.

cd ~
gio trash ~/univer/praktyka/u15

Типові помилки

Якщо Mint українською - у дужках той самий текст українською (з перекладу language-pack-uk-base). Англійський текст для пошуку в інтернеті: LC_ALL=C команда.

  • bash: ./pryvit.sh: Permission denied (bash: ./pryvit.sh: Відмовлено у доступі) - нема права x: chmod +x pryvit.sh (або запускай bash pryvit.sh).
  • Permission denied на своєму ж файлі в ~ - його колись створили через sudo (наприклад, новий файл через sudo nano чи sudo touch), і він тепер root-а (stat -c '%U' файл покаже root). Повернути: sudo chown "$USER:$USER" файл, цілу теку - з -R.
  • Запускати віконні програми через sudo (sudo nemo, sudo xed) - вони пишуть свої налаштування в твою теку вже від root, і потім ці програми чи навіть вхід у систему ламаються. Практики радять тоді sudo chown -R "$USER:$USER" "$HOME". Для системних файлів - sudo -e (крок 9), для тек - у Nemo «Відкрити як адміністратор», лише коли справді треба.
  • sudo usermod -G dialout без -a - замінює всі твої додаткові групи однією dialout, і ти випадаєш з групи sudo (втрачаєш адмін-права). Завжди -aG (append - додати).
  • Додав себе в групу, а groups її не показує - не перезайшов у сеанс.
  • Sorry, try again. (Вибачте, повторіть спробу.) - неправильний пароль sudo. Після трьох спроб: sudo: 3 incorrect password attempts (sudo: 3 невдалих спроби введення пароля). Перевір розкладку (Super+Space, урок 13) і Caps Lock.
  • evgen is not in the sudoers file. (evgen немає у файлі sudoers.) - твого користувача нема в групі sudo (так буває з користувачем, створеним як «Стандарт»). Додати може лише адміністратор: «Користувачі та групи» → «Тип обліківки» → «Адміністратор».
  • chmod 777, «щоб запрацювало» - дозволяє всім усе. Так роблять у поганих порадах з YouTube. Скрипту досить chmod +x, файлу - 644, теці - 755. Рекурсивне 777 по системних теках ламає систему (sudo і ssh відмовляються працювати з такими правами).
  • Забув пароль - його не «показати»: можна лише задати новий через режим відновлення (recovery mode) в меню GRUB, детально в уроці 26.

Як роблять профі

  • Найменші потрібні права (principle of least privilege): sudo - лише на одну команду, яка справді змінює систему; свої файли - без sudo взагалі.
  • Перш ніж sudo - прочитай команду. Пости r/linux4noobs (2026): найбільше біди - від порад «скопіюй і встав» з chmod 777 і роботою від root.
  • Редагування системних файлів - через sudo -e (або sudoedit), а не sudo nano чи sudo xed.
  • Доступ до пристроїв - через групи (dialout, plugdev), а не запуск програми від root.
  • Ключі й секрети - chmod 600: ssh сам відмовиться працювати з ключем, який можуть читати інші (урок 21).

Самоперевірка

  1. Що означає -rw-r----- і яким числом це записати?
  2. Чому ./run.sh пише Permission denied, а bash run.sh працює?
  3. Чий пароль питає sudo і скільки часу його памʼятає? Як змусити забути?
  4. Ти створив новий файл через sudo nano ~/univer/labs/lr1/lab2.py, і тепер без sudo він не зберігається. Чому і як виправити?
  5. Як додати себе в групу dialout і що зробити після цього?
Відповіді
  1. Файл: власник читає і пише, група лише читає, інші нічого. 640.
  2. У файлу нема права x. bash run.sh запускає bash, а він тільки читає файл - потрібне лише r.
  3. Твій власний пароль (з яким входиш у Mint). Памʼятає 15 хвилин. sudo -k - забути одразу.
  4. Новий файл, створений від root, належить root (а вже наявний файл sudo nano зберігає зі старим власником evgen - тому біда саме з новими). sudo chown "$USER:$USER" ~/univer/labs/lr1/lab2.py - і далі редагувати без sudo.
  5. sudo usermod -aG dialout "$USER" (з -a!), потім вийти з сеансу і зайти знову, перевірити groups.
