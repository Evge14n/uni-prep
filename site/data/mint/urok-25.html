Урок 25. Безпека - ufw, оновлення, що не запускати з sudo

← Усі уроки

Навіщо: у Linux майже все погане стається не «саме», а тому що ти щось запустив від root. Тут - короткий список звичок, які закривають 95 % ризиків, і брандмауер, який у Mint вимкнений з коробки.

Коротко

Головне правило: sudo - це «зроби від імені адміністратора все, що написано далі». Пароль, який питає sudo, - це твоя згода. (У Mint при наборі цього пароля видно зірочки - так налаштовано файлом /etc/sudoers.d/0pwfeedback з пакета mintsystem.)

Що НЕ запускати з sudo:

Не роби Чому Як правильно
«sudo pip install ...» ламає системний Python, від якого залежить сама Mint venv або pipx (урок 02, 03)
графічні програми з sudo (xed, Nemo, браузер) лишають у твоїй домашній теці файли, що належать root, потім «Permission denied» звичайний запуск; системний файл - sudoedit /etc/файл (відкриє твій редактор, а збереже від root)
чужий скрипт з інтернету, який «треба запустити з sudo» він може зробити з системою що завгодно спершу прочитати (less), перевірити (shellcheck), зрозуміти кожен рядок
завантажити скрипт curl-ом і одразу передати його «sudo bash» з невідомого сайту ти навіть не бачиш, що виконується завантажити у файл, прочитати, тоді вирішувати
права 777 «щоб працювало» будь-хто і будь-яка програма може змінити файл розібратись, кому треба доступ (урок 15)

Незнайому команду перевір на explainshell.com: сайт розбирає рядок по шматках. Пост r/linux4noobs «Most YouTube docker tutorials are actively trying to ruin your system» (18.08.2026, 283 бали) - про «поради» з YouTube на кшталт chmod 777 і роботи від root; в іншому пості (29.06.2026) людина виконала пораду ШІ з apt purge і стерла сервер.

Брандмауер ufw (Uncomplicated Firewall) - фільтр вхідних підключень. На Mint 22.3 встановлений, але вимкнений (Status: inactive), Welcome радить його увімкнути. Після sudo ufw enable типові правила: вхідні - заборонено, вихідні - дозволено. Тобто інтернет, оновлення, GitHub працюють як раніше, а до ноутбука ззовні не підключитись. Мишкою - gufw («Налаштування брандмауера» в меню).

Команда Що робить
sudo ufw status verbose стан і типові правила
sudo ufw enable / sudo ufw disable увімкнути (і при старті системи) / вимкнути
sudo ufw allow ssh дозволити вхідний ssh (лише якщо поставив ssh-сервер, урок 21)
sudo ufw status numbered і sudo ufw delete 1 правила з номерами / видалити правило 1

Решта звичок: - Оновлення - «Диспетчер оновлень», урок 02. Вразливості закривають саме оновлення. - Програми - з «Керування програмами» / apt. PPA і неперевірені Flatpak - лише коли розумієш навіщо (урок 16). Ключ PPA доводить лише «звідки» пакет, а не «безпечно». - Пароль входу - довгий. Відійшов від ноутбука - Ctrl+Alt+L (блокування; Super+L у Cinnamon - це налагоджувач Looking Glass, не блокування). - Шифрування диска (LUKS) вибирається лише під час встановлення Mint («Encrypt the new Linux Mint installation»). Потім увімкнути можна тільки перевстановленням. Посібник Mint попереджає про проблеми цієї опції з деякими драйверами NVIDIA. Перевірити, чи диск зашифрований: lsblk -f (шукай crypto_LUKS). - Резервні копії 3-2-1: 3 копії, на 2 різних носіях, 1 - поза домом (хмара, GitHub для коду). Timeshift - не резервна копія лаб (домашню теку не зберігає, урок 01). Для лаб: git + GitHub (урок 24), cron + rsync (урок 23). - Secure Boot не вимикай (урок 17). - Розширення браузера - мінімум і лише з офіційного каталогу. Розширення бачить усі сторінки, які ти відкриваєш. - Фішинг - найчастіша атака і на Linux: лист «підтвердіть пароль» з посиланням. Пароль вводь лише на сайті, який відкрив сам (закладка), дивись на адресу. На GitHub і пошті - двофакторний вхід.

Антивірус. Чесно: віруси для Linux існують (переважно для серверів), але для домашньої Mint головний ризик - не «вірус сам заліз», а ти сам запустив щось погане з sudo. Посібник Easy Linux Tips (оновлено 30.05.2026, для Mint і Ubuntu) прямо радить антивірус не ставити: вірус не встановиться без твого пароля або без того, що ти сам зробиш скрипт виконуваним, а сам антивірус має високі права в системі і тому стає зручною ціллю для атак. Це думка одного досвідченого автора, а не правило Mint. Якщо треба перевірити файл для когось на Windows - у репозиторії є clamav.

Передбач, потім запусти

  1. Свіжа Mint 22.3. Що покаже команда?
sudo ufw status
Відповідь 
Status: inactive

Брандмауер є, але вимкнений (у /etc/ufw/ufw.conf стоїть ENABLED=no).

  1. Ти ввімкнув ufw. Чи відкриються сайти і чи буде працювати git push?
Відповідь

Так. Типове правило: deny (incoming), allow (outgoing) - забороняються лише вхідні підключення (хтось ззовні стукає до тебе), а все, що починаєш ти сам (браузер, apt, ssh до GitHub), - дозволено.

  1. Поза venv: pip install requests. Що буде? І чи допоможе sudo?
Відповідь

Справжній початок виводу:

error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install
    python3-xyz, where xyz is the package you are trying to
    install.

Mint захищає системний Python (PEP 668). sudo тут не вихід: так ти ставиш пакети просто в систему і можеш зламати програми Mint. Правильно - venv (урок 03) або pipx.

  1. journalctl _COMM=sudo без sudo. Чи побачиш записи про sudo? Залежить від груп - спершу groups.
Відповідь

У тестовій Mint користувач лише в групі sudo, і там спершу така підказка (справжній вивід):

Hint: You are currently not seeing messages from other users and the system.
      Users in groups 'adm', 'systemd-journal' can see all messages.
      Pass -q to turn off this notice.

Журнал sudo пише система, тому без групи adm видно не все. На ноутбуці інакше: першого користувача інсталятор Mint додає в adm (урок 15, крок 1), тож підказки не буде, і записи про sudo видно і без sudo (на ноутбуці не перевірено). Немає adm у groups - пиши sudo journalctl ... (крок 2).

Руками

Крок 1. Увімкнути брандмауер.

sudo ufw status verbose
sudo ufw enable
sudo ufw status verbose

Справжній вивід двох останніх команд у тестовій Mint 22.3:

Firewall is active and enabled on system startup
Status: active
Logging: on (low)
Default: deny (incoming), allow (outgoing), disabled (routed)
New profiles: skip

Перевір, що інтернет працює: curl -I https://linuxmint.com (урок 21). Те саме мишкою: меню → «Налаштування брандмауера» (gufw) → перемикач «Стан».

Крок 2. Хто і що робив з sudo.

sudo journalctl _COMM=sudo -n 5 --no-pager
last -n 5

Кожен виклик sudo - у журналі: хто, з якої теки і яку команду. Рядок з тестової Mint (імʼя компʼютера замінено на evgen-laptop; у тебе буде імʼя твого ноутбука, дата і номер процесу свої):

Nov 18 10:30:34 evgen-laptop sudo[282]:    evgen : TTY=pts/0 ; PWD=/home/evgen ; USER=root ; COMMAND=/usr/sbin/ufw status verbose

Після дати - імʼя компʼютера, далі sudo[номер процесу], хто запускав і що. last показує входи в систему і перезавантаження. У тестовій машині там лише рядки reboot system boot ...; на ноутбуці будуть і твої входи. Побачив команду, якої не запускав, - привід розібратись.

Крок 3. Відкриті порти. Як в уроці 21:

sudo ss -tulpn

Усе, що слухає на 127.0.0.1 / 127.0.0.53 / [::1], доступне лише з самого ноутбука. Порти на 0.0.0.0 або [::] доступні з мережі - з увімкненим ufw вони все одно закриті, поки не зробиш ufw allow.

Крок 4. Чи не лишилось у домашній теці файлів root (наслідок запуску графічних програм з sudo):

find ~ -not -user "$USER" 2>/dev/null | head

Порожньо - добре. Якщо щось є - поверни собі: sudo chown -R "$USER:$USER" ~/назва_теки (саме ту теку, що знайшлась).

Крок 5. Чи зашифрований диск.

lsblk -f

У стовпці FSTYPE шукай crypto_LUKS. Нема - диск не зашифрований; для ноутбука, який носиш в університет, варто подумати про це при наступному перевстановленні (з резервною копією!).

Крок 6. Перевірка чужої команди - тренування. Скопіюй в explainshell.com рядок find ~ -not -user "$USER" 2>/dev/null | head і подивись, як сайт пояснює кожен шматок. Так роби з будь-якою «порадою», перш ніж вставити її в термінал.

Крок 7. Звичка. Ctrl+Alt+L щоразу, коли встаєш з-за ноутбука в аудиторії.

Типові помилки

  • «Увімкнув ufw - зламався інтернет». Не має: вихідні дозволені. Якщо справді щось перестало працювати - sudo ufw status verbose і перевір, чи ти не додавав deny вручну. Вимкнути для перевірки - sudo ufw disable.
  • ERROR: You need to be root to run this script (українською ERROR: Ви маєте бути супер-користувачем, щоб запустити цей скрипт - справжній запуск з перекладом language-pack-uk-base; англійською - LC_ALL=C ufw status)
  • ufw без sudo.
  • Після запуску GUI-програми з sudo - не відкриваються налаштування, «Permission denied» у домашній теці. Крок 4.
  • --break-system-packages «щоб pip запрацював» - ти сам вимикаєш захист системного Python. venv.
  • «Порада» з форуму або від ШІ з sudo і rm / chmod / dd - не вставляй, поки не розумієш кожне слово (explainshell, урок 22). Особливо, якщо там будь-що з / або ~ після rm.
  • Один пароль скрізь - якщо витече з одного сайту, зламають усі. Менеджер паролів (напр. вбудований у Firefox) і різні паролі.
  • Резервна копія на тому самому диску (як тренувальна ~/backup з уроків 21 і 23) - помре разом з диском. 3-2-1: флешка або зовнішній диск і GitHub.

Як роблять профі

  • Найменші права. Працюють звичайним користувачем, sudo - лише на конкретну команду, яку розуміють.
  • Брандмауер увімкнений завжди, назовні відкрито лише те, що свідомо дозволено (ufw allow ...).
  • Оновлення - регулярно, бо більшість атак використовують уже виправлені вразливості. Easy Linux Tips: «Vulnerabilities: No Big Problem if Fixed Quickly».
  • Секрети - не в коді і не в git (урок 24), двофакторний вхід на GitHub.
  • Перед будь-якою зміною - знімок Timeshift (урок 01), для даних - окремі копії.

Самоперевірка

  1. Що змінюється для тебе і для інших компʼютерів після sudo ufw enable?
  2. Назви три речі, які не варто запускати з sudo, і чому.
  3. Чому Timeshift - не резервна копія лаб, і що тоді резервна копія?
  4. Як дізнатися, які команди запускали з sudo на цьому ноутбуці?
  5. Тобі в чаті скинули рядок з sudo і просять «просто встав». Що робиш?
Відповіді
  1. Ти - нічого не помітиш: вихідні підключення дозволені. Інші компʼютери більше не зможуть підключитися до твого ноутбука (вхідні заборонено), поки ти явно щось не дозволиш.
  2. pip (ламає системний Python - є venv), графічні програми (лишають файли root у домашній теці), чужі скрипти й команди з інтернету (виконають що завгодно від root). Ще - права 777.
  3. Timeshift зберігає систему, а домашню теку типово не зберігає. Резервна копія лаб - git + приватний GitHub, копія на інший диск або флешку (rsync, cron), правило 3-2-1.
  4. sudo journalctl _COMM=sudo (рядки COMMAND=...).
  5. Не вставляю. Розбираю кожне слово (explainshell.com), питаю, навіщо це; якщо там скрипт - спершу читаю його.
