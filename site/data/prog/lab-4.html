Загальна математика turtle (одна сторінка, потрібна майже в кожному завданні)

1) Поворот - це кут ЗОВНІШНІЙ, а не внутрішній. Черепашка йде вздовж сторони. На вершині вона повертає на стільки, на скільки треба відхилитися від прямого руху. Якщо внутрішній кут фігури β, поворот:

поворот = 180° - β

Квадрат: β = 90° → поворот 90°. Правильний трикутник: β = 60° → поворот 120° (не 60!). Ромб 60°/120°: на гострій вершині поворот 120°, на тупій - 60°.

2) Обійти будь-яку замкнену опуклу фігуру = повернутися сумарно на 360°. Тому в правильному n-кутнику кожен поворот 360°/n (п'ятикутник: 72°).

3) Розета з n однакових фігур: намалював фігуру, повернувся на 360°/n, і так n разів.

36 кіл   → 360 / 36 = 10°
24 ромби → 360 / 24 = 15°
72 квадрати → 360 / 72 = 5°

Щоб це працювало, після кожної фігури черепашка має стояти ТАМ САМО і дивитися ТУДИ САМО, де почала. Коло (circle) і замкнений багатокутник саме так і закінчуються.

4) Циклічні кольори: colors[i % len(colors)]. Остача від ділення ходить по колу:

i            : 0 1 2 3 4 5 6 7 8 ...
i % 4        : 0 1 2 3 0 1 2 3 0 ...

5) Групи по 12, 20, 24: цілочисельне ділення i // 20 дає номер групи:

i       : 0 ... 19 | 20 ... 39 | 40 ... 59
i // 20 :    0     |     1     |     2

Звідси 2 + i // 20 = 2, 3, 4 без жодного if. Але й через if i < 20: ... elif ... - теж правильно.

6) Градуси → радіани (для math.sin, math.cos): math.radians(кут).

радіани = градуси · π / 180       90° → π/2 ≈ 1,5708

math.cos(90) - це косинус 90 РАДІАН (≈ -0,448), а не 0. Найчастіша помилка в 1.8.

7) Полярні координати → звичайні:

x = r · cos θ
y = r · sin θ

8) Заливка. begin_fill() ... малюєш ЗАМКНЕНИЙ контур ... end_fill(). Колір заливки - fillcolor("gold"), або одразу обидва: color("blue", "gold") (лінія, заливка).

9) Швидко і без стрілки: speed(0) - НА ПОЧАТКУ (до циклу), hideturtle() - в кінці (або теж на початку, тоді стрілку не видно взагалі). speed(0) після циклу нічого не дає.

10) Перейти без лінії: penup() → goto(x, y) → pendown(). Саме в такому порядку. Забув pendown() - далі нічого не малюється. Забув penup() - через екран тягнеться зайва лінія.

1.1 Правильна зірка draw_star(n, length, k=2)

Що має вийти

Рисунок 1 (перший зліва вгорі): семикутна зірка {7/2} на БІЛОМУ тлі, контур синій, промені залиті золотим. Центр (семикутник посередині) лишився БІЛИМ - це нормально, так і на рисунку (пояснення нижче). Вікно 600 × 600.

Математика простими словами

Уяви 7 точок на колі, як цифри на годиннику. Звичайний семикутник: з'єднуєш кожну з НАСТУПНОЮ (крок k = 1). Зірка: з'єднуєш через одну (крок k = 2): 0 → 2 → 4 → 6 → 1 → 3 → 5 → 0.

Кут повороту з умови:

          360° · k
angle = ──────────
             n

n = 7, k = 2:   angle = 360 · 2 / 7 = 720 / 7 ≈ 102,857°
n = 5, k = 2:   angle = 720 / 5 = 144°   (класична п'ятикутна зірка)
n = 7, k = 1:   angle = 360 / 7 ≈ 51,43°  (звичайний семикутник)

Чому так: за весь обхід зірки {n/k} черепашка обертається не на 360°, а на k · 360° (для k = 2 - два повні оберти). Ділиш на n поворотів - отримуєш кут.

НСД (gcd). Якщо gcd(n, k) = 1, усі n вершин в одному контурі - одна зірка одним розчерком. Якщо gcd(n, k) > 1, контур замикається раніше. Приклад n = 6, k = 2: gcd = 2, кут 120°, черепашка намалює ТРИКУТНИК і далі піде по ньому вдруге (а не «зірку Давида» з двох трикутників). Тому умова і просить вивести попередження.

from math import gcd
gcd(7, 2) = 1   → все добре
gcd(6, 2) = 2   → попередження
gcd(8, 2) = 2   → попередження (вийде квадрат)
gcd(8, 3) = 1   → одна зірка {8/3}

Чому центр білий. Контур зірки сам себе перетинає. Tk (на ньому працює turtle) заливає за правилом «парне/непарне»: точка всередині, якщо промінь з неї перетинає контур непарну кількість разів. Центр обведений двічі → парно → не заливається. На рисунку викладача так само.

План

  1. import turtle, from math import gcd.
  2. Функція draw_star(n, length, k=2): порахувати кут, перевірити gcd і, якщо треба, print(...) попередження.
  3. Колір лінії і заливки, begin_fill().
  4. Цикл з n ітерацій: вперед на length, поворот на кут.
  5. end_fill().
  6. Поза функцією: вікно 600 × 600, виклик draw_star(7, 150, 2), turtle.done().

Підказки

Рівень 1. Вікно потрібного розміру задає turtle.setup(ширина, висота). Поворот у зірці - right чи left, не важливо (буде дзеркальна зірка). Важливо, щоб кут був з формули.

Рівень 2.

turn_angle = 360 * k / n

і перевірка if gcd(n, k) != 1: → print("Увага: ...").

Рівень 3.

def draw_star(n: int, length: float, k: int = 2) -> None:
    turn_angle = ...
    if gcd(n, k) != 1:
        print(...)
    turtle.color("blue", "gold")
    turtle.begin_fill()
    for _ in range(...):
        turtle.forward(...)
        turtle.right(...)
    turtle.end_fill()

Для doctest можна винести star_turn_angle(n, k) -> float (рядок 360 * k / n) і перевірити: star_turn_angle(5, 2) → 144.0, star_turn_angle(4, 1) → 90.0.

Типові помилки

  • 360 / n * k і 360 * k / n - однаково. А от 360 // n * k - ЦІЛОЧИСЕЛЬНЕ ділення, для n = 7 дасть 51 · 2 = 102 замість 102,857, і зірка НЕ замкнеться (буде щілина).
  • Цикл range(k * n) або range(360) замість range(n) - зайві обходи.
  • begin_fill() після циклу - нічого не заллється.
  • Попередження через return "..." замість print - умова каже вивести в консоль.
  • turtle.setup(600, 600) після малювання - вікно вже відкрилось іншого розміру. Ставити на початку.

1.2 Кольорова розета з 36 кіл

Що має вийти

Рисунок 2: чорне тло, 36 різнокольорових кіл однакового радіуса 80, що проходять через центр і разом утворюють «квітку»-бублик. Кольори повторюються по колу (6 штук).

Математика простими словами

turtle.circle(80) малює коло радіуса 80, яке ДОТИКАЄТЬСЯ поточної точки, а центр кола - на 80 пікселів ЛІВОРУЧ від напрямку черепашки. Після кола черепашка там само і дивиться туди ж. Повернув на 10° - наступне коло зсунуте на 10°. 36 · 10° = 360° - повне коло, рівно 36 кіл.

Кольори: список з 6 назв, колір кола номер i - colors[i % 6], тобто 0,1,2,3,4,5,0,1,... Колір 0 буде в колах 0, 6, 12, 18, 24, 30 (6 разів).

План

  1. turtle.bgcolor("black"), turtle.speed(0).
  2. Список з 6 кольорів (наприклад red, orange, yellow, lime, cyan, magenta - на рисунку схожі).
  3. Цикл на 36: колір лінії colors[i % len(colors)], circle(80), left(10).
  4. hideturtle(), done().

Підказки

Рівень 1. Змінна циклу тут потрібна (для кольору), тому for i in range(36), а не for _.

Рівень 2.

turtle.pencolor(colors[circle_index % len(colors)])

Рівень 3.

for circle_index in range(...):
    turtle.pencolor(...)
    turtle.circle(...)
    turtle.left(...)

Для doctest: функція pick_color(index, colors) повертає colors[index % len(colors)]; pick_color(7, ["a", "b", "c"]) → 'b'.

Типові помилки

  • colors[i % 6] замість colors[i % len(colors)] - працює, але умова прямо просить len(colors).
  • left(360 / 36) - нормально (= 10.0), а left(36) - помилка: кола підуть з кроком 36°, вийде 10 кіл на оберт, повтори одне на одному.
  • bgcolor викликати з turtle. - це функція модуля, не кольору лінії. pencolor("black") замість bgcolor - чорні лінії на білому.
  • Без speed(0) чекатимеш хвилину.

1.3 Квадратна кольорова спіраль (60 відрізків)

Що має вийти

Рисунок 3: чорне тло, квадратна спіраль, що розкручується від центру. Кожна сторона одного кольору: верхні горизонталі золоті, праві вертикалі малинові, нижні салатові, ліві блакитні. Зовнішні витки товщі (лінія 2 → 3 → 4).

Математика простими словами

Довжина відрізка номер i (рахуємо з 0):

length = 10 + 4 · i

i = 0  → 10
i = 1  → 14
i = 59 → 10 + 236 = 246

Поворот праворуч 90° після кожного - тому спіраль іде за годинниковою стрілкою. Оскільки кольорів 4 і кут 90° (4 повороти = повний оберт), кожен напрям завжди має свій колір: відрізок 0 (вправо) золотий, 1 (вниз) малиновий, 2 (вліво) салатовий, 3 (вгору) блакитний, 4 (знов вправо) золотий...

Товщина за номером:

i = 0 ... 19  → pensize(2)
i = 20 ... 39 → pensize(3)
i = 40 ... 59 → pensize(4)

Або if / elif / else, або формулою 2 + i // 20 (див. загальну математику, п. 5).

Довжину можна або рахувати формулою від i, або тримати змінну і додавати 4 після кожного кроку (умова каже саме «після кожного кроку збільшуйте на 4» - другий спосіб ближчий до тексту).

План

  1. Тло, speed(0), список кольорів ["gold", "crimson", "lime", "cyan"] (саме ці 4 назви стоять у теорії ЛР4, стор. 4; салатовий = lime, блакитний = cyan).
  2. segment_length = 10.
  3. Цикл на 60: товщина за номером, колір colors[i % len(colors)], forward(segment_length), right(90), segment_length += 4.
  4. hideturtle(), done().

Підказки

Рівень 1. Що змінюється від кроку до кроку: довжина, колір, товщина. Що не змінюється: кут.

Рівень 2.

turtle.pensize(2 + segment_index // 20)

Рівень 3.

segment_length = 10
for segment_index in range(60):
    turtle.pensize(...)
    turtle.pencolor(...)
    turtle.forward(...)
    turtle.right(...)
    segment_length += ...

Для doctest: segment_pen_size(0) → 2, segment_pen_size(20) → 3, segment_pen_size(59) → 4.

Типові помилки

  • Межі груп: if i < 20 ... elif i < 40 ... else - правильно. if i <= 20 - 21 відрізок у першій групі.
  • left(90) замість right(90) - спіраль у інший бік (дзеркально). Умова каже праворуч.
  • segment_length += 4 ПЕРЕД forward - перший відрізок буде 14, а не 10.
  • Колір за segment_length % 4 замість номера - кольори «поїдуть» (10, 14, 18 ... усі дають остачу 2).

1.4 Оптична квітка з 24 ромбів

Що має вийти

Рисунок 4: чорне тло, 24 ромби зі спільною вершиною в центрі, розкладені по колу. Верхня половина блакитна (cyan), нижня помаранчева (orange). У центрі сходяться ГОСТРІ кути ромбів (60°), тому там густо.

Математика простими словами

Ромб - чотири однакові сторони по 100. Кути 60° і 120° чергуються. Черепашка повертає на ЗОВНІШНІЙ кут (180° - внутрішній):

внутрішній 120° → поворот 60°
внутрішній 60°  → поворот 120°

сума поворотів: 60 + 120 + 60 + 120 = 360°  → ромб замкнувся, черепашка в початку

Порядок: вперед 100, ліворуч 60, вперед 100, ліворуч 120, вперед 100, ліворуч 60, вперед 100, ліворуч 120. Останній поворот 120° відбувається в початковій вершині - отже там внутрішній кут 60°, гострий. Так і на рисунку. (Якщо почати з повороту 120°, у центрі будуть тупі кути - теж «квітка», але рідша, не як на рисунку.)

Розета: 24 ромби, 360 / 24 = 15° між ними. Кольори: ромби 0-11 cyan, 12-23 orange. Перші 12 · 15° = 180° - півкола, тому половина квітки одного кольору.

План

  1. Тло, speed(0).
  2. (Добре для оцінки) функція draw_rhombus(side_length) - малює один ромб, повертається в початок.
  3. Цикл на 24: колір (cyan, якщо номер < 12, інакше orange), ромб, left(15).
  4. hideturtle(), done().

Підказки

Рівень 1. Спершу намалюй ОДИН ромб і переконайся, що черепашка після нього там само і дивиться туди ж (постав turtle.showturtle() і подивись на стрілку). Тоді вже цикл.

Рівень 2. Ромб - це двічі повторена пара «вперед, 60, вперед, 120»:

for _ in range(2):
    turtle.forward(side_length)
    turtle.left(60)
    turtle.forward(side_length)
    turtle.left(120)

Рівень 3.

for rhombus_index in range(24):
    if rhombus_index < ...:
        turtle.pencolor("cyan")
    else:
        turtle.pencolor(...)
    draw_rhombus(100)
    turtle.left(...)

Типові помилки

  • Повороти на 60 і 120 переплутані з внутрішніми кутами: «вперед, ліворуч 120» чотири рази - це не ромб, а трикутник, що обходиться двічі.
  • left(15) всередині циклу ромба (зайвий відступ) - кожна сторона повернута, ромб не замкнеться.
  • Межа кольорів <= 12 - 13 блакитних і 11 помаранчевих.
  • hideturtle() всередині циклу - не помилка, але зайво 24 рази.

1.5 Павутинка: 6 променів і 7 шестикутників

Що має вийти

Рисунок 5: чорне тло, 6 тонких сірих променів з центру (горизонтальний і два похилі, разом «сніжинка»), поверх них 7 вкладених шестикутників з вершинами вгорі й унизу. П'ять внутрішніх білі тонкі, два зовнішні жовті товсті.

Математика простими словами

Промені: 6 штук, між ними 360 / 6 = 60°. Кожен промінь - «вперед 150, назад 150, повернути на 60». Назад - щоб повернутися в центр, не піднімаючи пера (лінія просто пройде двічі по тому самому місцю).

Шестикутник через circle(size, steps=6): черепашка малює «коло» з 6 відрізків, тобто правильний шестикутник, вписаний у коло радіуса size. Центр кола - на size ЛІВОРУЧ від черепашки. Тому якщо поставити черепашку в (0, -size) і направити праворуч (heading 0), центр буде в (0, 0). Саме це умова й каже: «розпочинаючи з точки (0, -size)».

радіуси: 20, 40, 60, 80, 100, 120, 140   (7 штук, крок 20)
номер:    0   1   2   3    4    5    6
          └──── білі, товщина 1 ────┘ └ жовті, 3 ┘

План

  1. Тло, speed(0).
  2. Промені: колір gray, цикл на 6 (вперед, назад, ліворуч 60).
  3. Цикл по радіусах: penup, goto(0, -size), setheading(0), pendown, колір і товщина за номером, circle(size, steps=6).
  4. hideturtle(), done().

Підказки

Рівень 1. Радіуси можна взяти списком [20, 40, ...] або range(20, 141, 20) - 141, бо кінець не входить.

Рівень 2. Перехід до старту кожного шестикутника:

turtle.setheading(0)
turtle.pendown()

Рівень 3.

    size = 20 + 20 * hexagon_index
    if hexagon_index < ...:
        turtle.pencolor("white")
        turtle.pensize(...)
    else:
        ...
    (перехід у (0, -size), як вище)
    turtle.circle(size, steps=6)

Типові помилки

  • Без penup між шестикутниками - зайві вертикальні лінії від одного до іншого.
  • Без setheading(0) - після променів черепашка дивиться не праворуч, шестикутники з'їдуть убік від центру.
  • Промені ПІСЛЯ шестикутників - сірі лінії перекреслять білі й жовті. Порядок: спочатку те, що позаду.
  • range(20, 140, 20) - лише 6 шестикутників (140 не входить).

1.6 «Кристал» з 20 кіл

Що має вийти

Рисунок 6: чорне тло, 20 кіл, що всі проходять через одну точку (центр), розкручуються «черепашкою-мушлею»: маленькі блакитні, середні темно-сині, великі золоті. Товщина 2.

Математика простими словами

Радіус кола номер i:

r = 30 + 5 · i      i = 0 ... 19

i = 7  → 65
i = 8  → 70
i = 15 → 105
i = 16 → 110
i = 19 → 125

Рівень 1. Колір вибирається за РАДІУСОМ, а не за номером. Тому спершу порахуй radius, потім колір.

Рівень 2.

    ...
elif radius < 110:
    ...
else:
    ...

(у elif не треба писати 70 <= radius - якщо дійшли сюди, radius уже ≥ 70).

Рівень 3. Для doctest: crystal_color(70) → 'royal blue', crystal_color(110) → 'gold' - межі найважливіші.

1.7 Кольорова шестикутна спіраль (360 відрізків)

Що має вийти

Математика простими словами

x = 100 → 2
x = 359 → 4,59

Підказки

Рівень 2.

Рівень 3.

    turtle.pencolor(colors[step % len(colors)])
    turtle.pensize(...)
    turtle.forward(...)
    turtle.left(...)

Типові помилки

  • x // 100 + 1 - товщина стрибатиме 1, 2, 3, 4 сходинками замість плавного росту.

1.8 Математична троянда r = 180 · cos(15θ)

Що має вийти

Рисунок 8: чорне тло, квітка з 15 вузьких пелюсток. Біля центру лінії пурпурові (magenta), на кінцях пелюсток блакитні (cyan). Товщина 2.

Математика простими словами

Це крива в полярних координатах: для кожного кута θ рахуєш відстань від центру r.

r = 180 · cos(15θ)

θ = 0°  → cos 0° = 1       → r = 180   (кінчик пелюстки праворуч)
θ = 6°  → cos 90° = 0      → r = 0     (повернулися в центр)
θ = 12° → cos 180° = -1    → r = -180  (від'ємний r = точка в ПРОТИЛЕЖНИЙ бік)

Тобто одна пелюстка - це 12° кута. Від'ємний r малює пелюстку з протилежного боку, тому за 0° ... 180° усі 15 пелюсток уже намальовані, а 180° ... 360° проходить по них удруге (для непарного числа 15 так завжди). Нічого не ламається - просто лінія двічі.

Перехід у звичайні координати:

x = r · cos θ
y = r · sin θ

Радіани: theta = math.radians(angle). І ще: всередині cos(15θ) теж радіани - якщо theta вже в радіанах, то math.cos(15 * theta) правильно.

Колір: abs(r) > 100 → cyan, інакше magenta. Беремо МОДУЛЬ, бо r буває від'ємним, а пелюстка при r = -150 така ж довга, як при r = 150.

План

  1. Тло, speed(0), pensize(2), import math.
  2. Перша точка (θ = 0): порахувати x, y, penup, goto, pendown.
  3. for angle in range(1, 361): theta у радіанах, r, x, y, колір за |r|, goto(x, y).
  4. hideturtle(), done().

Підказки

Рівень 1. Крок 1° достатній: на пелюстку припадає 12 точок, виходить гладко.

Рівень 2.

theta = math.radians(angle)
radius = 180 * math.cos(15 * theta)

Рівень 3.

for angle in range(...):
    theta = ...
    radius = ...
    point_x = radius * math.cos(theta)
    point_y = ...
    if abs(radius) > 100:
        turtle.pencolor("cyan")
    else:
        ...
    turtle.goto(point_x, point_y)

Типові помилки

  • math.cos(angle) без radians - вийде хаотична «зірка» з ламаних ліній, бо 1, 2, 3 ... сприймаються як радіани (1 рад ≈ 57°).
  • Не підняли перо перед першою точкою - з центру (0, 0) до (180, 0) тягнеться зайва лінія. На рисунку її теж можна не помітити, бо вона лягає на пелюстку, але правильно - penup.
  • if radius > 100 без abs - половина пелюсток (з від'ємним r) буде повністю пурпурова.
  • range(360) - не дійде до 360° і може лишитися щілина. range(361) або range(1, 361) після першої точки.

Рівень 2. Квадрат:

Рівень 3.

1.11 Пейзаж через декомпозицію

Що має вийти

Рисунок на стор. 17 праворуч: персикове небо смугами, жовте сонце, помаранчеві гори позаду, теракотові ближче, пурпурова вода, темно-фіолетові скелі спереду зліва і справа, 8 птахів-«галочок».

Що головне в цьому завданні

Тут оцінюють не точність гір до пікселя, а СТРУКТУРУ: 1. Функція draw_polygon(t, points, color) - одна на всі фігури. Приймає черепашку, список точок [(x, y), ...] і колір, малює залитий багатокутник. 2. Функція draw_bird(t, x, y, size) - птах із двох дуг circle(radius, extent). 3. Малювати ВІД ЗАДНЬОГО ПЛАНУ ДО ПЕРЕДНЬОГО (Z-index з теорії, стор. 6): небо → сонце → далекі гори → ближні гори → вода → передній план → птахи. Що намальоване пізніше, лежить зверху. 4. speed(0), hideturtle(). 5. Об'єктний стиль: screen = turtle.Screen(), t = turtle.Turtle() (функції приймають t).

Як отримати координати гір (найбільша робота)

Відкрий картинку з умови в Paint: унизу вікна Paint показує координати курсора в пікселях. Пройдись по вершинах гори і випиши точки. Але в Paint (0, 0) - ЛІВИЙ ВЕРХНІЙ кут і y росте ВНИЗ, а в turtle (0, 0) - центр і y вгору. Переведення (картинка 783 × 526):

x_turtle = x_paint - 392
y_turtle = 263 - y_paint

Зручно зробити маленьку функцію, яка це рахує, і писати точки прямо з Paint. Вікно того ж розміру: screen.setup(784, 526).

Птах з двох дуг

t.circle(radius, extent) малює ДУГУ: шматок кола на extent градусів. Додатний radius - дуга вигинається ліворуч, від'ємний - праворуч. Птах на рисунку - як «галочка» з вигнутими крилами: дві дуги виходять з нижньої точки вгору-вліво і вгору-вправо.

ліве крило:  з нижньої точки, напрям 145° (вгору-вліво), circle(size, 40)
праве крило: з тієї ж точки,  напрям 35° (вгору-вправо),  circle(-size, 40)

Між крилами - penup, goto назад у нижню точку, pendown. Товщина 3-5, колір темно-коричневий.

План

  1. screen, t, розмір вікна, t.speed(0), t.hideturtle().
  2. draw_polygon: penup → goto(перша точка) → pendown → color → begin_fill → goto по всіх інших → goto(перша) (замкнути!) → end_fill.
  3. Небо - 2-3 прямокутники різного відтінку через ту ж draw_polygon.
  4. Сонце - begin_fill, circle(44), end_fill (почати з точки на 44 нижче центру, як у 1.5).
  5. Гори, вода, передній план - по одному виклику draw_polygon зі своїм списком точок.
  6. Список птахів [(x, y, size), ...] і цикл з draw_bird.

Підказки

Рівень 1. Кольори в turtle можна задавати і назвою, і кодом "#fb9a35". Коди можна взяти піпеткою з картинки (Paint → піпетка → «Змінити кольори» показує RGB; переведи в hex або пиши t.color((251, 154, 53)) після screen.colormode(255)).

Рівень 2.

def draw_polygon(t, points, color):
    t.penup()
    t.goto(points[0])
    t.pendown()
    t.color(color)
    t.begin_fill()

        t.goto(point)

(це майже вся функція - її дала сама теорія на стор. 5-6, тут лише зібрано докупи).

  • Порядок шарів: вода після переднього плану - вода перекриє скелі.

Завдання 2. Інтерактивний годинник

Що має вийти

Рисунок стор. 18: зліва аналоговий (біле тло, коло з 60 поділками, 12 жирних, три стрілки: годинна товста коротка, хвилинна довша, секундна червона тонка). Справа цифровий (чорне тло, великі зелені цифри HH:MM:SS і дата). Числа 1-12 умова теж вимагає (на рисунку їх нема).

Що потрібно (за умовою)

  1. Аналоговий режим: циферблат, 12 поділок + числа, 3 стрілки різні товщиною, довжиною, кольором.
  2. Ліва кнопка миші - аналоговий / цифровий. Права - показати / сховати дату з днем тижня.
  3. Мінімум 3 теми, Up/Right - наступна, Down/Left - попередня. Тема міняє фон, циферблат, кожну стрілку, текст.
  4. На 00 секунд - спалах (фон іншим кольором).
  5. Без миготіння: screen.tracer(0) + screen.update() + screen.ontimer(...).

Математика стрілок (найважливіше)

Кут на годиннику рахуємо від 12 ЗА годинниковою стрілкою.

секундна:  6° за секунду                         (360 / 60)
хвилинна:  6° за хвилину + 0,1° за секунду        (6 / 60 = 0,1)
годинна:   30° за годину + 0,5° за хвилину        (360 / 12 = 30,  30 / 60 = 0,5)
           + 0,5/60 ° за секунду

кут_год = (hours % 12) · 30 + minutes · 0,5 + seconds · 0,5 / 60
кут_хв  = minutes · 6 + seconds · 0,1
кут_сек = seconds · 6

Перевірка на числах: 15:30:00 → годинна (3 · 30) + 30 · 0,5 = 90 + 15 = 105° (між 3 і 4, як і має бути о пів на четверту).

Це і є «розширені формули з урахуванням хвилин і секунд» з умови (теорія стор. 7-8: Δθ = 6°, 1 крок = 0,1°).

А turtle рахує напрям від осі x ПРОТИ годинникової. Переведення:

heading = 90 - кут_годинника

12 год (0°)  → heading 90  (вгору)
3 год (90°)  → heading 0   (праворуч)

φ = 90° - k · 30°
x = R · cos φ,   y = R · sin φ      (φ - у радіани!)

Фізика простими словами

Стіна в x = 0. Мала кулька стартує з x = L/2 і летить до стіни зі швидкістю -v. Велика стоїть у x = L.

Між зіткненнями сил немає, тому рух рівномірний: x(t) = x0 + v·t.

Коли вдариться об стіну (лише якщо летить вліво, v_m < 0):

x_m + v_m · t = 0   ⇒   t = -x_m / v_m

Коли наздожене велику (лише якщо v_m > v_M, тобто відстань скорочується):

x_m + v_m·t = x_M + v_M·t   ⇒   t = (x_M - x_m) / (v_m - v_M)

Наступна подія - та, в якої t менший.

Після удару об стіну: v_m = -v_m (модуль той самий, знак інший). Після зіткнення кульок (формули з теорії, стор. 11):

       (m - M)·v_m + 2M·v_M              2m·v_m + (M - m)·v_M
u_m = ──────────────────────      u_M = ──────────────────────
              m + M                             m + M

Перевір на числах: m = M = 1, v_m = 2, v_M = 0 → u_m = 0, u_M = 2 (обмін швидкостями, як у більярді).

Коли кінець: мала летить вправо, але не швидше за велику: 0 ≤ v_m ≤ v_M - вона вже не наздожене, а стіна позаду. Велика весь час тільки віддаляється (її штовхають лише зліва).

Шлях - сума модулів: S = S + |v_m| · t на кожному етапі. Але умова каже рахувати S до ОСТАННЬОГО удару об стіну (стор. 20), тому запам'ятовуй S щоразу при ударі об стіну.

Рівень 3. Анімація: щоб кадр знав позиції в будь-який момент, бери останню подію, що вже відбулася до моменту t, і x = x_події + v_події · (t - t_події). Масштаб екрана підбери під НАЙДАЛЬШУ точку великої кульки в кінці, бо вона весь час їде вправо і інакше втече за екран. Для графіків S(m) і S(M) бери значення в геометричній прогресії (від M/10⁴ до 2M) і логарифмічні осі plt.xscale("log") - інакше все цікаве стиснеться в купку біля нуля.

Що вийде на графіках і чому (для фізичного аналізу)

  1. S(v) - горизонтальна пряма. Найважливіше пояснення. Усі моменти зіткнень пропорційні 1/v, а місця зіткнень від v не залежать: швидша кулька проходить ТОЙ САМИЙ маршрут, просто швидше (як той самий фільм, прокручений швидше). Шлях - це довжина маршруту, тому не змінюється.
  2. S(L) - пряма через нуль. Якщо всі відстані збільшити вдвічі, вся картина зіткнень просто масштабується, кількість і порядок ударів ті самі → S ∝ L.
  3. S(m) і S(M) залежать лише від відношення r = M/m (формули швидкостей містять тільки відношення мас). Більше r → більше відскоків між стіною і великою кулькою → більше S. Мала кулька ЛЕГША → шлях ДОВШИЙ. Графіки «сходинками», бо N ціле: поки N не змінюється, S майже стоїть, при зміні N - стрибок. Якщо m ≥ M - лише один удар об стіну, S = L/2.
  4. N(r). Моделювання дає (перевірено для r від 1 до 10⁶):
N ≈ (π / 2) · √(M / m)       точніше N = ⌈ π / (2·arctg√(m/M)) ⌉
r = 100   → N = 16
r = 10⁴   → N = 158
r = 10⁶   → N = 1571  (= 1570,8 → цифри π!)

Це відома задача «більярд Гальперіна» (G. Galperin, Regular and Chaotic Dynamics, 2003): там велика кулька НАЛІТАЄ на малу, і N дає цифри π (r = 100 → 31, r = 10⁴ → 314). У нашій ЛР велика спочатку стоїть, тому зіткнень приблизно вдвічі менше: π/2 · √r. Звідки π: якщо ввести координати √m·x_m і √M·x_M, енергія стає «довжиною вектора», кожне зіткнення - віддзеркалення, і кулька «ходить» у куті з кутом arctg√(m/M). Скільки віддзеркалень влазить у 90° - стільки й зіткнень. (Глибоко пояснювати на захисті не обов'язково, але це сильний аргумент.) 5. M = m: після удару об стіну мала наздоганяє велику, вони обмінюються швидкостями, мала зупиняється. N = 2, S = L/2. 6. M ≫ m: велика майже не зрушує з місця при кожному ударі, мала відскакує майже з тією ж швидкістю, ходить туди-сюди дуже багато разів. N росте як √(M/m), S теж росте (швидше за √r). 7. Стіна не змінює енергію: модуль швидкості той самий (u = -v), а E = mv²/2 залежить від v², тобто від модуля. Стіна нескінченно масивна (M → ∞ у формулі), вона нічого не забирає. 8. Кульки обидві міняють швидкість: за 3-м законом Ньютона сили однакові й протилежні, а маси скінченні, тому імпульс передається - і він, і енергія зберігаються лише СУМАРНО.

Типові помилки

  • Крок dt замість подій - умова прямо забороняє («Не використовуйте ... фіксованим малим кроком часу dt»).
  • Ділення на нуль: t = (x_M - x_m) / (v_m - v_M), коли швидкості рівні. Рахувати лише коли v_m > v_M.
  • x_m < x_M в умові кінця: після зіткнення кульки в ОДНІЙ точці (x_m == x_M), і така умова дасть нескінченний цикл.
  • S рахують до кінця моделювання, а умова - до останнього удару об СТІНУ (для M = 4 це 25, а «повний» шлях 75).
  • float(input()) без try - при вводі «abc» програма падає. Умова вимагає перевірку.
  • Графік без підписів осей і заголовка - умова їх вимагає (plt.xlabel, plt.ylabel, plt.title).
  • Анімація і matplotlib обидва на Tk: показуй графіки ПІСЛЯ того, як закриєш вікно turtle (turtle.done() повертає керування, коли вікно закрите).
