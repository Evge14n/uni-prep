Тема 4. День 4: Права і sudo

Навіщо: розуміти «Permission denied», запускати свої скрипти і не ламати систему через sudo.

Коротко (5 хв)

Хто ти: whoami → evgen. id → твої групи (є sudo - значить, можеш бути адміністратором).

Права файлу - у ls -l:

Нове тут:

  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки). -l - докладний список: права, власник, розмір у байтах, дата зміни (long - «довгий»).

Як читати:

  • Слово з мінусом (як -l тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Короткі можна склеювати: -ld = -l і -d.
  • Символи ~ > # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

-rwxr-xr--  1 evgen evgen  512 Nov 17 10:00 run.sh
│└┬┘└┬┘└┬┘    │     │
│ │  │  │     │     └ група
│ │  │  │     └────── власник
│ │  │  └ інші (others):   r--  лише читати
│ │  └─── група (group):   r-x  читати і запускати
│ └────── власник (user):  rwx  читати, писати, запускати
└──────── тип: - файл, d тека, l посилання

r = read (читати), w = write (змінювати), x = execute (запускати; для теки - заходити в неї).

Числа замість букв: r = 4, w = 2, x = 1, додаєш для кожної трійки. rwx = 4+2+1 = 7, r-x = 4+1 = 5, r-- = 4. Тому: - chmod 755 run.sh → rwxr-xr-x (скрипт: усі можуть запускати, змінює лише власник); - chmod 644 lab.py → rw-r--r-- (звичайний файл).

Нове тут:

  • chmod - змінює права файлу: хто може читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. 755 - rwxr-xr-x: 7 = rwx (4+2+1) тобі, 5 = r-x (4+1) групі й іншим; для скриптів і тек - усі читають і запускають, змінюєш лише ти; 644 - rw-r--r--: 6 = rw- (4+2) тобі, 4 = r-- групі й іншим; звичайний файл - ти змінюєш, інші лише читають.

Простіше буквами: chmod +x run.sh - дозволити запуск, chmod -w file - заборонити зміну.

Нове тут:

  • chmod: +x - + - додати право, x (execute - «виконувати») - запускати файл як програму; без u/g/o - власнику, групі й іншим; -w - це НЕ прапорець, а права: забрати w (змінювати) - файл стане лише для читання.

Запуск свого скрипта: ./run.sh (./ = «з цієї теки»). Без chmod +x буде «Permission denied». Можна і без прав: bash run.sh, python3 lab.py.

Нове тут:

  • bash - програма, що читає й виконує твої команди; bash файл.sh - з файлу. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»).
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.

sudo - «зробити від імені адміністратора (root)». sudo apt install ... спитає твій пароль Ubuntu (символи не видно). Пароль памʼятається ~15 хв.

Нове тут:

  • sudo - виконує одну команду як адміністратор; спитає твій пароль (видно зірочки). Назва: superuser do - «зроби як суперкористувач» (адміністратор).
  • apt install - ставить програму з інтернету; на «Бажаєте продовжити? [Y/n]» - Enter. Назва: apt - Advanced Package Tool - «розширений інструмент для пакетів (програм)».

Правила: - sudo - лише для системного: apt, файли поза домашньою текою. - Свої файли (~/...) ніколи не чіпай через sudo: файли стануть власністю root, і потім без sudo їх не зміниш. Ознака: у ls -l власник root. - sudo pip install - не роби. Python-пакети для лаб - у venv (день 8).

Нове тут:

  • pip install - ставить бібліотеку Python (лише у venv). Назва: pip - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».

Особливість WSL: файли на /mnt/c і /mnt/d показують права як rwxrwxrwx - це диск Windows, справжні права там вирішує Windows. chmod на них зазвичай нічого не змінює.

Руками (10 хв)

whoami
id
cd ~/univer/praktyka
printf 'echo "Привіт з скрипта"\n' > run.sh
ls -l run.sh             # -rw-r--r-- : x нема
./run.sh                 # Permission denied
bash run.sh              # працює: bash сам читає файл
chmod +x run.sh
ls -l run.sh             # -rwxr-xr-x
./run.sh                 # тепер працює
chmod 600 run.sh
ls -l run.sh             # -rw------- : лише ти читаєш і пишеш
chmod 755 run.sh
sudo whoami              # спитає пароль, відповідь root
ls -l /etc/hostname      # власник root
echo test > /etc/test.txt          # Permission denied - система не твоя
ls -ld /mnt/c            # drwxrwxrwx - диск Windows

Нове тут:

  • whoami - друкує твій логін. Назва: who am I - «хто я».
  • id - показує твій номер у системі (uid) і групи. Назва: identity - «особа» (ID - ідентифікатор, номер).
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • '...' (single quotes) - текст буквально: $, * і пробіли всередині - звичайні символи.
  • echo - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • > (redirect) - пише вивід у файл, старий вміст стирає.
  • ls: -d (--directory) - показати саму теку, а не її вміст: ls -ld lr1 (directory - «тека»).
  • # (hash) - коментар: далі до кінця рядка bash не читає.
  • chmod: 600 - rw-------: 6 лише тобі (читати і змінювати), групі й іншим 0 - для ключів ssh і паролів.
  • ./скрипт - запускає програму за шляхом до її файлу, напр. ./файл.sh. Назва: ./ - «звідси».

Типові помилки

  • sudo перед усім підряд «щоб не було помилок». Потім Permission denied уже на власних файлах. Виправити: sudo chown -R evgen:evgen ~/univer (повернути собі власність).
  • chmod 777 «щоб працювало». Це дозволяє всім усе. Для скрипта досить chmod +x (або 755).
  • Забув пароль Ubuntu. У PowerShell Windows: wsl -u root passwd evgen (замість evgen - твоє імʼя в Ubuntu, воно в рядку перед @) - задаси новий.
  • Запускаєш run.sh без ./ → «command not found». Поточна тека не шукається автоматично.

Нове тут:

  • chown - змінює, чий файл: власника і групу (зазвичай через sudo). Назва: change owner - «змінити власника». -R (--recursive) - змінити власника теки і всього, що в ній (recursive - «рекурсивно»: і в усіх підтеках).
  • chmod: 777 - rwxrwxrwx: 7 усім трьом - усім усе; майже завжди помилка, див. приклад.

Самоперевірка

  1. Що означають права -rw-r--r--?
  2. Яким числом записати rwxr-xr-x?
  3. Чому ./script.sh пише «Permission denied», а bash script.sh працює?
  4. Чий пароль питає sudo у WSL?
  5. Чому не можна sudo nano ~/univer/labs/lab.py?

Нове тут:

  • nano - простий редактор файлів у терміналі. Назва: nano - жарт з одиницями: наступник редактора pico (піко < нано).
Відповіді
  1. Звичайний файл; власник читає і пише, група і всі інші лише читають.
  2. 755 (7 = 4+2+1, 5 = 4+1).
  3. У файлу нема права x. bash script.sh запускає bash, а він просто читає файл, тому x не потрібне.
  4. Твій пароль користувача Ubuntu (того, що задав при встановленні), не пароль Windows.
  5. Файл може стати власністю root (якщо nano створить його заново), і потім ти без sudo його не збережеш. Свої файли редагують без sudo.
