Тема 7. День 7: Пайпи, перенаправлення, grep

Навіщо: знайти, де в лабах функція, зберегти вивід у файл, порахувати рядки - однією командою.

Коротко (5 хв)

Перенаправлення:

Запис Що робить
команда > файл вивід у файл (файл перезаписується)
команда >> файл дописати в кінець файлу
команда 2> файл помилки (stderr) у файл
команда > файл 2>&1 і вивід, і помилки в один файл
команда < файл взяти ввід з файлу (замість клавіатури)
команда > /dev/null викинути вивід

Пайп | - вивід однієї команди стає входом наступної: ls | wc -l - скільки файлів; history | grep git - які git-команди я вводив.

grep - знайти рядки з текстом:

Команда Що
grep "def " lab.py рядки з def
grep -n з номерами рядків
grep -i без різниці великі/малі
grep -r "turtle" . у всіх файлах теки і підтек
grep -c лише кількість рядків
grep -v рядки, де цього нема

Інші корисні: wc -l (рядки), sort, uniq -c (порахувати однакові сусідні), head, tail, find . -name "*.py" (знайти файли за назвою).

Ввід для програми з input(). Програма питає число - можна подати без клавіатури:

printf "5\n" | python3 lab.py
printf "3\n4\n" | python3 lab.py      # два input() - два рядки
python3 lab.py < vvid.txt

Нове тут:

  • printf - друкує текст за шаблоном; \n - Enter. Назва: print formatted - «надрукувати за шаблоном».
  • python3 - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
  • "..." - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».
  • | - передає вивід однієї команди на ввід іншій. Назва: pipe - «труба» (пайп), вертикальна риска.
  • < - подає файл програмі замість клавіатури. Назва: input redirect - «ввід з файлу».
  • # - коментар: далі до кінця рядка bash не читає. Назва: hash («решітка») - коментар.

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка. Зручно, коли ганяєш ту саму перевірку багато разів.

Руками (10 хв)

cd ~/univer/praktyka
printf 'def area(r):\n    return 3.14 * r * r\n\n\ndef perimeter(r):\n    return 2 * 3.14 * r\n\nprint(area(2))\n' > geom.py
grep "def " geom.py
grep -n "def " geom.py
grep -c "def " geom.py               # 2
grep -v "^$" geom.py                 # без порожніх рядків
python3 geom.py > out.txt
cat out.txt
python3 geom.py >> out.txt
cat out.txt                          # два рядки
python3 nema.py 2> err.txt
cat err.txt                          # No such file or directory
ls / | wc -l
find ~/univer -name "*.py" -not -path "*/.venv/*" | head
printf 'name = input()\nprint("Привіт,", name)\n' > hi.py
printf "Студент\n" | python3 hi.py
history | grep cd | tail -5

Нове тут:

  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • grep - знаходить рядки з текстом у файлах. Назва: g/re/p з редактора ed: «знайти регулярний вираз у всьому файлі і надрукувати». -n - показати номер рядка перед кожним збігом (line number); -c - лише порахувати рядки зі збігом у кожному файлі (count); -v - навпаки: рядки, де шаблону НЕМА (invert).
  • cat - показує вміст файлу. Назва: concatenate - «зчепити»: склеює кілька файлів в один вивід.
  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки). / - корінь системи: bin, etc, home, usr .
  • wc - рахує рядки, слова, символи. Назва: word count - «підрахунок слів»; рахує ще рядки й байти. -l - лише кількість рядків (lines).
  • find - шукає файли за назвою, часом чи власником. Назва: find - «знайти». -name - за назвою, шаблон у лапках: -name ".py"; великі й малі літери різні; -not - заперечення наступної умови: -not -user "$USER" - чужі файли; -path - шлях (а не лише назва) підходить під шаблон: -path '/.venv/*'.
  • head - показує перші рядки файлу. Назва: head - «голова»: початок файлу.
  • history - показує список уже набраних команд з номерами. Назва: history - «історія» набраних команд.
  • tail - показує останні рядки; -f стежить наживо. Назва: tail - «хвіст»: кінець файлу.
  • ~ - домашня тека /home/evgen. Назва: tilde («тильда») - домашня тека.
  • '...' - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».
  • > - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.
  • >> - дописує вивід у кінець файлу. Назва: append - «дописати» в кінець файлу.
  • 2> - пише лише помилки у файл. Назва: redirect stderr - «перенаправити помилки»: 2 - номер потоку помилок.

Якщо на цьому ПК чи ноутбуці лаби лежать у ~/univer/prog або ~/univer/labs:

grep -rn "import doctest" ~/univer/labs
grep -rl "turtle" ~/univer/labs

Нове тут:

  • grep: -r - шукати в усіх файлах теки і підтек (recursive); -l - лише назви файлів, де є збіг (list).

Типові помилки

  • python3 lab.py > lab.py - стирає твій код: > спершу обнуляє файл. Вивід пиши в інший файл.
  • > замість >> - старий вміст пропав.
  • grep def без лапок і з пробілом: grep def area geom.py шукає «def» у файлах area і geom.py. Фраза з пробілом - у лапках: grep "def area" geom.py.
  • grep -r по всьому диску (/ чи /mnt/d) - дуже довго. Шукай у конкретній теці.

Самоперевірка

  1. Чим > відрізняється від >>?
  2. Як порахувати, скільки функцій (def) у файлі lab4.py?
  3. Як запустити lab.py, що питає одне число, і подати йому 10 без клавіатури?
  4. Що робить 2>?
  5. Чому python3 lab.py > lab.py - погана ідея?
Відповіді
  1. > перезаписує файл, >> дописує в кінець.
  2. grep -c "def " lab4.py.
  3. printf "10\n" | python3 lab.py (або echo 10 | python3 lab.py).
  4. Перенаправляє помилки (потік stderr) у файл.
  5. Перед запуском > очищає lab.py, тож Python запускає вже порожній файл, а код зник.
