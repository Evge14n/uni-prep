Тема 7. День 7: Пайпи, перенаправлення, grep

Навіщо: знайти, де в лабах функція, зберегти вивід у файл, порахувати рядки - однією командою.

Коротко (5 хв)

Перенаправлення:

Запис Що робить
команда > файл вивід у файл (файл перезаписується)
команда >> файл дописати в кінець файлу
команда 2> файл помилки (stderr) у файл
команда > файл 2>&1 і вивід, і помилки в один файл
команда < файл взяти ввід з файлу (замість клавіатури)
команда > /dev/null викинути вивід

Пайп | - вивід однієї команди стає входом наступної: ls | wc -l - скільки файлів; history | grep git - які git-команди я вводив.

Нове тут:

  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки).
  • | (pipe) - вивід лівої команди йде на вхід правої.
  • wc - рахує рядки, слова, символи. Назва: word count - «підрахунок слів»; рахує ще рядки й байти. -l (--lines) - лише кількість рядків (lines - «рядки»).
  • history - показує список уже набраних команд з номерами. Назва: history - «історія» набраних команд.
  • grep - шукає рядки з текстом (у файлах або те, що прийшло через |). Назва: g/re/p з редактора ed: global regular expression print - «скрізь знайти шаблон, надрукувати».

Як читати:

  • Слово з мінусом (як -l тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Короткі можна склеювати: -not = -n і -o і -t.
  • Символи ~ | > * # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

grep - знайти рядки з текстом:

Команда Що
grep "def " lab.py рядки з def
grep -n з номерами рядків
grep -i без різниці великі/малі
grep -r "turtle" . у всіх файлах теки і підтек
grep -c лише кількість рядків
grep -v рядки, де цього нема

Нове тут:

  • grep: -n (--line-number) - показати номер рядка перед кожним збігом (line number - «номер рядка»); -i (--ignore-case) - без різниці між великими й малими літерами (ignore case - «не зважати на регістр»); -r (--recursive) - шукати в усіх файлах теки і підтек (recursive - «рекурсивно», углиб); . - з -r: шукати в поточній теці і всіх підтеках; -c (--count) - не показувати рядки, а лише порахувати, скільки їх зі збігом (count - «порахувати»); -v (--invert-match) - навпаки: рядки, де шаблону НЕМА (invert - «перевернути»).
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.

Інші корисні: wc -l (рядки), sort, uniq -c (порахувати однакові сусідні), head, tail, find . -name "*.py" (знайти файли за назвою).

Нове тут:

  • uniq - склеює однакові сусідні рядки (з -c - рахує). Назва: unique - «єдиний, неповторний»: прибрати повтори. -c (--count) - писати перед рядком, скільки разів він ішов підряд (count - «рахувати»).
  • find - шукає файли й теки за назвою, і в усіх підтеках. Назва: find - «знайти». -name - за назвою, шаблон у лапках: -name "*.py"; великі й малі літери різні; . - шукати тут і в усіх підтеках.

Ввід для програми з input(). Програма питає число - можна подати без клавіатури:

printf "5\n" | python3 lab.py
printf "3\n4\n" | python3 lab.py      # два input() - два рядки
python3 lab.py < vvid.txt

Нове тут:

  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
  • # (hash) - коментар: далі до кінця рядка bash не читає.
  • < (input redirect) - подає файл програмі замість клавіатури.

Зручно, коли ганяєш ту саму перевірку багато разів.

Руками (10 хв)

cd ~/univer/praktyka
printf 'def area(r):\n    return 3.14 * r * r\n\n\ndef perimeter(r):\n    return 2 * 3.14 * r\n\nprint(area(2))\n' > geom.py
grep "def " geom.py
grep -n "def " geom.py
grep -c "def " geom.py               # 2
grep -v "^$" geom.py                 # без порожніх рядків
python3 geom.py > out.txt
cat out.txt
python3 geom.py >> out.txt
cat out.txt                          # два рядки
python3 nema.py 2> err.txt
cat err.txt                          # No such file or directory
ls / | wc -l
find ~/univer -name "*.py" -not -path "*/.venv/*" | head
printf 'name = input()\nprint("Привіт,", name)\n' > hi.py
printf "Студент\n" | python3 hi.py
history | grep cd | tail -5

Нове тут:

  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • '...' (single quotes) - текст буквально: $, * і пробіли всередині - звичайні символи.
  • 2> (redirect stderr) - пише лише помилки у файл.
  • > (redirect) - пише вивід у файл, старий вміст стирає.
  • >> (append) - дописує вивід у кінець файлу.
  • grep: ^ на початку шаблону - «рядок починається з цього тексту».
  • cat - показує вміст файлу. Назва: concatenate - «зчепити» (уміє склеїти кілька файлів в один вивід).
  • ls: / - корінь системи: bin, etc, home, usr .
  • find: -not - заперечення наступної умови: -not -user "$USER" - чужі файли (not - «не»); -path - весь шлях (а не лише назва) підходить під шаблон: -path '*/.venv/*' (path - «шлях»).
  • head - показує перші рядки файлу (або того, що прийшло через |). Назва: head - «голова».
  • tail - показує останні рядки (файлу чи того, що прийшло через |). Назва: tail - «хвіст». -5 - лише 5 останні рядки (те саме, що -n 5).

Якщо на цьому ПК чи ноутбуці лаби лежать у ~/univer/prog або ~/univer/labs:

grep -rn "import doctest" ~/univer/labs
grep -rl "turtle" ~/univer/labs

Нове тут:

  • grep: -l (--files-with-matches) - лише назви файлів, де є збіг (list - «список»).

Типові помилки

  • python3 lab.py > lab.py - стирає твій код: > спершу обнуляє файл. Вивід пиши в інший файл.
  • > замість >> - старий вміст пропав.
  • grep def без лапок і з пробілом: grep def area geom.py шукає «def» у файлах area і geom.py. Фраза з пробілом - у лапках: grep "def area" geom.py.
  • grep -r по всьому диску (/ чи /mnt/d) - дуже довго. Шукай у конкретній теці.

Самоперевірка

  1. Чим > відрізняється від >>?
  2. Як порахувати, скільки функцій (def) у файлі lab4.py?
  3. Як запустити lab.py, що питає одне число, і подати йому 10 без клавіатури?
  4. Що робить 2>?
  5. Чому python3 lab.py > lab.py - погана ідея?
Відповіді
  1. > перезаписує файл, >> дописує в кінець.
  2. grep -c "def " lab4.py.
  3. printf "10\n" | python3 lab.py (або echo 10 | python3 lab.py).
  4. Перенаправляє помилки (потік stderr) у файл.
  5. Перед запуском > очищає lab.py, тож Python запускає вже порожній файл, а код зник.

Нове тут:

  • echo - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.
