Тема 8. День 8: Python у venv і запуск ЛР

Навіщо: головне для лаб - запускати код, проганяти doctest і перевірки стилю, які просить викладач.

Коротко (5 хв)

venv (віртуальне середовище) - окрема «коробка» з Python-бібліотеками для проєкту. Скрипт установки вже зробив ~/univer/.venv з pytest, flake8, black, pycodestyle, ruff, mypy, matplotlib, numpy.

Команда Що робить
python3 -m venv .venv створити venv у поточній теці
source ~/univer/.venv/bin/activate увімкнути (рядок починається з (.venv))
univer те саме + перейти в ~/univer (наша команда)
deactivate вимкнути
pip install назва поставити бібліотеку у venv
pip list що стоїть
which python який Python зараз (у venv - .../.venv/bin/python)

Нове тут:

  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).
  • python3 -m venv - створює venv - окрему теку з Python і бібліотеками для лаб. Назва: virtual environment - «віртуальне середовище».
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • univer - переходить у ~/univer і вмикає venv.
  • deactivate - вимикає venv (окремий Python проєкту): python знову системний. Назва: deactivate - «вимкнути» (venv).
  • pip install - ставить бібліотеку Python (лише у venv). Назва: pip - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».
  • pip list - показує встановлені бібліотеки і їхні версії.
  • which - показує, який саме файл запуститься. Назва: which - «котрий». python - покаже, який python запуститься: у venv - з теки .venv/bin; поза venv у Mint python (без 3) нема - тиша.

Як читати:

  • Слово з мінусом (як -m тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Символи ~ | # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Як перевіряти doctest у лабах. У заготовках викладача в кінці файлу стоїть doctest.testmod().

Команда Коли
python lab4.py як задумав викладач: testmod() у файлі проганяє doctest. Тиша = все пройшло, ***Test Failed*** = ні. Далі програма працює як звичайно (питає input(), малює)
python lab4.py -v те саме з подробицями (-v бачить testmod()), унизу Test passed.
python -m pytest --doctest-modules -q lab4.py надійна перевірка: 1 passed або FAILED і код помилки (зручно в скриптах)
perevir lab4.py наша команда: doctest (через pytest) + flake8 + mypy

Нове тут:

  • perevir - перевіряє лабу всіма інструментами одразу (doctest, стиль, типи).

Пастка: не запускай python -m doctest lab4.py для таких файлів. Коли в файлі є doctest.testmod() не під if __name__ == "__main__":, команда -m doctest змушує його перевіряти ще й сам модуль doctest, і ти побачиш чужу помилку 1 of 21 in __main__.DebugRunner ***Test Failed***, хоча твій код правильний. python -m doctest годиться лише для файлів, де testmod() нема або він під if __name__ == "__main__":.

Стиль: flake8 --max-line-length=78 lab4.py (викладач просив рядки до 78), mypy lab4.py (типи, знаходить str замість int), black -l 78 lab4.py (сам переформатує файл, перед цим зроби коміт або копію).

Нове тут:

  • flake8 - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. --max-line-length - найбільша довжина рядка; викладач хоче 78.

Вимоги викладача (з файлу «Вимоги викладача»): лаба зарахована, коли проходять усі doctest; функція повертає через return, а не друкує; код - у наданій функції, назви і doctest не міняти; перед здачею flake8, pycodestyle, mypy, ruff або black.

Якщо в лабі є input() на верхньому рівні файлу (як у твоїй ЛР3), то pytest скаже «reading from stdin» (а perevir підкаже, що робити). Тоді: printf "5\n" | python lab.py - testmod() усередині спрацює, а ввід піде з printf.

Нове тут:

  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • | (pipe) - вивід лівої команди йде на вхід правої.

turtle (ЛР4) у WSL: на Windows 11 і Windows 10 збірки 19044+ (з WSL з Microsoft Store) вікно відкривається як звичайне вікно Windows. Наприкінці потрібен turtle.done(), інакше вікно одразу закриється (так і в методичці ЛР4). Головне правило для turtle-лаби: малювання і turtle.done() - лише під if __name__ == "__main__":. Інакше перевірка doctest (pytest, perevir) відкриє вікно і чекатиме, поки ти його закриєш. Якщо вікна нема зовсім (стара Windows) - див. «00 - Почни тут», крок 6.

Надрукуй (це тренування, не сама лаба):

import doctest


def square_area(side: float) -> float:
    """
    Площа квадрата.

    >>> square_area(3)
    9
    >>> square_area(2.5)
    6.25
    """
    return side * side


doctest.testmod()

Далі:

python kvadrat.py                # тиша - усі doctest пройшли
python kvadrat.py -v             # подробиці, внизу Test passed.
perevir kvadrat.py               # doctest: усе пройшло (1 passed ...), flake8, mypy

Нове тут:

  • # (hash) - коментар: далі до кінця рядка bash не читає.

Тепер зіпсуй: заміни side * side на side * 2, збережи, і ще раз python kvadrat.py - побачиш Failed example з Expected: 9 і Got: 6. І perevir kvadrat.py - напише «Є ПОМИЛКИ». Поверни як було.

Типові помилки

  • Забув univer (venv вимкнено) → ModuleNotFoundError: No module named 'matplotlib' або externally-managed-environment при pip. Подивись, чи є (.venv) на початку рядка.
  • python vs python3: поза venv у Ubuntu є лише python3. У venv працюють обидва.
  • python -m doctest на файлі з doctest.testmod() - чужий «Test Failed» з DebugRunner (див. вище).
  • python lab.py при помилках doctest все одно завершується «успішно» (код 0) - у скриптах бери pytest.
  • Venv не переносять копіюванням між комп'ютерами. На новому - створюють заново (ustanovka.sh).
  • Venv не кладуть у git (день 9, .gitignore).
  • doctest «падає» через пробіл у кінці рядка або 6.25 проти 6.250. Doctest порівнює текст буквально - дивись Expected і Got.
  • Doctest викладача теж бувають з помилками (у ЛР1 завдання 3 два приклади хибні - розбір ЛР1 завдання 3 лежить у теці Лабораторні). Не підганяй код - скажи викладачу.

Самоперевірка

  1. Як зрозуміти, що venv увімкнено?
  2. python lab.py нічого не вивів про doctest і перейшов до програми. Це добре чи погано?
  3. Як перевірити лабу так, як просить викладач (doctest, стиль, типи)?
  4. Лаба питає input() одне число. Як прогнати її з числом 7 без клавіатури?
  5. Чому python -m doctest lab.py показує «1 of 21 in main.DebugRunner Failed», хоча код правильний?
Відповіді
  1. Рядок-запрошення починається з (.venv); which python показує шлях з .venv.
  2. Добре: doctest.testmod() мовчить, коли все пройшло. Подробиці - python lab.py -v.
  3. perevir lab.py (doctest через pytest + flake8 до 78 + mypy) або окремо: python -m pytest --doctest-modules -q lab.py, flake8 --max-line-length=78 lab.py, mypy lab.py.
  4. printf "7\n" | python lab.py.
  5. У файлі doctest.testmod() стоїть на верхньому рівні, а -m doctest робить головним модулем сам doctest, тож testmod() перевіряє його власні приклади. Перевіряй python lab.py або pytest.
