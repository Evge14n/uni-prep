Тема 9. День 9: git

Навіщо: «збереження гри» для коду. Зламав лабу - повернувся до робочої версії за секунду.

Коротко (5 хв)

git запамʼятовує знімки (коміти) теки. Кожен коміт - стан усіх файлів у момент + підпис, що змінив.

правиш файли  →  git add  →  git commit  →  історія (git log)
(робоча тека)    (вибрав,      (знімок
                 що зберегти)   з підписом)
Команда Що робить
git init зробити теку репозиторієм (один раз)
git status що змінено, що вибрано для коміту
git add lab4.py вибрати файл у наступний коміт (git add . - усе)
git commit -m "Завдання 1 готове" зробити коміт з підписом
git log --oneline історія комітів
git diff що змінено з останнього коміту (вийти - q)
git restore lab4.py скасувати незбережені в коміт зміни файлу
git show HEAD~1:lab4.py показати файл, яким він був один коміт тому

Перед першим комітом git має знати, хто ти (один раз на комп'ютер):

git config --global user.name "Твоє Імʼя Прізвище"
git config --global user.email "твоя@пошта"

Нове тут:

  • git config - читає і змінює налаштування git (імʼя, пошта, редактор). Назва: config - від configuration, «налаштування». --global - для тебе на цьому ноутбуці: пише у файл ~/.gitconfig, діє в усіх репо.
  • "..." - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

.gitignore - файл зі списком того, що git не чіпає. Для Python:

.venv/
__pycache__/
*.png

Коли комітити: кожне завдання лаби, що проходить doctest, - коміт. Перед великими правками (black, переписування функції) - коміт.

GitHub - сайт, куди можна вивантажити репозиторій (git push). Для лаб не обовʼязково; почни з локального git.

Руками (10 хв)

cd ~/univer/praktyka
mkdir den9 && cd den9
git init
printf 'def double(x: int) -> int:\n    """\n    >>> double(4)\n    8\n    """\n    return x * 2\n' > lab.py
git status                      # lab.py червоний: untracked
git add lab.py
git status                      # зелений: буде в коміті
git commit -m "Функція double"
git log --oneline
printf '.venv/\n__pycache__/\n' > .gitignore
git add .gitignore
git commit -m "gitignore"
sed -i 's/x \* 2/x * 3/' lab.py         # «зламали» код
python3 -m doctest lab.py              # Failed: Expected 8, Got 12
git diff                               # видно, що змінилось
git restore lab.py                     # повернули
python3 -m doctest lab.py              # тиша - знову все добре
git log --oneline

Нове тут:

  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • mkdir - створює нову теку. Назва: make directory - «зробити теку».
  • git init - робить теку репозиторієм git (створює .git). Назва: init - від initialize, «почати, підготувати».
  • printf - друкує текст за шаблоном; \n - Enter. Назва: print formatted - «надрукувати за шаблоном».
  • git status - показує, що змінено і що піде в наступний коміт. Назва: status - «стан».
  • git add - додає зміни файлу в наступний коміт (індекс). Назва: add - «додати» (в індекс, тобто в наступний коміт).
  • git commit - зберігає знімок змін з індексу в історію. Назва: commit - «зафіксувати»: зберегти знімок змін в історію. -m - повідомлення коміту одразу в команді; без -m відкриється nano.
  • git log - показує історію комітів, новий зверху. Назва: log - «журнал»: історія комітів. --oneline - по рядку на коміт: 7 знаків хешу і перший рядок повідомлення.
  • sed - друкує потрібні рядки або замінює текст. Назва: stream editor - «потоковий редактор»: править текст, що тече крізь нього. -i - змінити САМ файл (без -i sed лише показує результат); -i.bak - ще й копія.
  • python3 - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль як програму: python3 -m pytest, python3 -m venv, python3 -m pdb.
  • python3 -m doctest - перевіряє приклади >>> з опису функцій. Назва: doc test - «тест у документації»: приклади >>> в описі функції.
  • git diff - показує, які рядки змінено (+ додано, - прибрано). Назва: diff - від difference, «різниця».
  • git restore - викидає зміни у файлі або забирає його з індексу. Назва: restore - «відновити».
  • ~ - домашня тека /home/evgen. Назва: tilde («тильда») - домашня тека.
  • && - друга команда - лише якщо перша вдалась. Назва: «і»: друга команда - лише якщо перша вдалась.
  • '...' - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».
  • > - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.
  • # - коментар: далі до кінця рядка bash не читає. Назва: hash («решітка») - коментар.

Для ЛР4 (один раз):

cd ~/univer/labs/ЛР4
git init
printf '.venv/\n__pycache__/\n*.png\n' > .gitignore

і після кожного готового завдання git add . і git commit -m "Завдання 1".

Кириличні назви файлів git status може показувати як \320\233\320\240.... Лікується один раз: git config --global core.quotepath false (скрипт установки це вже зробив).

Типові помилки

  • Author identity unknown при коміті - не зроблено git config --global user.name/email.
  • git commit без -m - відкриється редактор (nano або vim). З vim вийти: Esc, потім :q! і Enter.
  • Забув git add - коміт «nothing to commit» або без потрібного файлу. Дивись git status.
  • git init у домашній теці ~ - тоді git бачить усе підряд. Роби в теці конкретної лаби.
  • Додав .venv у git - тисячі файлів. Спершу .gitignore.
  • git restore назавжди скасовує незакомічені зміни файлу. Перед ним глянь git diff.

Самоперевірка

  1. Яка послідовність команд зберігає зміни у git?
  2. Як подивитися, що змінилося з останнього коміту?
  3. Ти зіпсував lab.py і ще не комітив. Як повернути?
  4. Навіщо .gitignore і що в нього писати для Python?
  5. Що означає Author identity unknown?
Відповіді
  1. git add файл (або git add .), потім git commit -m "опис".
  2. git diff (а git status - які файли).
  3. git restore lab.py - файл стане таким, як в останньому коміті.
  4. Щоб git не зберігав зайве: .venv/, __pycache__/, картинки-результати.
  5. git не знає імені та пошти автора. git config --global user.name "Твоє Імʼя Прізвище" і user.email "...".
