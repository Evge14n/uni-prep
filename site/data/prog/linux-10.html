Тема 10. День 10: Свій bash-скрипт

Навіщо: команди, які вводиш щоразу перед здачею лаби, - в один файл і запускати одним словом.

Коротко (5 хв)

Bash-скрипт - текстовий файл з командами, по одній на рядок. Те саме, що вводиш руками.

#!/bin/bash
# перший рядок (shebang): яким інтерпретатором запускати
# усе після # - коментар

name="Студент"                 # змінна: БЕЗ пробілів навколо =
echo "Привіт, $name"         # $name - взяти значення

echo "Перший аргумент: $1"   # $1, $2 - те, що написали після назви скрипта
echo "Усього аргументів: $#"

if [ -f "$1" ]; then         # -f: такий файл існує
    echo "Файл $1 є"
else
    echo "Файлу $1 нема"
fi

for f in *.py; do            # цикл по всіх .py у теці
    echo "Знайшов: $f"
done

Нове тут:

  • # (hash) - коментар: далі до кінця рядка bash не читає.
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • echo - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.
  • $ЗМІННА (dollar) - бере значення змінної (назви, під якою bash тримає текст).
  • [ - перевіряє умову: чи є тека, чи рівні числа тощо. Назва: [ - друга назва команди test («перевірити»); ] лише закриває умову. -f - правда, якщо є такий звичайний файл (file - «файл»); ] - закриває умову, обовʼязково останнім словом і через пробіл.
  • ; (semicolon) - розділяє команди в рядку, виконує всі по черзі.
  • * (asterisk) - будь-які символи в назві; bash сам замінює * на список файлів.

Як читати:

  • Слово з мінусом (як -f тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Короткі можна склеювати: -la = -l і -a.
  • Символи ~ | > & * # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Перевірка в [ ] Що означає
-f файл файл існує
-d тека тека існує
-z "$x" рядок порожній
"$a" = "$b" рядки рівні
$n -gt 5 число більше 5 (-lt менше, -eq дорівнює)

$? - код завершення останньої команди: 0 = успіх, не 0 = помилка. set -e на початку скрипта - зупинитись на першій помилці.

Нове тут:

  • set - вмикає суворий режим: скрипт зупиняється на першій помилці. Назва: set - «встановити» (налаштування самого bash). -e - зупинити скрипт, щойно якась команда впала (errexit - «вийти при помилці»).

Запуск: bash skrypt.sh або chmod +x skrypt.sh і ./skrypt.sh.

Нове тут:

  • bash - програма, що читає й виконує твої команди; bash файл.sh - з файлу. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»).
  • chmod - змінює права файлу: хто може читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. +x - + - додати право, x (execute - «виконувати») - запускати файл як програму; без u/g/o - власнику, групі й іншим.

Alias - коротке імʼя для команди, у ~/.bashrc: alias ll='ls -la'. Після правки source ~/.bashrc. Так зроблені наші univer і perevir (подивись: tail -n 25 ~/.bashrc).

Нове тут:

  • alias - дає коротке імʼя (аліас) довгій команді. Назва: alias - «псевдонім, інше імʼя».
  • '...' (single quotes) - текст буквально: $, * і пробіли всередині - звичайні символи.
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/.bashrc - перечитати свої налаштування після правки, без нового вікна.
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • tail - показує останні рядки (файлу чи того, що прийшло через |). Назва: tail - «хвіст». -n (--lines) - скільки останніх рядків показати: -n 3, коротко -3 (lines - «рядки»).

Руками (10 хв): скрипт «перевір усі лаби в теці»

cd ~/univer/praktyka
nano zdaty.sh

Нове тут:

  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • nano - простий редактор файлів у терміналі. Назва: nano - жарт з одиницями: наступник редактора pico (піко < нано).

Надрукуй:

#!/bin/bash
# zdaty.sh - перевірити всі .py у теці перед здачею
# запуск: ./zdaty.sh ~/univer/labs/ЛР4

folder="${1:-.}"          # якщо теку не дали - поточна
source ~/univer/.venv/bin/activate

if [ ! -d "$folder" ]; then
    echo "Нема теки $folder"
    exit 1
fi

ok=0
bad=0
for f in "$folder"/*.py; do
    if python -m pytest --doctest-modules -q -p no:cacheprovider "$f" < /dev/null > /dev/null 2>&1 && flake8 --max-line-length=78 "$f" > /dev/null; then
        echo "ГОТОВО  $f"
        ok=$((ok + 1))
    else
        echo "ПРАВИТИ $f"
        bad=$((bad + 1))
    fi
done
echo "Готово: $ok, правити: $bad"

Нове тут:

  • $( ) (command substitution) - підставляє вивід команди в рядок.
  • source: ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
  • [: -d - правда, якщо є така тека (directory - «тека»); ! - заперечення: [ ! -d тека ] - правда, якщо теки НЕМА.
  • exit - закінчує скрипт або закриває термінал; число - код виходу (0 - успіх). Назва: exit - «вихід». 1 - «щось не так» - найчастіший код помилки.
  • python3 -m pytest - проганяє тести (приклади >>>) і чесно каже: усе пройшло чи ні. Назва: py + test - «тести для Python». --doctest-modules - шукати doctest (приклади >>>) у файлах .py; без нього pytest шукає лише функції test_; -q (--quiet) - коротко: крапка за кожен тест і рядок підсумку «1 passed in 0.01s» (quiet - «тихо»); -p - увімкнути або вимкнути додаток pytest; -p no:cacheprovider - не створювати теку .pytest_cache (plugin - «додаток»).
  • > (redirect) - пише вивід у файл, старий вміст стирає.
  • flake8 - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. --max-line-length - найбільша довжина рядка; викладач хоче 78.
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).

Далі:

chmod +x zdaty.sh
./zdaty.sh ~/univer/labs/ЛР4      # kvadrat.py з дня 8 - ГОТОВО
./zdaty.sh /nema                   # Нема теки /nema
echo $?                            # 1 - скрипт повідомив про помилку

Нове тут:

  • ./скрипт - запускає програму за шляхом до її файлу, напр. ./файл.sh. Назва: ./ - «звідси».

Хочеш запускати звідусіль словом zdaty: додай у кінець ~/.bashrc рядок alias zdaty='~/univer/praktyka/zdaty.sh' і виконай source ~/.bashrc.

Типові помилки

  • name = "Студент" з пробілами - bash думає, що name це команда: name: command not found.
  • $1 без лапок: шлях з пробілом розвалиться на два аргументи. Пиши "$1", "$f".
  • [ без пробілів: if [-f "$1"] - помилка. Потрібно if [ -f "$1" ].
  • Скрипт, збережений з CRLF (Блокнот Windows) → $'\r': command not found. День 3.
  • Забув chmod +x → Permission denied. Або запускай bash zdaty.sh.
  • Лаба з input() на верхньому рівні вийде «ПРАВИТИ» (pytest не дає їй читати клавіатуру) - таку перевір руками: printf "5\n" | python лаба.py, як у дні 8.

Нове тут:

  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • | (pipe) - вивід лівої команди йде на вхід правої.

Самоперевірка

  1. Навіщо перший рядок #!/bin/bash?
  2. Що не так у рядку count = 5?
  3. Як у скрипті взяти перший аргумент і чому його беруть у лапки?
  4. Що означає $? і яке значення - успіх?
  5. Як зробити, щоб команда zdaty працювала з будь-якої теки?
Відповіді
  1. Каже системі, що файл треба виконувати через bash (коли запускаєш ./скрипт.sh).
  2. Пробіли навколо =. Правильно count=5.
  3. "$1". Лапки - щоб шлях з пробілом лишився одним аргументом.
  4. Код завершення останньої команди; 0 - успіх.
  5. Додати alias zdaty='~/univer/praktyka/zdaty.sh' у ~/.bashrc і виконати source ~/.bashrc (або покласти скрипт у теку з PATH, напр. ~/.local/bin).
