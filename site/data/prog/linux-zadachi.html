Завдання 1. Робоче місце для нової лаби за 5 хвилин

Викладач дав заготовку lab5.py (вона в тебе в «Завантаженнях» Windows). Треба: тека для лаби в Linux, git з .gitignore, заготовка всередині, перевірка doctest і перший коміт «Заготовка».

Розвʼязок 
mkdir -p ~/univer/labs/ЛР5
cd ~/univer/labs/ЛР5
ls /mnt/c/Users                              # дізнатись своє імʼя Windows
cp /mnt/c/Users/IMYA/Downloads/lab5.py .      # IMYA - твоє імʼя Windows (без апострофа!), крапка = сюди
git init
printf '.venv/\n__pycache__/\n*.png\n' > .gitignore
univer                                        # увімкнути venv (перейде в ~/univer)
cd -                                          # назад у ЛР5
python lab5.py                                # заготовка: doctest падають - функції ще порожні, це нормально
git add .
git commit -m "Заготовка"
git log --oneline

Нове тут:

  • mkdir - створює нову теку. Назва: make directory - «зробити теку». -p (--parents) - створює й усі проміжні теки шляху; тека вже є - без помилки (parents - «батьківські»).
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку». - - назад, у теку, де ти був перед цим (cd друкує її шлях).
  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки).
  • # (hash) - коментар: далі до кінця рядка bash не читає.
  • cp - копіює файл або теку. Назва: copy - «копіювати». . - «сюди», у поточну теку: cp ~/Завантаження/lab1.py .
  • git init - робить теку репозиторієм git (створює .git). Назва: init - від initialize, «почати, підготувати».
  • git add - додає зміни файлу в наступний коміт (індекс). Назва: add - «додати» (в індекс, тобто в наступний коміт). . - усе в поточній теці і підтеках; спершу глянь git status, щоб не додати зайве.
  • git commit - зберігає знімок змін з індексу в історію. Назва: commit - «зафіксувати». -m (--message) - повідомлення коміту одразу в команді; без -m відкриється nano (message - «повідомлення»).
  • git log - показує історію комітів, новий зверху. --oneline - по рядку на коміт: 7 знаків хешу і перший рядок повідомлення.
  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • '...' (single quotes) - текст буквально: $, * і пробіли всередині - звичайні символи.
  • > (redirect) - пише вивід у файл, старий вміст стирає.
  • univer - переходить у ~/univer і вмикає venv.
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.

Як читати:

  • Слово з мінусом (як -p тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Короткі можна склеювати: -rl = -r і -l.
  • Символи ~ | > & * # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Чому так: заготовку комітимо до правок, щоб завжди можна було побачити git diff, що саме ти змінив, і повернутись до оригіналу (вимога викладача - не міняти назви, параметри і doctest заготовки).

Нове тут:

  • git diff - показує, які рядки змінено (+ додано, - прибрано).

Завдання 2. Огляд усіх лаб однією-двома командами

У теці з лабами (~/univer/labs або ~/univer/prog/Лабораторні) дізнайся: а) які файли використовують doctest; б) скільки функцій у кожному .py; в) скільки рядків довші за 78 символів (викладач за це чіпляється) у кожному файлі.

Розвʼязок 
cd ~/univer/labs
grep -rl "import doctest" --include="*.py" .          # а) лише імена файлів
grep -c "^def " *.py                                   # б) файл:кількість (функції верхнього рівня)
univer; cd -
flake8 --select=E501 --max-line-length=78 *.py | cut -d: -f1 | sort | uniq -c   # в)

Нове тут:

  • grep - шукає рядки з текстом (у файлах або те, що прийшло через |). Назва: g/re/p з редактора ed: global regular expression print - «скрізь знайти шаблон, надрукувати». -r (--recursive) - шукати в усіх файлах теки і підтек (recursive - «рекурсивно», углиб); -l (--files-with-matches) - лише назви файлів, де є збіг (list - «список»); --include - з -r: шукати лише у файлах за шаблоном, --include="*.py" (include - «включити»); . - з -r: шукати в поточній теці і всіх підтеках; -c (--count) - не показувати рядки, а лише порахувати, скільки їх зі збігом (count - «порахувати»); ^ на початку шаблону - «рядок починається з цього тексту».
  • * (asterisk) - будь-які символи в назві; bash сам замінює * на список файлів.
  • ; (semicolon) - розділяє команди в рядку, виконує всі по черзі.
  • flake8 - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. --select - перевіряти лише ці коди, напр. --select E501 - лише задовгі рядки (select - «вибрати»); --max-line-length - найбільша довжина рядка; викладач хоче 78.
  • | (pipe) - вивід лівої команди йде на вхід правої.
  • cut - вирізає з рядків потрібні стовпці. Назва: cut - «вирізати». -f (--fields) - які поля взяти: -f1 або -f1,6,7 або -f2-4 (fields - «поля»).
  • sort - впорядковує рядки. Назва: sort - «сортувати, впорядкувати».
  • uniq - склеює однакові сусідні рядки (з -c - рахує). Назва: unique - «єдиний, неповторний»: прибрати повтори. -c (--count) - писати перед рядком, скільки разів він ішов підряд (count - «рахувати»).

Пояснення в): flake8 друкує файл:рядок:колонка: E501 line too long, cut -d: -f1 лишає імʼя файлу, sort | uniq -c рахує, скільки разів кожне імʼя. Якщо файл не надрукувався - довгих рядків нема. Напр. на твоєму ПК у ЛР2_завдання3_body_moving.py один такий рядок (19, 192 символи) - це рядок doctest з довгим очікуваним результатом. Doctest викладача не міняй; якщо треба, спитай, чи це рахується.

Завдання 3. Скрипт «зібрати лабу на здачу»

Викладач просить папку з назвою «прізвище, ім'я, група, рік». Напиши zibraty.sh: бере теку лаби, перевіряє кожен .py (doctest + flake8 78), і якщо всі готові - копіює їх у теку Прізвище_Імʼя_Група_2026 і робить zip-архів, усередині якого саме ця тека з файлами. Якщо хоч один не готовий - нічого не збирає і пише, який саме.

Розвʼязок 
#!/bin/bash
# zibraty.sh - зібрати лабу на здачу
# запуск: ./zibraty.sh ~/univer/labs/ЛР4

lab="$1"
if [ ! -d "$lab" ]; then
    echo "Дай теку лаби: ./zibraty.sh ~/univer/labs/ЛР4"
    exit 1
fi
source ~/univer/.venv/bin/activate

bad=0
for f in "$lab"/*.py; do
    if ! python -m pytest --doctest-modules -q -p no:cacheprovider "$f" < /dev/null > /dev/null 2>&1; then
        echo "doctest не проходить: $f"
        bad=1
    fi
    if ! flake8 --max-line-length=78 "$f" > /dev/null; then
        echo "flake8 має зауваження: $f"
        bad=1
    fi
done
if [ "$bad" = 1 ]; then
    echo "Не збираю - спершу виправ."
    exit 1
fi

name=$(basename "$lab")                       # ЛР4
out="$HOME/univer/zdacha/$name/Прізвище_Імʼя_Група_2026"
mkdir -p "$out"
cp "$lab"/*.py "$out"/
cd "$HOME/univer/zdacha/$name"
python -m zipfile -c "${name}.zip" "Прізвище_Імʼя_Група_2026"
echo "Готово: $HOME/univer/zdacha/$name/${name}.zip"

Нове тут:

  • $ЗМІННА (dollar) - бере значення змінної (назви, під якою bash тримає текст).
  • $( ) (command substitution) - підставляє вивід команди в рядок.
  • [ - перевіряє умову: чи є тека, чи рівні числа тощо. Назва: [ - друга назва команди test («перевірити»); ] лише закриває умову. -d - правда, якщо є така тека (directory - «тека»); ! - заперечення: [ ! -d тека ] - правда, якщо теки НЕМА; ] - закриває умову, обовʼязково останнім словом і через пробіл; = - рядки однакові: [ "$a" = "$b" ]; != - різні.
  • echo - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.
  • exit - закінчує скрипт або закриває термінал; число - код виходу (0 - успіх). Назва: exit - «вихід». 1 - «щось не так» - найчастіший код помилки.
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
  • < (input redirect) - подає файл програмі замість клавіатури.
  • 2>&1 («потік 2 туди ж, куди потік 1»: помилки разом зі звичайним виводом) - помилки йдуть разом зі звичайним виводом.
  • basename - дає назву файлу без шляху. Назва: base name - «основна назва».
  • python3 -m zipfile - робить і розпаковує .zip засобами Python. Назва: zipfile - вбудований у Python інструмент для .zip; -m - запустити його як програму. -c (--create) - створити архів з файлів і тек, теки - з усім вмістом (create - «створити»).
  • python3: -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).

Запуск: chmod +x zibraty.sh, потім ./zibraty.sh ~/univer/labs/ЛР4. Архів відкрити в Провіднику: cd ~/univer/zdacha/ЛР4 && explorer.exe . (саме так, з cd: Linux-шлях аргументом Провідник не розуміє).

Нове тут:

  • chmod - змінює права файлу: хто може читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. +x - + - додати право, x (execute - «виконувати») - запускати файл як програму; без u/g/o - власнику, групі й іншим.
  • && (AND) - друга команда - лише якщо перша вдалась.
  • explorer.exe - відкриває теку в Провіднику Windows (лише у WSL). Назва: explorer - «оглядач». . - крапка = поточна тека.

Що тут нового: basename бере останню частину шляху; $HOME - те саме, що ~, але працює в лапках; python -m zipfile -c робить zip без встановлення програми zip, але кладе в архів лише ОСТАННЮ теку шляху. Тому скрипт заходить (cd) туди, де лежить Прізвище_Імʼя_Група_2026, і пакує саме її - так назва теки в архіві збережеться (перша версія цього розвʼязку губила її, знайшла перевірка). Doctest тут через pytest (python -m pytest --doctest-modules), а не python -m doctest - день 8, «пастка». Увага: лабу з input() на верхньому рівні pytest не перевірить (не дає читати клавіатуру) - вона піде в «doctest не проходить»; таку перевір руками з вводом, як у дні 8.
