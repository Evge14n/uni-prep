Коротко

Уся лаба - це повторення одного кола:

nano lr1_1.py  →  зберегти (Ctrl+O, Enter)  →  вийти (Ctrl+X)  →  запустити  →  читати Expected / Got  →  знову nano
Що робиш Команда
тека для лаби mkdir -p ~/univer/labs/lr1 і cd ~/univer/labs/lr1
увімкнути venv source ~/univer/.venv/bin/activate (зліва зʼявиться (.venv))
файли викладача з Telegram зазвичай ~/Завантаження/Telegram Desktop/: ls ~/Завантаження/"Telegram Desktop"
дістати заготовку з .ipynb klitynka файл.ipynb 4 > lr1_1.py (функцію klitynka зробимо нижче)
редагувати nano lr1_1.py
запустити з введенням printf "127\n" | python3 lr1_1.py
усі doctest докладно printf "127\n" | python3 lr1_1.py -v | tail -n 3
doctest з чесним кодом виходу printf "127\n" | python3 -m pytest --doctest-modules -q -s lr1_1.py
стиль і типи python3 -m black -l 78, flake8, pycodestyle, ruff check, mypy

Нове тут:

  • mkdir - створює нову теку. Назва: make directory - «зробити теку». -p (--parents) - створює й усі проміжні теки шляху; тека вже є - без помилки (parents - «батьківські»).
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки).
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • klitynka - друкує одну клітинку з .ipynb за номером.
  • > (redirect) - пише вивід у файл, старий вміст стирає.
  • nano - простий редактор файлів у терміналі. Назва: nano - жарт з одиницями: наступник редактора pico (піко < нано).
  • printf - друкує текст; \n у ньому - Enter (новий рядок). Назва: print formatted - «надрукувати за шаблоном».
  • | (pipe) - вивід лівої команди йде на вхід правої.
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).
  • tail - показує останні рядки (файлу чи того, що прийшло через |). Назва: tail - «хвіст». -n (--lines) - скільки останніх рядків показати: -n 3, коротко -3 (lines - «рядки»).
  • python3 -m pytest - проганяє тести (приклади >>>) і чесно каже: усе пройшло чи ні. Назва: py + test - «тести для Python». --doctest-modules - шукати doctest (приклади >>>) у файлах .py; без нього pytest шукає лише функції test_; -q (--quiet) - коротко: крапка за кожен тест і рядок підсумку «1 passed in 0.01s» (quiet - «тихо»); -s - не перехоплювати ввід і вивід: потрібен, коли файл питає input().
  • python3 -m black - сам гарно оформлює код Python (пробіли, переноси). Назва: black - «чорний»: як у Форда, «будь-який колір, якщо він чорний». -l (--line-length) - найбільша довжина рядка; викладач хоче 78, сам black ставить 88 (line length - «довжина рядка»).
  • flake8 - шукає помилки стилю і зайвий код (працює, коли увімкнено venv). Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду.

Як читати:

  • Слово з мінусом (як -p тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Символи ~ | > * набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Три правила лаби, які викладач перевіряє насамперед (ЛР1, с. 12 методички; файл «Вимоги викладача»):

  • без if, elif, else і без циклів for, while у всіх трьох завданнях (с. 12: «Заборонено оператори галуження ... та цикли»); у завданні 3 ще й без списків і словників;
  • назву, параметри функції і doctest не міняти - свій код вкладаєш у готову функцію;
  • функція повертає рядок через return, а не друкує його через print; doctest мають пройти всі.

Умова коротко

Оригінал: Лабораторна_робота_1_Пайтон,_2026_2027.pdf (далі «с.» - сторінка цього PDF) або той самий .ipynb (далі «клітинка» - номер клітинки, рахуємо з 0). Теорія - с. 1-12, у ній є майже всі потрібні прийоми.

Завдання 1. Цифри тризначного числа (с. 13-15, умова - клітинка 3, заготовка - клітинка 4). Користувач вводить число. Функція number_operations(number) рахує суму цифр, модуль різниці між числом і числом, записаним навпаки, і частку «число / сума цифр» з трьома знаками після крапки (44.000, а не 44.0). Для недодатного числа повертає Number must be positive, для не тризначного - Number of digits must be 3. Повертає один рядок з \n усередині.

Завдання 2. Тривалість космічної місії (с. 15-17, клітинки 5 і 6). Користувач вводить кількість секунд. Функція time_operations(seconds) розкладає їх на дні, години, хвилини, секунди (лише // і %, доба = 86400 с) і дає ще запис D days, HH:MM:SS з двома цифрами в годинах, хвилинах, секундах. Для відʼємного числа - Number of seconds must be non-negative.

Завдання 3. Оплата банкнотами (с. 17-22, клітинки 7 і 8). Вводять ціну і скільки є банкнот 500, 100, 50, 20, 10, 5, 1. Функція calculate_payment(...) бере від найбільшого номіналу стільки банкнот, скільки влазить у залишок, але не більше, ніж є. Виводить, скільки взято кожних, і Remaining amount: ... UAH. Окремо перевіряти «чи можна оплатити» не треба. Заборонено if, for, while, списки; дозволено min(), //, %.

Крок 3. Дістати заготовки з .ipynb

.ipynb - це JSON (текстовий формат запису даних: списки [...] і пари «назва: значення» у {...}; Python читає його модулем json): текст і код лежать у «клітинках». Дві короткі функції bash: klityny показує список клітинок, klitynka друкує одну клітинку. Скопіюй обидва рядки в термінал (вставка - Ctrl+Shift+V):

klityny() { python3 -c 'import json, sys; [print(i, c["cell_type"], "".join(c["source"])[:45].split("\n")[0]) for i, c in enumerate(json.load(open(sys.argv[1]))["cells"])]' "$1"; }
klitynka() { python3 -c 'import json, sys; print("".join(json.load(open(sys.argv[1]))["cells"][int(sys.argv[2])]["source"]))' "$1" "$2"; }

Нове тут:

  • ; (semicolon) - розділяє команди в рядку, виконує всі по черзі.

Подивись, які клітинки є:

klityny Лабораторна_робота_1_Пайтон,_2026_2027.ipynb

0 markdown # Лабораторна робота 1
1 markdown ## Теоретична частина
2 markdown ## Практична частина
3 markdown ### **Завдання 1. Операції з цифрами тризначн
4 code import doctest
5 markdown ### **Завдання 2. Визначення тривалості космі
6 code import doctest
7 markdown ### **Завдання 3. Формування суми покупки дос
8 code import doctest

Нове тут:

  • klityny - показує список клітинок .ipynb з номерами.

Клітинки code 4, 6, 8 - це заготовки трьох завдань. Знак > пише вивід команди у файл:

klitynka Лабораторна_робота_1_Пайтон,_2026_2027.ipynb 4 > lr1_1.py
klitynka Лабораторна_робота_1_Пайтон,_2026_2027.ipynb 6 > lr1_2.py
klitynka Лабораторна_робота_1_Пайтон,_2026_2027.ipynb 8 > lr1_3.py
ls

Функції живуть, поки відкрите вікно термінала. Щоб були завжди (знадобляться в ЛР2), допиши їх у ~/.bashrc:

declare -f klityny klitynka >> ~/.bashrc

Нове тут:

  • declare - з -f друкує код твоїх функцій (саморобних команд). Назва: declare - «оголосити» (змінну чи функцію bash). -f - надрукувати повний код функцій з цими назвами (function - «функція»).

Чому не файл lab1_doctests.py з чату? У ньому завдання 1 зламане: рядок з return не компілюється, а два doctest розірвані на два рядки (розбір - у розділі «Коли помиляється doctest викладача»). Завдання 2 і 3 там такі самі, як у .ipynb, але простіше брати все з одного місця.

Крок 4. Відкрий файл у nano і подивись на будову

nano lr1_1.py
Клавіші nano Що роблять

Будова файлу, яку чекає викладач (заготовка вже так зроблена, ти дописуєш лише позначене):

import doctest                                   ← як у заготовці


def number_operations(number: int) -> str:      ← назву і параметри НЕ міняти
    """
    опис і doctest викладача                     ← НЕ міняти жодного символу
    """
    твій код: обчислення                         ← пишеш ти
    return результат                             ← один рядок-результат


number = int(input("Enter number: "))           ← введення: пишеш ти (int, бо input дає str)

print(number_operations(number))                ← виклик із заготовки, обгорнутий у print

doctest.testmod()                                ← як у заготовці

Дві речі в заготовці треба знати:

  • у завданнях 1 і 2 викладач викликає функцію без print - результат тоді нікуди не виводиться. Умова каже «вивести», тому обгорни виклик у print(...), як у заготовці завдання 3;
  • doctest.testmod() стоїть унизу файлу, без if __name__ == "__main__":. У ЛР1 так і залиш: if заборонений, а викладач дав саме таку заготовку.

Відступ усередині функції - 4 пробіли (з Кроку 0 Tab сам ставить 4 пробіли).

Крок 5. Перший запуск - побач, що все червоне, і це нормально

Збережи і вийди (Ctrl+O, Enter, Ctrl+X). Запусти заготовку, поки ти ще нічого не дописав:

python3 lr1_1.py

NameError: name 'number' is not defined

Python дійшов до рядка number_operations(number), а змінної number ще нема - бо ще нема введення. Допиши рядок з input і print(...) навколо виклику (як у схемі вище). Функцію поки не чіпай. Запусти знову. Програма чекає числа - набери 127 і Enter. Або подай число одразу, без набору, через printf:

printf "127\n" | python3 lr1_1.py

Enter number: None
**********************************************************************
File "/home/evgen/univer/labs/lr1/lr1_1.py", line 13, in __main__.number_operations
Failed example:
    number_operations(124)
Expected:
    'The sum of digits of the number 124 is 7;\nthe absolute value of the difference of the number and reversed number is 297;\nthe fraction of the number 124 and the sum of its digits is 17.714.'
Got nothing

і в кінці:

1 items had failures:
   5 of   5 in __main__.number_operations
***Test Failed*** 5 failures.

Як це читати:

  • Enter number: - підказка з твого input. Число прийшло з printf, тому на екрані його нема, і текст програми йде в тому самому рядку - так і має бути;
  • None - функція ще нічого не повертає (return нема), а print надрукував це «нічого»;
  • File "/home/evgen/..." - повний шлях до файлу; у тебе замість evgen буде твій логін;
  • Failed example - який виклик з doctest не пройшов, line 13 - де він у файлі;
  • Expected - що мало бути, Got - що вийшло насправді (Got nothing = функція повернула None);
  • 5 of 5 - не пройшли всі 5 прикладів. Твоя мета - щоб цей звіт зник.

Це і є «спершу тест, потім код» (про це говорив викладач): doctest уже написані, ти дописуєш функцію, доки вони не позеленіють.

Крок 6. Пиши малими кроками

Не пиши всю функцію відразу. Один-два рядки → Ctrl+O, Ctrl+X → запуск → дивишся Got. Наприклад, спершу лише сума цифр і return f"... {сума} ...", потім різниця, потім частка. Щоб швидко глянути проміжне значення, можна тимчасово вставити print(...) у функцію і потім прибрати (докладно - Урок 05).

Коли doctest пройшли всі, програма після свого виводу нічого більше не пише - це і є «усе добре». Для 127 (приклад з с. 14) має бути рівно так:

Enter number: The sum of digits of the number 127 is 10;
the absolute value of the difference of the number and reversed number is 594;
the fraction of the number 127 and the sum of its digits is 12.700.

Переконайся докладно:

printf "127\n" | python3 lr1_1.py -v | tail -n 3

5 tests in 2 items.
5 passed and 0 failed.
Test passed.

-v показує кожен приклад (Trying ... Expecting ... ok), tail -n 3 залишає три останні рядки.

True поводиться як 1, False як 0. Рядок × 1 = той самий рядок, рядок × 0 = порожній рядок. Це прийом з с. 7-8 замість if.

Doctest показує результат функції так, як його показує інтерактивний Python - через repr: у лапках і з \n. print друкує той самий рядок «по-людськи». Тому твоя функція повертає рядок з \n, а doctest порівнює його repr.

Як роблять профі

  • Захист if __name__ == "__main__":. У звичайних проєктах введення і doctest.testmod() ховають під цю перевірку - тоді файл можна імпортувати (pytest, інші модулі) без запитання input(). Викладач сам показує це на с. 10 (приклад з %%writefile). Але в ЛР1 if заборонений, тому лишай заготовку як є; у наступних лабах можна спитати викладача. https://docs.python.org/3/library/main.html
  • pytest як «суддя». pytest --doctest-modules збирає doctest з усіх файлів і дає код виходу, який розуміють скрипти й GitHub Actions. https://docs.pytest.org/en/stable/how-to/doctest.html
  • ruff замість купи інструментів. ruff check замінює flake8 і частину pylint, а ruff format задуманий як «drop-in replacement for Black» (так пише документація ruff). Викладач поки хоче всі пʼять інструментів - жени всі. https://docs.astral.sh/ruff/formatter/
  • Типи + mypy. Анотації (number: int, -> str) і mypy ловлять половину дурних помилок до запуску (п. 4 «Типових помилок»). https://mypy.readthedocs.io/en/stable/
  • Маленькі коміти. Одне завдання = один коміт з людським повідомленням. Урок 24 - як вивантажити на GitHub.

Самоперевірка

  1. Чому python3 lr1_1.py не годиться як єдина перевірка перед здачею, і яка команда дає чесний код виходу?
  2. Що означають Expected, Got і Got nothing у звіті doctest?
  3. Чому python -m doctest lr1_1.py показує провал у __main__.DebugRunner, хоча код правильний?
  4. Як без if повернути Number must be positive лише для недодатного числа?
  5. Як переконатися, що doctest у завданні 3 помилковий, а не твій код?
Відповіді
  1. Він мовчить, коли все добре, але й код виходу 0 повертає навіть при провалених doctest - провал легко пропустити. Чесний код виходу дає printf "127\n" | python3 -m pytest --doctest-modules -q -s lr1_1.py (0 - пройшли, 1 - є провали); докладний звіт - python3 lr1_1.py -v.
  2. Expected - що написав викладач у doctest, Got - що реально повернула твоя функція. Got nothing - функція повернула None (нема return). Якщо Expected у лапках, а Got без лапок - ти друкуєш замість повертати.
  3. При python -m doctest головним модулем стає сам doctest, і рядок doctest.testmod() у твоєму файлі тестує його власні приклади, один з яких падає в DebugRunner. Це не твій код.
  4. Помножити рядок на умову: True = 1, False = 0, тож рядок зʼявляється лише тоді, коли умова істинна (с. 7-8 методички). Решту частин результату так само множать на свої умови і додають.
  5. Перерахувати Expected руками: скласти номінали × кількість. У прикладі 2 виходить 1295 грн при ціні 1245, у прикладі 3 - 132 грн при «залишку 0» замість 5. Очікуване суперечить умові - отже, помилка в doctest; написати викладачу.
