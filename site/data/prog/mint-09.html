Урок 09. ЛР4 у терміналі (turtle)

← Усі уроки

Навіщо: у ЛР4 програма малює у вікні. Треба знати, як це вікно відкрити з термінала, як його закрити, що робити, коли воно не зʼявляється, і як перевіряти математику doctest-ом без вікна взагалі.

Коротко

turtle («черепашка») - модуль Python для малювання: уявна черепашка повзе по вікну і лишає слід. Вікно малює бібліотека Tk (через модуль tkinter). На свіжій Mint 22.3 пакета python3-tk нема, його треба поставити один раз. Скрипт ustanovka-mint.sh (урок 03) це вже робить.

Що Команда / рядок коду
поставити Tk для turtle (один раз) sudo apt install python3-tk
перевірити, що Tk є python3 -c "import tkinter; print(tkinter.TkVersion)" → 8.6
запустити малюнок python3 lr4_1_1.py - відкриється вікно
тримати вікно відкритим останній рядок програми turtle.done()
закрити вікно кліком у ньому замість done() - screen.exitonclick()
зупинити програму закрити вікно хрестиком ✕; поки ще малює - Ctrl+C у терміналі (не завжди); останній засіб - Ctrl+\
перевірити математику без вікна python3 -m doctest -v lr4_1_1.py (бо testmod() у тебе під if __name__, крок 3)

Нове тут:

  • sudo - виконує одну команду як адміністратор; спитає твій пароль (видно зірочки). Назва: superuser do - «зроби як суперкористувач» (адміністратор).
  • apt install - ставить програму з інтернету; на «Бажаєте продовжити? [Y/n]» - Enter. Назва: apt - Advanced Package Tool - «розширений інструмент для пакетів (програм)».
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -c - виконати один рядок коду без файлу: python3 -c 'print(2 ** 10)' (command - «команда»); -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • python3 -m doctest - перевіряє приклади >>> з опису функцій. Назва: doc test - «тест у документації». -v (--verbose) - докладно: кожен приклад (Trying, Expecting, ok) і підсумок «N passed and M failed» (verbose - «багатослівно»).

Як читати:

  • Слово з мінусом (як -c тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Символи ~ | * набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Головне про вікно:

python3 lr4_1_1.py
   │
   ├─ рядки малювання виконуються, вікно відкрите
   │
   ├─ turtle.done()  ← тут програма ЧЕКАЄ: вікно живе, термінал зайнятий
   │                    (turtle.done - це те саме, що turtle.mainloop)
   │
   └─ закрив вікно хрестиком → done() закінчився → програма йде далі → кінець

Якщо turtle.done() нема, вікно закривається відразу після останньої команди (так і написано в ЛР4, с. 1). Поки вікно відкрите, термінал не приймає нових команд. Це нормально: закрий вікно хрестиком ✕. Ctrl+C у терміналі тут не допоможе: у turtle.done() програмою керує Tk (цикл подій вікна), і Python не обробляє Ctrl+C, поки Tk чекає. Якщо вікно зависло і не закривається - Ctrl+\ у терміналі (крок 4).

Готових doctest-ів до ЛР4 викладач не дав: є лише PDF. Малюнок doctest-ом не перевіриш, а математику (кути, радіуси, моделювання зіткнень) - можна. Для цього є turtle.TNavigator() - «черепашка без вікна»: уміє forward, left, goto і рахує позицію, але нічого не малює. Тому doctest з нею працює будь-де, навіть без графіки.

Передбач, потім запусти

Спершу відповідай подумки, нічого не запускаючи, і лише тоді розкрий «Відповідь». Файли з цих прикладів зʼявляться в розділі «Крок за кроком у терміналі» нижче - запусти й перевір себе, коли його пройдеш.

1. Шестикутник «без вікна». Що надрукує останній рядок?

import turtle

nav = turtle.TNavigator()
for _ in range(6):
    nav.forward(50)
    nav.left(60)
print(nav.position())
print(round(nav.xcor(), 6), round(nav.ycor(), 6))
Відповідь 
(-0.00,0.00)
-0.0 0.0

Черепашка повернулась у старт, але float має похибку: x вийшов -3.9e-14, крихітне відʼємне число. Після round лишається відʼємний нуль -0.0. Для Python -0.0 == 0.0 - це True, але doctest порівнює текст, і -0.0 ≠ 0.0. Тому в doctest краще писати перевірку так: nav.distance(0, 0) < 1e-9 → True.

2. Кольори по колу (з ЛР4, с. 4). Що надрукує?

colors = ["gold", "crimson", "lime", "cyan"]
for step in range(6):
    print(step, colors[step % len(colors)])
Відповідь 
0 gold
1 crimson
2 lime
3 cyan
4 gold
5 crimson

step % 4 дає 0, 1, 2, 3, 0, 1, ... - індекс «ходить по колу». len(colors) замість числа 4 - щоб код не зламався, коли додаси пʼятий колір.

3. Ти назвав свій файл turtle.py (бо «це ж лаба з turtle») і запустив python3 turtle.py. У файлі:

import turtle

turtle.forward(100)
turtle.done()
Відповідь 
AttributeError: partially initialized module 'turtle' has no attribute 'forward' (most likely due to a circular import)

import turtle шукає модуль спершу в теці скрипта і знаходить твій turtle.py, а не справжній. Твій файл імпортує сам себе, і forward у ньому нема. Ліки: перейменуй файл (lr4_1_1.py). Те саме буде з math.py, random.py тощо.

4. Ти зайшов на ноутбук по ssh (урок 21) або в текстову консоль Ctrl+Alt+F2 і запустив малюнок. Що буде?

Відповідь

Вікна відкрити нікуди, останній рядок помилки:

_tkinter.TclError: no display name and no $DISPLAY environment variable

DISPLAY - змінна, яка каже програмі, на який екран малювати. У графічному терміналі Cinnamon вона є, у ssh і в TTY - нема. Turtle запускай у звичайному терміналі на робочому столі (Ctrl+Alt+T). Doctest з TNavigator працює і там, і там.

Крок за кроком у терміналі

Крок 1. Tk і тека лаби. Відкрий термінал (Ctrl+Alt+T):

sudo apt install python3-tk
python3 -c "import tkinter; print(tkinter.TkVersion)"
mkdir -p ~/univer/labs/lr4
cd ~/univer/labs/lr4
source ~/univer/.venv/bin/activate

Нове тут:

  • mkdir - створює нову теку. Назва: make directory - «зробити теку». -p (--parents) - створює й усі проміжні теки шляху; тека вже є - без помилки (parents - «батьківські»).
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.

Друга команда має надрукувати 8.6. Якщо ставив усе скриптом з уроку 03 - першу можна пропустити, а останню (source ...) замінює слово univer. Але univer лише переходить у ~/univer і вмикає venv - теку лаби він не робить, тож після нього: mkdir -p labs/lr4 і cd labs/lr4.

Крок 2. PDF умови поруч. Файли з чату лежать у теці завантажень. На українській Mint вона зветься ~/Завантаження, на англійській - ~/Downloads (точну назву друкує xdg-user-dir DOWNLOAD). Нове тут:

  • xdg-user-dir - друкує шлях до теки завантажень, зображень тощо. Назва: XDG user directory - «тека користувача» за правилами freedesktop.org. DOWNLOAD - тека завантажень (туди кладуть файли браузер і Telegram).

Крок 3. Один файл на завдання. Назви: lr4_1_1.py, lr4_1_2.py, ..., lr4_2_clock.py, lr4_3_balls.py (ніколи не turtle.py). Відкрий редактор:

nano lr4_1_1.py

Нове тут:

  • nano - простий редактор файлів у терміналі. Назва: nano - жарт з одиницями: наступник редактора pico (піко < нано).

Структура файлу (заглушки ... - місця для твого коду):

# ЛР4, завдання 1.1
import doctest
import math
import turtle


def ...(...) -> ...:          ← функції з умови (назви й параметри - як у PDF)
    """Що робить, одним реченням.

    >>> приклад виклику           ← doctest лише для того, що ПОВЕРТАЄ число
    очікуваний результат
    """
    ...


if __name__ == "__main__":       ← усе, що малює, - тільки тут
    doctest.testmod()
    screen = turtle.Screen()
    screen.setup(600, 600)
    ... малювання ...
    turtle.done()                ← останній рядок

Чому малювання під if __name__ == "__main__":. Команда python3 -m doctest файл.py імпортує файл. Усе, що стоїть на верхньому рівні, виконається: на ноутбуці вискочить вікно, а без екрана буде TclError. Під if малювання запускається лише від python3 lr4_1_1.py, а тести - тихо, без вікна.

Тому в твоїх файлах ЛР4 команда python3 -m doctest -v чесна. На файлах викладача, де doctest.testmod() стоїть просто внизу файлу (ЛР1, ЛР5), вона дає чужий провал DebugRunner - там перевіряй python3 файл.py -v або perevir (урок 04, «Типові помилки» п. 10).

Збереження в nano: Ctrl+O, Enter; вихід: Ctrl+X (урок 03).

Крок 4. Запуск і вікно.

python3 lr4_1_1.py
  • Зʼявилось вікно, малюнок готовий - роздивись і закрий хрестиком ✕. Термінал знову приймає команди.
  • Хочеш закривати кліком по вікну - заміни turtle.done() на screen.exitonclick() (screen = turtle.Screen()).
  • Малює дуже довго (наприклад, нескінченний цикл малювання) - закрий вікно ✕ або клацни в термінал і натисни Ctrl+C. Поки йде малювання, Ctrl+C може спрацювати (останній рядок буде KeyboardInterrupt - це не помилка в коді, це ти зупинив програму), а може й ні. Коли програма вже дійшла до turtle.done() - точно ні: там чекає Tk, і Ctrl+C він не бачить. Закривай вікно.
  • Вікно зависло і не закривається - останній засіб: у терміналі Ctrl+\ (сигнал SIGQUIT - «негайно вийди»). Програма вмирає одразу, без traceback, термінал пише (перевірено в тестовій Mint на звичайній програмі, що чекала):
Quit (core dumped)

На українській Mint - Вихід (збережено знімок оперативної пам’яті). «Знімок памʼяті» - службовий файл для розбору падіння, тобі він не потрібен. Код виходу - 131 (echo $?). - Закрив вікно хрестиком посеред малювання - буде помилка turtle.Terminator (вікна вже нема, а черепашка ще малює). Теж не баг: просто дочекайся кінця. Текст цієї помилки тут не відтворено (потрібен екран), опис - у Довідник функцій, розділ turtle → turtle.Terminator.

Нове тут:

  • echo - друкує на екран текст, який йому дали. Назва: echo - «луна»: повторює те, що йому дали.

Крок 5. Математика - doctest без вікна. Не пиши doctest, який створює turtle.Turtle() чи turtle.Screen(): він відкриє вікно. Винось обчислення у функцію, що повертає число, а рух перевіряй через TNavigator. Приклад на іншій задачі (не з ЛР4): скільки сторін має правильний многокутник, якщо на кожній вершині черепашка повертає на turn градусів. Файл bagatokutnyk.py:

def side_count(turn: float) -> int:
    """Скільки сторін має правильний многокутник із поворотом turn.

    >>> side_count(72)
    5
    >>> import turtle
    >>> nav = turtle.TNavigator()
    >>> for _ in range(side_count(72)):
    ...     nav.forward(100)
    ...     nav.left(72)
    >>> nav.distance(0, 0) < 1e-9
    True
    """
    return round(360 / turn)

python3 -m doctest -v bagatokutnyk.py | tail -n 3

5 tests in 2 items.
5 passed and 0 failed.
Test passed.

Нове тут:

  • | (pipe) - вивід лівої команди йде на вхід правої.
  • tail - показує останні рядки (файлу чи того, що прийшло через |). Назва: tail - «хвіст». -n (--lines) - скільки останніх рядків показати: -n 3, коротко -3 (lines - «рядки»).

import turtle стоїть усередині doctest, бо поза тестами модуль у цьому файлі не потрібен. Якби він був угорі файлу, flake8 сказав би F401 'turtle' imported but unused (імпортовано, але не використано). У самій лабі turtle малює, тож там імпорт угорі - на місці.

Ідея: «обійшов фігуру - повернувся в старт» перевіряється без жодного вікна. Так само можна перевірити кут своєї зірки з 1.1 (після n відрізків черепашка має бути в старті) або координати точок троянди з 1.8.

Крок 6. Підказки по завданнях (без розвʼязків - розвʼязок твій).

  • 1.1 зірка. Кут - готова формула з умови. math.gcd(n, k) дає найбільший спільний дільник (ДОВІДНИК-ФУНКЦІЙ: math.gcd()). Попередження - звичайний print. Фарба: begin_fill() до циклу, end_fill() після.
  • 1.2-1.10. Майже скрізь одна схема: for на N повторів, у тілі - одна фігура і поворот. Колір по колу - як у «Передбач» №2. Зміна товщини чи кольору «першим 12 - одне, наступним 12 - інше» - це умова на номер ітерації (if/elif або цілочисельне ділення //). Потрібне: circle(r), circle(r, steps=6), pensize, pencolor, setheading, goto, penup/pendown (ДОВІДНИК, розділ turtle).

Пастка в умові завдання 3 (с. 12). Там написано: кінець, коли мала кулька ліворуч від великої (x_m < x_M), летить вправо (v_m > 0) і не швидше за велику (v_m ≤ v_M). Якщо закодувати це дослівно, цикл не зупиниться:

  • після останнього зіткнення кульок вони стоять в одній точці, x_m == x_M (у перевірочній програмі курсу для m = 1, M = 4, L = 10, v = 1 обидві координати однакові: 50.000000000000014), тому x_m < x_M хибне;
  • при m = M після зіткнення мала кулька зупиняється: v_m = 0.0, і v_m > 0 теж хибне.

Подій більше нема, а умова кінця не спрацювала - програма висить або «зіштовхує» кульки знову в тій самій точці. Подумай, яка умова кінця правильна саме для швидкостей (без координат), і перевір її на m = M. Про це варто сказати викладачу.

Як роблять профі

  • Модель окремо від показу. Фізику (зіткнення) пишуть як чисту функцію «вхід → числа», покривають тестами, а анімацію роблять тонким шаром зверху. Так тестують і ігрові рушії, і наукові симуляції.
  • Подієве моделювання (event-driven) - стандарт для задач з пружними зіткненнями: рахують час до наступної події, а не женуть малий крок dt. Так влаштовані симуляції газу з твердих кульок.
  • Графіки - у файли. На серверах і в автоматичних перевірках (CI) екрана нема, тому savefig у PNG, а не show().
  • Тести без екрана. Для turtle це TNavigator; для справжніх програм з вікнами - «віртуальний екран» Xvfb.
  • Форматування - інструментом. black і ruff format вирівнюють код самі, людина стиль не править руками.

Самоперевірка

  1. Що робить turtle.done() і що буде без нього?
  2. Чим turtle.TNavigator() відрізняється від turtle.Turtle() і навіщо він у doctest?
  3. Чому файл з лабою не можна називати turtle.py?
  4. Що означає помилка no display name and no $DISPLAY environment variable?
  5. Чому дослівна умова кінця з с. 12 (x_m < x_M) не спрацьовує після останнього зіткнення кульок?
Відповіді
  1. Запускає цикл подій вікна і тримає вікно відкритим, доки його не закриють; програма на ньому чекає. Без нього вікно закривається одразу після останньої команди.
  2. TNavigator лише рахує позицію і кут, вікна не створює. Тому doctest з ним працює без екрана і не відкриває вікон під час перевірки.
  3. import turtle спершу шукає модуль у теці скрипта, знайде твій файл і імпортує його замість справжнього; буде AttributeError: partially initialized module 'turtle' ....
  4. Програма хоче відкрити вікно, а змінної DISPLAY (на який екран малювати) нема: запуск по ssh або в TTY.
  5. Після зіткнення обидві кульки в одній точці (x_m == x_M), тому строга нерівність хибна; а при m = M ще й v_m = 0, тож v_m > 0 теж хибне. Подій нема, умова не спрацьовує - цикл не закінчується.
