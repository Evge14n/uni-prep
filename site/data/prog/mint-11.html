Нове тут:

  • cp - копіює файл або теку. Назва: copy - «копіювати».
  • ~ (tilde) - твоя домашня тека, /home/evgen.
  • "..." (double quotes) - усе між лапками - одне слово, навіть з пробілами.
  • python3 - запускає Python: твій файл .py, один рядок коду або вбудований інструмент. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль Python (вбудований чи поставлений через pip) як програму, напр. python3 -m venv (module - «модуль»).
  • python3 -m doctest - перевіряє приклади >>> з опису функцій. Назва: doc test - «тест у документації». -v (--verbose) - докладно: кожен приклад (Trying, Expecting, ok) і підсумок «N passed and M failed» (verbose - «багатослівно»).
  • | (pipe) - вивід лівої команди йде на вхід правої.
  • tail - показує останні рядки (файлу чи того, що прийшло через |). Назва: tail - «хвіст». -n (--lines) - скільки останніх рядків показати: -n 3, коротко -3 (lines - «рядки»).
  • python3 -m pytest - проганяє тести (приклади >>>) і чесно каже: усе пройшло чи ні. Назва: py + test - «тести для Python». --doctest-modules - шукати doctest (приклади >>>) у файлах .py; без нього pytest шукає лише функції test_; -q (--quiet) - коротко: крапка за кожен тест і рядок підсумку «1 passed in 0.01s» (quiet - «тихо»).
  • xdg-open - відкриває файл у його звичайній програмі. Назва: XDG (X Desktop Group, нині freedesktop.org) + open - «відкрити». graf.png - будь-яка картинка відкриється в переглядачі зображень.
  • timeout - зупиняє команду, якщо вона працює задовго. Назва: time out - «час вийшов».

Як читати:

  • Слово з мінусом (як -m тут) - прапорець: уточнює, що саме зробити команді.
  • Якщо поруч у дужках стоїть довга назва з двома мінусами - це той самий прапорець, пиши будь-яку одну.
  • Символи ~ | * # набирай в англійській розкладці (~ - Shift і клавіша ліворуч від 1; | - Shift і клавіша \; # - Shift і 3 (в українській розкладці там №)).

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

На відміну від ЛР5, у файлі ЛР6 нема doctest.testmod(). Тому python3 lr6_1.py нічого не друкує: тести ніхто не запускає. Запускай python3 -m doctest ... (це безпечно: чужого провалу, як у ЛР5, тут не буде) або допиши в кінець свій блок if __name__ == "__main__": з doctest.testmod().

3. Число 55 при k = 3 - щасливе? Порахуй три кроки (кожна цифра в кубі, суму):

print(5**3 + 5**3, 2**3 + 5**3 + 0**3, 1**3 + 3**3 + 3**3)

55 → 250 → 133 → 55 → ... - цикл без одиниці, отже за означенням з умови (с. 6) 55 не 3-щасливе. А тест викладача is_happy(55, 3) чекає True. Про це - нижче, у «Що не так у файлі викладача».

5. Не з ЛР6: послідовність «число → його квадрат, лише дві останні цифри», старт з 3. Чи дійде вона до 1?

value = 3
for step in range(8):
    value = value * value % 100
    print(value, end=" ")
print()
Відповідь 
9 81 61 21 41 81 61 21

Ні: після 81 іде коло 81 → 61 → 21 → 41 → 81, і одиниці в ньому нема. Цикл for на 8 кроків - це «підглядання», а програма не знає наперед, скільки кроків робити. Памʼятати всі пройдені числа (у списку) в завданні 1 заборонено - тому в теорії (с. 2-3) алгоритм «черепаха і заєць», що помічає коло без жодного списку.

6. Не з ЛР6: дільники 16 парами «малий - великий».

number = 16
for small in range(1, 5):
    if number % small == 0:
        print(small, number // small)
Відповідь 
1 16
2 8
4 4

Кожен дільник до √16 = 4 дає пару (small і number // small), тому далі 4 іти не треба. Але в останньому рядку пара - те саме число двічі. Якщо додавати обидва числа пари, 4 порахується двічі. Повний квадрат - пастка (с. 2).

7. Не з ЛР6: що за число?

print(((2 * 10 + 0) * 10 + 2) * 10 + 6)
Відповідь 
2026

Те саме, що 2·10³ + 0·10² + 2·10 + 6, але без жодного степеня: щокроку «попереднє × основу + наступна цифра». Це і є ідея схеми Горнера (с. 5) - для полінома замість 10 стоїть x, а замість цифр - коефіцієнти.

Пастка - повний квадрат («Передбач» 6: пара 4 4 для 16; так само 6 · 6 = 36) - такий дільник рахується один раз. Перевір свою функцію на 16, 36 і 1 руками, до запуску тестів.

def print_digits(number: int) -> None:
    """Друкує цифри числа через кому, в кінці крапка. Без списків і рядків.

    >>> print_digits(2026)
    2, 0, 2, 6.
    >>> print_digits(7)
    7.
    """
    divisor = 1
    while divisor * 10 <= number:
        divisor *= 10
    while divisor > 1:
        print(number // divisor % 10, end=", ")
        divisor //= 10
    print(number % 10, end=".\n")

def cube_root_bisect(value: float, eps: float) -> tuple[float, int]:
    """Кубічний корінь бісекцією і кількість кроків.

    >>> cube_root_bisect(27, 1e-6)
    (3.0, 25)
    >>> cube_root_bisect(2, 1e-6)
    (1.259921, 21)
    """
    low, high = 0.0, max(1.0, value)
    steps = 0
    while high - low > eps:
        middle = (low + high) / 2
        if middle**3 < value:
            low = middle
        else:
            high = middle
        steps += 1
    return round((low + high) / 2, 6), steps

Що не так у файлі викладача

Викладач просив надсилати помилки в doctest. Перевірено запуском у тестовій Mint 22.3:

  1. is_happy(55, 3) і is_happy(136, 3) чекають True. За означенням (с. 6: цикл має містити 1): 55 → 250 → 133 → 55 і 136 → 244 → 136 - цикли без одиниці. Правильна функція дає False, і саме ці 2 з 36 тестів не пройдуть. Покажи викладачу ланцюжки.
  2. Коментар у тестах «Для k = 1 будь-яке число зводиться до 1 лише якщо воно саме 1» - неправда: 10 → 1 + 0 = 1. Тестів на це нема, але не покладайся на коментар.
  3. Коментар «alpha = 1 ... неможливо для n >= 1» суперечить тесту is_abundant(1, 1) → True: σ(1) = 1 = 1·1. Правий тест.
  4. Назва is_abundant. «Abundant» англійською - «надлишкове» число (σ(n) > 2n), а функція перевіряє α-досконалість (σ(n) = α·n). Назву не міняй (так вимагає викладач), просто знай.
  5. flake8 на файлі викладача: 5 рядків E501 (коментарі в тестах довші за 78), 2 × E302 (між функціями один порожній рядок замість двох), 2 × E265 (#Тут без пробілу після #). E302 і E265 виправиш сам або black -l 78 (порожні рядки і пробіл - не тести). E501 у рядках тестів не чіпай - скажи викладачу.

Перевір перед здачею

Ті самі команди, що в уроках 04, 07-10. Файл завдання 1 не питає input(), тож printf не потрібен:

cd ~/univer/labs/lr6
source ~/univer/.venv/bin/activate
python3 -m doctest -v lr6_1.py | tail -n 3
python3 -m pytest --doctest-modules -q lr6_1.py
python3 -m black -l 78 lr6_1.py
python3 -m flake8 --max-line-length=78 lr6_1.py
python3 -m pycodestyle --max-line-length=78 lr6_1.py
python3 -m ruff check lr6_1.py
python3 -m mypy lr6_1.py
grep -n "\[\|{\|append\|join" lr6_1.py

Нове тут:

  • python3 -m black - сам гарно оформлює код Python (пробіли, переноси). Назва: black - «чорний»: як у Форда, «будь-який колір, якщо він чорний». -l (--line-length) - найбільша довжина рядка; викладач хоче 78, сам black ставить 88 (line length - «довжина рядка»).
  • python3 -m flake8 - шукає помилки стилю і зайвий код, нічого не змінює. Назва: pyflakes + pep8: обʼєднав дві старі програми перевірки коду. --max-line-length - найбільша дозволена довжина рядка; викладач хоче 78 (типово 79).
  • python3 -m pycodestyle - перевіряє лише оформлення коду за PEP 8 (правилами стилю Python). Назва: Python code style - «стиль коду Python» (раніше програма звалась pep8). --max-line-length - найбільша довжина рядка; викладач хоче 78 (типово 79).
  • python3 -m ruff check - швидко шукає помилки в коді, з --fix сам виправляє.
  • python3 -m mypy - перевіряє типи (int, str ...) без запуску програми.
  • grep - шукає рядки з текстом (у файлах або те, що прийшло через |). Назва: g/re/p з редактора ed: global regular expression print - «скрізь знайти шаблон, надрукувати». -n (--line-number) - показати номер рядка перед кожним збігом (line number - «номер рядка»).

Для lr6_2.py і lr6_3.py - те саме (вони питають input(), тому для pytest - printf "...\n" | ... -q -s, як в уроці 04). Самоперевірка

  1. Чому cp ~/Завантаження/doctests_lab_6(1).py lr6_1.py дає помилку і як її уникнути?
  2. Чому python3 lr6_1.py з файлом викладача нічого не друкує?
  3. Що означає <BLANKLINE> у doctest і як його отримати з функції?
  4. Чому при пошуку дільників до √n число 36 - пастка?
  5. Чому is_happy(55, 3) має бути False, хоча тест чекає True?
Відповіді
  1. Дужки - службові символи bash. Назву треба взяти в лапки ("doctests_lab_6(1).py") або дописати через Tab.
  2. У файлі тільки визначення функцій; ніхто не викликає doctest.testmod(). Треба python3 -m doctest lr6_1.py або свій блок if __name__ == "__main__":.
  3. Тест чекає надрукований порожній рядок; його дає print() без аргументів.
  4. 36 = 6 · 6: пара дільника 6 - він сам, і якщо додати обидва, σ або кількість дільників вийде більшою.
  5. 55 → 250 → 133 → 55 - цикл без 1, а за означенням k-щасливе число має прийти до 1. Помилка в тесті.
