Урок 22. bash - змінні, PATH, пайпи, grep, find

← Усі уроки

Навіщо: однією командою знайти всі print( у лабах, рядки довші за 78 символів, файли, змінені сьогодні, і зрозуміти, чому «команда не знаходиться» після pipx install.

Коротко

Термінал і nano - урок 03. Тут - те, з чого складаються команди.

Змінні.

name="Прізвище"            без пробілів навколо =
echo "$name"            "..." - підставить значення:   Прізвище
echo '$name'            '...' - буквально, як написано: $name
echo "Сьогодні $(date +%A)"   $(команда) - підставити вивід команди

Правило: змінну завжди бери в подвійні лапки "$x". Без лапок пробіл у значенні розбиває його на два слова.

Змінні оточення (environment) - ті, що успадковують програми, запущені з термінала: HOME, PATH, USER. Звичайна змінна живе лише в цьому bash; export x робить її змінною оточення. Подивитись: printenv HOME, усі - env. Python читає їх через os.environ.

PATH - список тек через :, де bash шукає команди. Набрав flake8 - bash іде по теках PATH зліва направо і запускає перший знайдений файл.

echo "$PATH" | tr ":" "\n"

Нове тут:

  • echo - друкує текст і значення змінних. Назва: echo - «луна»: повторює те, що йому дали.
  • tr - замінює окремі символи в тексті. Назва: translate - «перекласти»: замінити одні символи іншими.
  • "..." - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».
  • $ЗМІННА - підставляє значення змінної. Назва: dollar («долар») - «значення змінної».

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Перші рядки - на кшталт /home/evgen/.local/bin, /usr/local/sbin, /usr/local/bin, /usr/sbin, /usr/bin. ~/.local/bin - туди ставлять свої команди pipx і uv (урок 02). У Mint її додає файл ~/.profile, але лише якщо тека вже була в момент входу в систему. Тому після першого pipx install нова команда може «не знаходитись», поки не вийдеш із сеансу і не зайдеш знову (або source ~/.profile).

Де команда?

Довідка: --help і man. Майже кожна команда має коротку довідку команда --help і повну сторінку посібника man команда:

grep --help | head -3
man grep
man -k crontab

Usage: grep [OPTION]... PATTERNS [FILE]...
Search for PATTERNS in each FILE.
Example: grep -i 'hello world' menu.h main.c

Нове тут:

  • grep - знаходить рядки з текстом у файлах. Назва: g/re/p з редактора ed: «знайти регулярний вираз у всьому файлі і надрукувати». --help - коротка довідка про всі прапорці; українською, якщо система українська.
  • head - показує перші рядки файлу. Назва: head - «голова»: початок файлу.
  • man - відкриває повний посібник до команди. Назва: manual - «посібник». -k - шукати команди, в назві чи короткому описі яких є слово (як apropos).
  • | - передає вивід однієї команди на ввід іншій. Назва: pipe - «труба» (пайп), вертикальна риска.

Якщо Mint українською, --help теж українською (Використання: grep [ПАРАМЕТР]... ШАБЛОНИ [ФАЙЛ]...); англійською - LC_ALL=C grep --help. man відкриває сторінку в переглядачі less: пробіл - сторінка вниз, b - вгору, /слово і Enter - шукати, n - наступний збіг, q - вийти. Сторінка йде розділами: NAME (що це), SYNOPSIS (як викликати; у [ ] - необовʼязкове), DESCRIPTION (усі параметри), EXAMPLES (є не завжди). man -k слово шукає команди за словом в описі. Номер у дужках, як crontab(5), - розділ посібника: man 5 crontab - формат файлу, man crontab - сама команда. (Сторінки man - з пакетів man-db і manpages, вони є на ISO 22.3; у тестовій Mint їх нема, тому вигляд сторінок там не перевірено.)

Аліаси і ~/.bashrc. ~/.bashrc - файл, який bash читає при кожному новому вікні термінала. У Mint він уже має аліаси ll (ls -alF), la, l і читає ще файл ~/.bash_aliases, якщо той є - свої аліаси пиши туди. Після правки - source ~/.bashrc або нове вікно.

Історія. ↑ - попередня команда. Ctrl+R і почни набирати - пошук в історії (ще Ctrl+R - старіша, Enter - виконати, Esc - взяти в рядок). !! - уся попередня команда: sudo !! = «те саме, але з sudo». У Mint історія тримає 1000 команд (HISTSIZE=1000 у ~/.bashrc), а команда, що починається з пробілу, не запамʼятовується.

Потоки і перенаправлення. У програми три потоки: ввід (stdin, 0), вивід (stdout, 1), помилки (stderr, 2).

Запис Що робить
команда > файл вивід у файл (файл перезаписується)
команда >> файл дописати в кінець
команда 2> файл лише помилки у файл
команда > файл 2>&1 і вивід, і помилки в один файл (або коротко &> файл)
команда < файл ввід з файлу замість клавіатури
к1 \| к2 вивід к1 стає вводом к2 (пайп)
к1 \|& к2 те саме разом з помилками
команда \| tee файл і на екран, і у файл
> /dev/null викинути вивід

Фільтри - команди, які беруть текст і віддають текст, тому їх ставлять у пайпи:

Команда Що робить
grep "текст" файл рядки з текстом. -n номери, -i без різниці великі/малі, -v рядки БЕЗ тексту, -c скільки, -w ціле слово, -l лише імена файлів, -r у всіх підтеках, -E розширені регулярні вирази, --include="*.py" лише такі файли
find . -name "*.py" знайти файли за назвою; -type d теки, -mtime -1 змінені за останню добу, -exec команда {} + - виконати для знайдених
xargs команда рядки з входу → аргументи команди
sort, sort -rn впорядкувати; -n як числа, -r навпаки
uniq -c склеїти сусідні однакові рядки і порахувати (тому спершу sort)
wc -l скільки рядків (-m символів)
cut -d: -f1 взяти 1-ше поле, поля розділені :
head -n 5, tail -n 5 перші / останні 5 рядків; tail -f файл - стежити за файлом наживо (Ctrl+C)
sed -n '2,3p' надрукувати рядки 2-3
sed 's/старе/нове/' замінити (перше входження в рядку; g в кінці - усі)
awk '{ print $1 }' надрукувати перше «слово» рядка; -F: - розділювач :

Регулярні вирази (шаблони для grep, sed): ^ початок рядка, $ кінець, . будь-який символ, * попереднє 0 і більше разів, [0-9] одна цифра, .\{79,\} - 79 і більше будь-яких символів (з -E: .{79,}).

Код виходу $?: 0 - успіх, не 0 - помилка. к1 && к2 - к2 лише якщо к1 успішна; к1 || к2 - лише якщо к1 впала.

Передбач, потім запусти

Усі приклади - у практичній теці з «Руками» (крок 1).

  1. Що створить кожен mkdir?
lab="ЛР 1"
mkdir $lab
ls

Нове тут:

  • mkdir - створює нову теку. Назва: make directory - «зробити теку».
  • ls - показує, що лежить у теці. Назва: list - «список» (вмісту теки).
Відповідь 
1
lr1
lr2
ЛР

Дві теки, ЛР і 1: без лапок пробіл розбив значення на два аргументи. mkdir "$lab" зробить одну теку ЛР 1. Прибери зайве: rmdir ЛР 1.

  1. Що надрукує кожен рядок?
x=5
bash -c 'echo "x=$x"'
export x
bash -c 'echo "x=$x"'

Нове тут:

  • bash - оболонка, що виконує команди; bash файл.sh запускає скрипт. Назва: Bourne-Again SHell - «знову оболонка Борна» (гра слів: born again - «народжений знову»). -c - виконати команди з рядка в новому bash: bash -c 'echo привіт'.
  • export - робить змінну видимою для запущених програм. Назва: export - «вивезти, експортувати»: передати змінну програмам-нащадкам.
  • '...' - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».
Відповідь 
x=
x=5

bash -c - нова програма. Звичайну змінну вона не бачить, змінну оточення (після export) - бачить. Так само і Python через os.environ.

  1. Файлу nema.py нема. Що буде на екрані і що у файлі out.txt?
python3 nema.py > out.txt
cat out.txt

Нове тут:

  • python3 - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови.
  • cat - показує вміст файлу. Назва: concatenate - «зчепити»: склеює кілька файлів в один вивід.
  • > - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.
Відповідь

Помилка - на екрані, out.txt - порожній: > перенаправляє лише stdout, а помилки йдуть у stderr. Щоб зловити і помилки: python3 nema.py > out.txt 2>&1. Тоді в out.txt буде (шлях у тебе свій):

python3: can't open file '/home/evgen/univer/praktyka/bash22/nema.py': [Errno 2] No such file or directory
  1. У lr2/mayatnyk.py рядок 5 - docstring українською на 71 символ. Хтось шукає довгі рядки через awk:
awk 'length > 78' lr2/mayatnyk.py

Нове тут:

  • awk - бере з рядків потрібні стовпці (поля). Назва: awk - перші літери авторів: Aho, Weinberger, Kernighan (Bell Labs, 1977).
Відповідь 
    """Період маятника в секундах для довжини нитки length у метрах."""

Рядок надрукувався, хоча в ньому 71 символ. У Mint awk - це mawk, і length рахує байти, а кожна українська літера в UTF-8 - 2 байти (тут 116 байт). flake8 рахує символи. Правильно - через grep, він рахує символи: grep -n '.\{79,\}' lr2/mayatnyk.py - тиша, довгих рядків нема.

Руками

Крок 1. Практична тека з трьома маленькими файлами (свої лаби не чіпаємо):

mkdir -p ~/univer/praktyka/bash22 && cd ~/univer/praktyka/bash22
mkdir -p lr1 lr2
printf 'def area(r: float) -> float:\n    return 3.14159 * r ** 2\n\n\nprint(area(2))\n' > lr1/kolo.py
printf 'import math\n\n\ndef period(length: float) -> float:\n    """Період маятника в секундах для довжини нитки length у метрах."""\n    return 2 * math.pi * math.sqrt(length / 9.81)\n\n\nprint("T =", period(1.0))\nprint("готово")\n' > lr2/mayatnyk.py
printf 'x = 5\nPrint(x)\n# тут print( лише в коментарі\n' > lr2/chernetka.py

Нове тут:

  • mkdir: -p - створює і всі проміжні теки шляху; якщо тека вже є - мовчить, без помилки.
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • printf - друкує текст за шаблоном; \n - Enter. Назва: print formatted - «надрукувати за шаблоном».
  • && - друга команда - лише якщо перша вдалась. Назва: «і»: друга команда - лише якщо перша вдалась.
  • ~ - домашня тека /home/evgen. Назва: tilde («тильда») - домашня тека.

Крок 2. Змінні і лапки.

name="Прізвище"

echo 'Привіт, $name'
printenv HOME

Привіт, Прізвище
Привіт, $name
/home/evgen

Нове тут:

  • printenv - друкує змінні оточення. Назва: print environment - «надрукувати оточення» (змінні оточення). HOME - назва змінної - БЕЗ $.

Крок 3. Своя команда в ~/.local/bin.

mkdir -p ~/.local/bin
printf '#!/bin/bash\necho "Привіт з ~/.local/bin"\n' > ~/.local/bin/pryvit
chmod +x ~/.local/bin/pryvit

Нове тут:

  • chmod - змінює права файлу: читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. +x - дозволити запуск (x); у Mint - усім трьом: власнику, групі й іншим.

Тепер набери pryvit. Якщо тека ~/.local/bin щойно зʼявилась, її ще нема в PATH - bash скаже pryvit: command not found. Тоді:

source ~/.profile
type pryvit

Нове тут:

  • source - виконує файл у поточному bash (venv, ~/.bashrc). Назва: source - «джерело»: виконати команди з файлу-джерела. ~/.profile - перечитати PATH, напр. щоб зʼявилась ~/.local/bin (урок 22).
  • type - каже, що це за команда і де вона. Назва: type - «тип»: що це за команда.

і знову pryvit:

pryvit is /home/evgen/.local/bin/pryvit
Привіт з ~/.local/bin

Так само поводяться команди від pipx install. (Якщо тека вже була, pryvit спрацює одразу.)

Крок 4. Свій аліас.

echo "alias gst='git status'" >> ~/.bash_aliases
source ~/.bashrc
type gst
alias ll

gst is aliased to `git status'
alias ll='ls -alF'

Нове тут:

  • source: ~/.bashrc - перечитати налаштування після правки (аліаси, функції).
  • type: gst - перевірити свій аліас (урок 22).
  • alias - дає коротке імʼя довгій команді. Назва: alias - «псевдонім, інше імʼя». ll - alias ll - показати, на що замінюється ll (у Mint - ls -alF з ~/.bashrc).
  • >> - дописує вивід у кінець файлу. Назва: append - «дописати» в кінець файлу.

Назву аліасу перевір заздалегідь: type назва має відповісти not found. Інакше аліас сховає справжню програму (наприклад, gs - це Ghostscript, програма для PDF, і з аліасом gs її вже не запустиш).

Крок 5. grep по всіх лабах.

grep -rn "print(" .
grep -rni "print(" .
grep -rc "def " --include="*.py" .
grep -rl "import" .
grep -v "^$" lr1/kolo.py

Нове тут:

  • grep: -r - шукати в усіх файлах теки і підтек (recursive); -n - показати номер рядка перед кожним збігом (line number); . - з -r: шукати в поточній теці і всіх підтеках; -i - без різниці між великими й малими літерами (ignore case); -c - лише порахувати рядки зі збігом у кожному файлі (count); --include - з -r: шукати лише у файлах за шаблоном, --include="*.py"; -l - лише назви файлів, де є збіг (list); -v - навпаки: рядки, де шаблону НЕМА (invert).

Справжній вивід перших двох (порядок файлів у тебе може бути інший):

./lr2/mayatnyk.py:9:print("T =", period(1.0))
./lr2/mayatnyk.py:10:print("готово")
./lr2/chernetka.py:3:# тут print( лише в коментарі
./lr1/kolo.py:5:print(area(2))
./lr2/mayatnyk.py:9:print("T =", period(1.0))
./lr2/mayatnyk.py:10:print("готово")
./lr2/chernetka.py:2:Print(x)
./lr2/chernetka.py:3:# тут print( лише в коментарі
./lr1/kolo.py:5:print(area(2))

Формат: файл:рядок:текст. З -i знайшовся ще Print(x) (велика літера). -c дасть ./lr1/kolo.py:1 тощо, -l - лише ./lr2/mayatnyk.py, а grep -v "^$" покаже файл без порожніх рядків.

Крок 6. find і xargs.

find . -name "*.py"
find . -name "*.py" -mtime -1
find . -name "*.py" -exec wc -l {} +
find . -name "*.py" | xargs grep -c "print"

Нове тут:

  • find - шукає файли за назвою, часом чи власником. Назва: find - «знайти». -name - за назвою, шаблон у лапках: -name "*.py"; великі й малі літери різні; . - шукати тут і в усіх підтеках; -mtime - за днем зміни: -mtime -1 - змінені менше доби тому (modification time).
  • wc - рахує рядки, слова, символи. Назва: word count - «підрахунок слів»; рахує ще рядки й байти. -l - лише кількість рядків (lines).
  • xargs - робить з рядків входу аргументи команди. Назва: extended arguments - «розширені аргументи»: рядки з входу стають аргументами.

Справжній вивід третьої команди:

 10 ./lr2/mayatnyk.py
  3 ./lr2/chernetka.py
  5 ./lr1/kolo.py
 18 total

-mtime -1 - змінені за останню добу (зараз - усі три). {} - місце для знайдених файлів, + - віддати всі разом однією командою.

Крок 7. Пайпи: порахувати і впорядкувати.

grep -rhoE '[A-Za-z_]+\(' --include='*.py' . | sort | uniq -c | sort -rn
grep -rn "print(" . | cut -d: -f1 | sort | uniq -c

      4 print(
      2 period(
      2 area(
      1 sqrt(
      1 Print(
      1 ./lr1/kolo.py
      1 ./lr2/chernetka.py
      2 ./lr2/mayatnyk.py

Нове тут:

  • grep: -h - не писати назву файлу перед рядком (це НЕ довідка); -o - друкувати лише знайдений шматок, а не весь рядок (only); -E - розширені регулярні вирази: |, +, {79,} без зворотних рисок.
  • sort - впорядковує рядки. Назва: sort - «сортувати, впорядкувати». -r - навпаки: від більшого до меншого; -n - як числа: 9 менше за 10 (без -n - як текст, і 10 іде перед 9).
  • uniq - склеює однакові сусідні рядки (з -c - рахує). Назва: unique - «єдиний, неповторний»: прибрати повтори. -c - писати перед рядком, скільки разів він ішов підряд.
  • cut - вирізає з рядків потрібні стовпці. Назва: cut - «вирізати»: взяти шматок кожного рядка. -f - які поля взяти: -f1 або -f1,6,7 або -f2-4.

Перше - які функції викликаються найчастіше (-o друкує лише знайдений шматок, -h - без імені файлу). Друге - скільки print( у кожному файлі.

Нове тут:

Нове тут:

  • grep: -q - нічого не друкувати, лише код виходу: 0 - знайшов, 1 - ні (quiet).

Типові помилки

Якщо Mint українською, bash і find пишуть українською - у дужках (справжній запуск з перекладом language-pack-uk-base). Англійський текст для пошуку: LC_ALL=C команда. Помилки Python (NameError тощо) завжди англійською.

  • name = "Прізвище" з пробілами → name: command not found (name: команду не знайдено): bash думає, що name - це команда.
  • grep print( lr1/kolo.py без лапок → syntax error near unexpected token `(' (синтаксична помилка коло неочікуваної лексеми «(») - дужки для bash особливі. Шаблон завжди в лапках: grep "print(" lr1/kolo.py.
  • python3 lab.py > lab.py - стирає код: > спершу обнуляє файл. Вивід - в інший файл.
  • > замість >> - старий вміст пропав.
  • uniq -c без sort - рахує лише сусідні однакові рядки, числа виходять дивні.
  • awk 'length > 78' з українським текстом - хибні результати (mawk рахує байти, передбачення 4). Для довжини рядків - grep '.\{79,\}'.
  • find . -name *.py без лапок: якщо в поточній теці є .py-файли, bash сам підставить їх імена, і find шукатиме не те (або скаже paths must precede expression, українською шляхи мають передувати виразу). Шаблон - у лапках: -name "*.py".
  • Імена файлів з пробілами + xargs розвалюються на шматки. Тоді find ... -print0 | xargs -0 ... або find ... -exec ... {} +.
  • Нова команда в ~/.local/bin «не знаходиться» - тека додалась у PATH лише при наступному вході (крок 3).
  • sudo не бачить твоїх аліасів і ~/.local/bin - у sudo свій, безпечний PATH. Свої команди від root не запускай.

Як роблять профі

  • Маленькі команди + пайпи. Філософія Unix: кожна програма робить одне, а пайпи їх зʼєднують. Курс MIT «Missing Semester» (2020, лекція Data Wrangling) будує на цьому цілу лекцію; Cambridge Unix Tools - теж.
  • ripgrep (rg) і fd - швидші сучасні замінники grep і find, самі пропускають .venv і те, що в .gitignore. У репозиторії Mint є (sudo apt install ripgrep fd-find, команда fd там зветься fdfind). Але grep і find є всюди, тому вчимо спершу їх.
  • Аліаси - лише для себе. У скриптах (урок 23) пишуть повні команди: аліасів там нема.
  • Перевірка рядка перед запуском - explainshell.com розбирає будь-яку команду по шматках.

Самоперевірка

  1. Чим відрізняються echo "$name" і echo '$name'?
  2. Навіщо export і як перевірити, що змінна стала змінною оточення?
  3. Як одним рядком знайти в усіх .py поточної теки і підтек рядки з print( з номерами рядків?
  4. Ти поставив програму через pipx, а bash пише command not found. Чому і що зробити?
  5. Чому python3 lab.py > out.txt не зберіг текст помилки, і як зберегти і вивід, і помилки?
Відповіді
  1. У подвійних лапках $name замінюється значенням (Прізвище), в одинарних - друкується буквально $name.
  2. Щоб змінну бачили програми, запущені з цього bash (Python, інший bash). Перевірка: bash -c 'echo "$x"' або printenv x.
  3. grep -rn --include="*.py" "print(" .
  4. pipx кладе команди в ~/.local/bin, а ~/.profile додає цю теку в PATH лише якщо вона була при вході. Вийти з сеансу і зайти знову (або source ~/.profile). Перевірка: type назва.
  5. > перенаправляє лише stdout, а помилки йдуть у stderr. Треба python3 lab.py > out.txt 2>&1 (або &> out.txt).
