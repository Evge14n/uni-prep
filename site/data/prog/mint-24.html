Урок 24. git і GitHub з ssh-ключем

← Усі уроки

Навіщо: git - «збереження гри» для коду: зламав лабу - за секунду назад до робочої версії. GitHub - копія твоїх лаб у хмарі (приватна), з якої їх можна дістати на будь-якому компʼютері.

Коротко

git запамʼятовує коміти - знімки теки з підписом «що змінив». Шлях файлу до коміту:

правиш файл  ──git add──►  вибрано в коміт  ──git commit──►  історія (git log)
(робоча тека)              (staging)                         │
                                                             └──git push──► GitHub (origin)
                                                  git pull ◄──────────────┘
Команда Що робить
git init зробити теку репозиторієм (один раз)
git status що змінено, що вибрано в коміт (--short - коротко)
git add файл вибрати файл у наступний коміт (git add . - усе в теці)
git commit -m "опис" зробити коміт
git log --oneline історія, по рядку на коміт
git diff що змінено і ще не вибрано (вийти - q)
git restore файл викинути незакомічені зміни файлу (назавжди!)
git switch -c назва / git switch main нова гілка / повернутись на main
git merge назва влити гілку в поточну
git remote add origin адреса запамʼятати адресу GitHub під імʼям origin
git push / git pull відправити коміти / забрати чужі (свої з іншого компʼютера)
git clone адреса скопіювати весь репозиторій (на новому компʼютері)

.gitignore - список того, що git не бачить. Для лаб:

.venv/
__pycache__/
.mypy_cache/
.pytest_cache/
.ruff_cache/

Гілка (branch) - окрема лінія комітів. main - основна. Хочеш спробувати інший розвʼязок, не ламаючи робочий, - git switch -c sproba, комітиш там, а якщо вдалось - git merge у main.

GitHub і ключ. GitHub приймає git push по ssh-ключу з уроку 21: ти один раз даєш GitHub свій публічний ключ (~/.ssh/id_ed25519.pub), і далі паролі не потрібні. Адреса репозиторію для ssh має вигляд git@github.com:Evge14n/labs.git.

Чесність. Репозиторій з розвʼязками лаб - приватний (Private). Публічний репозиторій з розвʼязками до дедлайну - це те саме, що дати списати всій групі. Після здачі можна, але спершу спитай викладача.

Передбач, потім запусти

  1. На новому компʼютері git ще не знає, хто ти. Що буде на першому коміті?
git commit -m "Функція double"

Нове тут:

  • git commit - зберігає знімок змін з індексу в історію. Назва: commit - «зафіксувати»: зберегти знімок змін в історію. -m - повідомлення коміту одразу в команді; без -m відкриється nano.
  • "..." - текст з пробілами одним словом, $ підставляється. Назва: подвійні лапки - «усе це одне слово, але $ працює».

Усе про кожну команду - у вкладці «Команди», а тут торкнись команди в коді - вискочить підказка.

Відповідь

Відмова. Вивід з тестової Mint 22.3 (імʼя компʼютера в ньому замінено на evgen-laptop):

Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Твоє Імʼя Прізвище"

to set your account's default identity.
Omit --global to set the identity only in this repository.

fatal: empty ident name (for <evgen@evgen-laptop.localdomain>) not allowed

На ноутбуці останній рядок буде інший. У тестовій системі в користувача порожнє повне імʼя, тому git скаржиться на імʼя. А на ноутбуці повне імʼя ти ввів, коли ставив Mint, - git його візьме, але не зможе вгадати пошту:

fatal: unable to auto-detect email address (got 'evgen@evgen-laptop.(none)')

(на ноутбуці не перевірено; так git пише, коли в імені компʼютера нема домену). Українською перші рядки - Особистість автора невідома і *** Будь ласка, скажіть мені, хто ви., а останній - fatal: не вдалося автоматично визначити адресу електронної пошти (отримано "evgen@evgen-laptop.(none)"). Лікується кроком 1 (git config --global user.name і user.email).

  1. Ти змінив lab.py (x * 2 → x * 3) і створив новий файл чернетка.py. Що скаже git status?
Відповідь 
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
    modified:   lab.py

Untracked files:
  (use "git add <file>..." to include in what will be committed)
    чернетка.py

no changes added to commit (use "git add" and/or "git commit -a")

modified - файл, який git уже знає, змінено. Untracked - git цей файл ще ніколи не бачив. Українська назва показана нормально, бо core.quotepath false (крок 1).

  1. Після python3 -m venv .venv у теці репозиторію git status --short показує ?? .venv/. Що зміниться, коли створиш .gitignore з рядком .venv/?
Відповідь

.venv/ зникне зі списку - git його більше не бачить. Замість нього зʼявиться сам .gitignore (його треба закомітити):

?? .gitignore
?? чернетка.py
  1. Ти на гілці sproba дописав функцію і закомітив. Потім git switch main. Чи є ця функція в lab.py?
Відповідь

Нема: grep -c triple lab.py дасть 0. Файли в теці завжди показують ту гілку, на якій ти стоїш. Після git merge sproba функція зʼявиться і в main.

Руками

Крок 1. Налаштувати git (один раз на компʼютер). git є не на свіжій Mint, а після уроку 03 (sudo apt install git). Імʼя - як на GitHub:

git config --global user.name "Твоє Імʼя Прізвище"
git config --global init.defaultBranch main
git config --global core.quotepath false

Нове тут:

  • git config - читає і змінює налаштування git (імʼя, пошта, редактор). Назва: config - від configuration, «налаштування». --global - для тебе на цьому ноутбуці: пише у файл ~/.gitconfig, діє в усіх репо.

Пошта: на GitHub відкрий Settings → Emails, увімкни «Keep my email addresses private» і скопіюй адресу виду ...@users.noreply.github.com - тоді справжня пошта не потрапить у коміти. Команда (встав свою адресу):

git config --global user.email "скопійована_адреса@users.noreply.github.com"

Перевір: git config --global --list. init.defaultBranch main - щоб основна гілка звалась main, а не master (без цього git init друкує довгу підказку hint: Using 'master' as the name for the initial branch). ustanovka-mint.sh з уроку 03 два останні рядки вже зробив.

Крок 2. Тренувальний репозиторій.

mkdir -p ~/univer/praktyka/git24 && cd ~/univer/praktyka/git24
git init
printf 'def double(x: int) -> int:\n    """\n    >>> double(4)\n    8\n    """\n    return x * 2\n' > lab.py
git status
git add lab.py
git commit -m "Функція double"
git log --oneline

Нове тут:

  • mkdir - створює нову теку. Назва: make directory - «зробити теку». -p - створює і всі проміжні теки шляху; якщо тека вже є - мовчить, без помилки.
  • cd - переходить в іншу теку. Назва: change directory - «змінити теку».
  • git init - робить теку репозиторієм git (створює .git). Назва: init - від initialize, «почати, підготувати».
  • printf - друкує текст за шаблоном; \n - Enter. Назва: print formatted - «надрукувати за шаблоном».
  • git status - показує, що змінено і що піде в наступний коміт. Назва: status - «стан».
  • git add - додає зміни файлу в наступний коміт (індекс). Назва: add - «додати» (в індекс, тобто в наступний коміт).
  • git log - показує історію комітів, новий зверху. Назва: log - «журнал»: історія комітів. --oneline - по рядку на коміт: 7 знаків хешу і перший рядок повідомлення.
  • && - друга команда - лише якщо перша вдалась. Назва: «і»: друга команда - лише якщо перша вдалась.
  • ~ - домашня тека /home/evgen. Назва: tilde («тильда») - домашня тека.
  • '...' - текст буквально, нічого не підставляється. Назва: одинарні лапки - «буквально, як написано».
  • > - пише вивід у файл, старий вміст стирає. Назва: redirect - «перенаправлення» виводу у файл.

Кінець виводу:

[main (root-commit) a4fbd19] Функція double
 1 file changed, 6 insertions(+)
 create mode 100644 lab.py
a4fbd19 Функція double

a4fbd19 - початок «імені» коміту (хеша). У тебе він буде інший: хеш залежить від автора і часу.

Крок 3. Зламати і повернути.

sed -i 's/x \* 2/x * 3/' lab.py
printf 'print("чернетка")\n' > чернетка.py
git status
git diff
git restore lab.py
git status --short

Нове тут:

  • sed - друкує потрібні рядки або замінює текст. Назва: stream editor - «потоковий редактор»: править текст, що тече крізь нього. -i - змінити САМ файл (без -i sed лише показує результат); -i.bak - ще й копія.
  • git status: --short - коротко: по рядку на файл з двома буквами стану (M, A, ??).
  • git diff - показує, які рядки змінено (+ додано, - прибрано). Назва: diff - від difference, «різниця».
  • git restore - викидає зміни у файлі або забирає його з індексу. Назва: restore - «відновити».

git diff показує, що саме змінено (- було, + стало):

diff --git a/lab.py b/lab.py
index add341c..1d9cbaf 100644
--- a/lab.py
+++ b/lab.py
@@ -3,4 +3,4 @@ def double(x: int) -> int:
     >>> double(4)
     8
     """
-    return x * 2
+    return x * 3

Після git restore lab.py у git status --short лишиться тільки ?? чернетка.py - зміна в lab.py зникла.

Крок 4. .gitignore.

python3 -m venv .venv
git status --short
printf '.venv/\n__pycache__/\n.mypy_cache/\n.pytest_cache/\n.ruff_cache/\n' > .gitignore
git status --short
git add .gitignore чернетка.py
git commit -m "gitignore і чернетка"

Нове тут:

  • python3 - запускає Python: файл, рядок коду або модуль. Назва: Python - на честь комедійного шоу «Monty Python», 3 - третя версія мови. -m - запусти модуль як програму: python3 -m pytest, python3 -m venv, python3 -m pdb.
  • python3 -m venv - створює окреме середовище Python (venv) для бібліотек лаб. Назва: virtual environment - «віртуальне середовище».

Крок 5. Гілка.

git switch -c sproba
printf '\n\ndef triple(x: int) -> int:\n    return x * 3\n' >> lab.py
git commit -am "Спроба: triple"
git switch main
grep -c triple lab.py
git merge sproba
git log --oneline
git branch -d sproba

Нове тут:

  • git switch - перемикає на іншу гілку (-c - створює нову). Назва: switch - «перемкнути». -c - створити нову гілку від поточного місця і перейти на неї.
  • git commit: -a - спершу сам додає зміни ВЖЕ відстежуваних файлів; нові файли - ні.
  • grep - знаходить рядки з текстом у файлах. Назва: g/re/p з редактора ed: «знайти регулярний вираз у всьому файлі і надрукувати». -c - лише порахувати рядки зі збігом у кожному файлі (count).
  • git merge - зливає іншу гілку в поточну. Назва: merge - «злити, обʼєднати».
  • git branch - показує, створює і видаляє гілки. Назва: branch - «гілка». -d - видалити гілку, якщо її коміти вже злито; інакше відмовить.
  • >> - дописує вивід у кінець файлу. Назва: append - «дописати» в кінець файлу.

-am = git add для вже відомих файлів + -m. Справжній вивід злиття і історії:

Updating 8806241..632cd09
Fast-forward
 lab.py | 4 ++++
 1 file changed, 4 insertions(+)
632cd09 Спроба: triple
8806241 gitignore і чернетка
a4fbd19 Функція double

Fast-forward - main просто «пересунули вперед» на коміти з гілки, бо в main за цей час нічого нового не було.

Крок 6. Репозиторій на GitHub (у браузері). github.com → зайди → + угорі праворуч → New repository: назва labs, Private, README / .gitignore / license не додавай (у тебе вже є локальний репозиторій) → Create repository. (Кроки - з документації GitHub; назви кнопок можуть трохи змінитись.)

Крок 7. Дати GitHub свій ssh-ключ. Ключ з уроку 21:

cat ~/.ssh/id_ed25519.pub

Нове тут:

  • cat - показує вміст файлу. Назва: concatenate - «зчепити»: склеює кілька файлів в один вивід.

Скопіюй рядок (виділи і Ctrl+Shift+C). GitHub → аватар → Settings → SSH and GPG keys → New SSH key → Title: Mint laptop, Key type: Authentication Key, вставити → Add SSH key. Перевір:

ssh -T git@github.com

Нове тут:

  • ssh - заходить у термінал іншого компʼютера по зашифрованому каналу. Назва: Secure Shell - «захищена оболонка»: зашифрований термінал на іншому компʼютері. -T - прапорець: не відкривати термінал на тому боці, лише перевірити вхід (ssh -T git@github.com). GitHub не дає командного рядка, тому для нього завжди -T; якщо вхід вдався, GitHub вітає на імʼя і закриває зʼєднання з кодом 1 - це нормально (Git урок 03); git@github.com - користувач git на сервері github.com - так GitHub приймає всіх, а тебе впізнає за ключем.

За документацією GitHub має бути (замість USERNAME - твій логін):

Hi USERNAME! You've successfully authenticated, but GitHub does not
provide shell access.

(Цей вивід не перевірено в тестовій Mint: її ключа на GitHub нема, там справжня відповідь - git@github.com: Permission denied (publickey)., як в уроці 21. Код виходу навіть при успіху - 1, так пише GitHub.)

Крок 8. Відправити лаби. Репозиторій лаб - ~/univer/labs з уроку 04. Якщо ти робив необовʼязковий крок 8 уроку 04, там уже є git init і коміти. Не робив (git status пише fatal: not a git repository) - спершу:

cd ~/univer/labs
git init
printf '.mypy_cache/\n.ruff_cache/\n.pytest_cache/\n__pycache__/\n' > .gitignore
git add .
git commit -m "Лаби на початок"

Нове тут:

  • git add: . - усе в поточній теці і підтеках; спершу глянь git status, щоб не додати зайве.

Далі - відправити:

cd ~/univer/labs
git status
git remote add origin git@github.com:Evge14n/labs.git
git push -u origin main

Нове тут:

  • git remote - показує і задає адресу репо на GitHub (origin). Назва: remote - «віддалений»: репо на іншому компʼютері (GitHub). origin - звичайна назва головного віддаленого репо; git clone ставить її сам.
  • git push - відправляє твої коміти на GitHub. Назва: push - «штовхнути»: відправити свої коміти на GitHub. -u - запамʼятати звʼязок гілки з GitHub; далі просто git push і git pull.

-u запамʼятовує, що main іде в origin/main, і далі досить git push і git pull. У тестовій Mint замість GitHub був локальний «сервер» (git init --bare), і git push -u надрукував:

To /home/evgen/labs.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

З GitHub буде To github.com:Evge14n/labs.git і ще кілька рядків прогресу (Enumerating objects...) - не перевірено. Онови сторінку репозиторію в браузері - файли там.

Далі - за бажанням

Крок 10 - інший шлях до того самого (програма gh). Якщо кроки 6-9 вийшли, він не потрібен.

Крок 10 (інший шлях). gh - офіційна програма GitHub. Вміє сама зробити ключ, залогінитись і створити репозиторій.

Увага: sudo apt install gh з репозиторію Mint дає стару версію 2.45, і вона зламана - gh pr view і gh issue view падають з «GraphQL: Projects (classic) is being deprecated». Розробники gh пишуть прямо: «the community-distributed 2.45.x / 2.46.x version is broken» (cli/cli, docs/install_linux.md, 18.11.2026). Тому став gh з офіційного репозиторію GitHub - це довгий рядок, копіюй його цілим (він додає ключ і репозиторій GitHub, потім gh оновлюватиметься разом з системою через Диспетчер оновлень):

(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
    && sudo mkdir -p -m 755 /etc/apt/keyrings \
    && out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
    && cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
    && sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
    && sudo mkdir -p -m 755 /etc/apt/sources.list.d \
    && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
    && sudo apt update \
    && sudo apt install gh -y

Нове тут:

  • type - каже, що це за команда і де вона. Назва: type - «тип»: що це за команда. -p - лише шлях до файлу, або нічого, якщо це не файл (path); wget - з -p у скриптах: є програма - нічого не ставити.
  • sudo - виконує одну команду від імені адміністратора (root). Назва: su do - «виконати як інший користувач», зазвичай root.
  • apt update - оновлює список пакетів, нічого не ставить. Назва: update - «оновити» (тут оновлюється лише список пакетів).
  • apt install - ставить програму (пакет) зі сховища. Назва: install - «встановити». -y - одразу відповідає «так» на «Продовжити?» - список того, що поставиться, не встигнеш прочитати.
  • mkdir: -m - одразу задає права нової теки, напр. -m 700 - лише для тебе.
  • wget - завантажує файл з інтернету за адресою. Назва: World Wide Web + get - «дістати з вебу».
  • tee - показує вивід і одночасно пише у файл. Назва: tee - трійник у трубах (літера T): потік іде у два боки.
  • chmod - змінює права файлу: читати, змінювати, запускати. Назва: change mode - «змінити режим», тобто права доступу файлу. go+r - дати читання групі (g = group) та іншим.
  • echo - друкує текст і значення змінних. Назва: echo - «луна»: повторює те, що йому дали.
  • mktemp - створює тимчасовий файл чи теку і друкує шлях. Назва: make temporary - «зробити тимчасовий» файл чи теку.
  • dpkg - ставить один .deb і знає, що встановлено. Назва: Debian package - «пакет Debian». --print-architecture - друкує архітектуру системи, напр. amd64.
  • || - друга команда - лише якщо перша впала. Назва: «або»: друга команда - лише якщо перша впала.
  • | - передає вивід однієї команди на ввід іншій. Назва: pipe - «труба» (пайп), вертикальна риска.
  • $( ) - підставляє вивід команди в рядок. Назва: command substitution - «підстановка команди».
  • $ЗМІННА - підставляє значення змінної. Назва: dollar («долар») - «значення змінної».
  • \ - екранує символ або переносить команду на новий рядок. Назва: backslash - «зворотна скісна риска».

Перевір: gh --version має показати 2.100 чи новішу, а не 2.45. Потім вхід:

gh auth login -p ssh -w

Нове тут:

  • gh auth login - входить у акаунт GitHub для gh (через браузер). Назва: auth - від authentication, «вхід, підтвердження особи»; login - «увійти». -p - як git ходитиме на GitHub: ssh (ключ з уроку 03) або https; -w - вхід через браузер: gh покаже одноразовий код, ти вставиш його на github.com; ssh - з -p: git через SSH; gh знайде ~/.ssh/id_ed25519.pub і запропонує завантажити його на GitHub.

-p ssh - працювати через ssh, -w - увійти через браузер (gh покаже одноразовий код, його вставляєш на сайті). Створити приватний репозиторій з поточної теки і одразу відправити:

cd ~/univer/labs
gh repo create labs --private --source=. --push

Нове тут:

  • gh repo create - створює репозиторій на GitHub з терміналу. Назва: repository create - «створити репозиторій» на GitHub. --private - приватний репо: бачиш лише ти (і кого запросиш); для лаб - саме так; --source - взяти теку, що вже є на ноутбуці, напр. --source=. - поточну; --push - одразу запушити коміти з --source на GitHub.

(Опції перевірено в gh --help у тестовій Mint; сам вхід - ні, там нема браузера й акаунта. Сніпет офіційного репозиторію перевірила сесія курсу git: встановився gh 2.105.0, gh pr view працює.)

Хочеш git глибше (гілки, конфлікти, Pull Request, теги для здачі, GitHub Pages, повний розбір gh) - окремий курс 05_Програмування\Git-GitHub\ (уроки 01-16 і «Лаби в git - univer-labs покроково»), робоче місце там те саме: ~/univer/labs/lr1...lr7.

Типові помилки

git перекладено: якщо Mint українською, повідомлення git теж українською (у дужках - справжній запуск з перекладом language-pack-uk-base); відповіді GitHub (remote: ...) і ssh - англійською. Англійський текст для пошуку: LC_ALL=C git ....

  • Author identity unknown (Особистість автора невідома) - передбачення 1, крок 1.
  • hint: Using 'master' as the name for the initial branch (Використання "master" як назви початкової гілки) - не задано init.defaultBranch main до git init. Для вже створеного: git branch -m main.
  • error: src refspec main does not match any (error: визначник посилання джерела main не збігається з жодним) при push - у репозиторії ще нема жодного коміту (або гілка зветься master). git log --oneline, git branch.
  • git@github.com: Permission denied (publickey). - GitHub не знає твій ключ (крок 7) або ssh бере інший.
  • remote: Support for password authentication was removed - адреса https://..., а не git@github.com:... (не перевірено в тестовій Mint). Виправити: git remote set-url origin git@github.com:Evge14n/labs.git.
  • ! [rejected] main -> main (fetch first) (українською [відхилено]) - на GitHub є коміти, яких нема в тебе (пушив з іншого компʼютера). Спершу git pull, потім git push (текст не перевірено в тестовій Mint).
  • Закомітив .venv - тисячі файлів. Спершу .gitignore, потім git rm -r --cached .venv і коміт.
  • Закомітив пароль чи токен - вважай, що він уже витік: зміни пароль / відклич токен. git rm --cached файл прибирає файл лише з наступних комітів, у старих він лишається. Секрети тримай поза репозиторієм і додавай їхні файли в .gitignore.
  • git restore стер потрібне - він не питає і не має «назад». Перед ним глянь git diff.
  • git commit без -m відкриє редактор (у Mint - nano): напиши опис, Ctrl+S, Ctrl+X.

Як роблять профі

  • Маленькі коміти з людським описом. Одне завдання або одна правка - один коміт. Книга Pro Git і курс MIT «Missing Semester» (лекція Version Control) вчать саме так.
  • Гілка на кожну спробу, main завжди робочий.
  • ssh-ключ з паролем або gh, а не паролі: GitHub не приймає пароль акаунта для git з 13.08.2021 (блог GitHub; для https - лише токени).
  • Приватний noreply-email у комітах - щоб пошта не потрапила в публічну історію.
  • Секрети - ніколи в git. Навіть у приватному репозиторії: його можуть зробити публічним, а історія лишиться.

Самоперевірка

  1. Назви по порядку команди, якими новий файл потрапляє на GitHub.
  2. Чим git restore lab.py небезпечний і що зробити перед ним?
  3. Навіщо .gitignore і що в ньому має бути для лаб на Python?
  4. Ти пушиш з ноутбука, а git пише Permission denied (publickey). Що перевірити?
  5. Чому репозиторій з лабами має бути приватним?
Відповіді
  1. git add файл, git commit -m "опис", git push (перший раз - git push -u origin main після git remote add origin ...).
  2. Він назавжди викидає незакомічені зміни файлу, без питань. Спершу git diff (або коміт).
  3. Щоб git не зберігав те, що можна перестворити або що секретне: .venv/, __pycache__/, кеші .mypy_cache/, .pytest_cache/, .ruff_cache/.
  4. Чи доданий ~/.ssh/id_ed25519.pub на GitHub (Settings → SSH and GPG keys), чи ssh -T git@github.com вітає тебе, чи адреса origin має вигляд git@github.com:... (git remote -v).
  5. Академічна чесність: публічні розвʼязки до дедлайну можуть списати інші, а відповідати будеш і ти. Викладач перевіряє розуміння.
