1. Ідея

Урок 1 дав «цеглинки»: змінні й print. Тепер з них складаємо справжню програму, яка питає дані (input), рахує і показує результат гарно відформатованим (%, f-рядки). А щоб ту саму обчислювальну частину можна було перевірити й використати ще раз, її ховають у функцію, яка повертає результат (return). Плюс правила оформлення PEP 8, бо викладач перевіряє не лише «чи працює», а й «чи правильно написано».

Головна думка уроку: друкувати і повертати - різні речі. print показує текст людині і віддає None. return віддає значення програмі, щоб з ним працювати далі. doctest у лабах перевіряє саме те, що функція повертає.

pass і присвоєння

def future_feature():

pass - «тут поки нічого». Функцію без return можна викликати, і вона поверне None («нічого»). Саме тому в заготовках задач стоїть pass: doctest чекає число чи рядок, отримує None і червоніє.

Присвоєння (с. 1): у x = e спершу рахується e, потім старе значення x стає недосяжним. x = 12 і y = (x**5 + x**4 + x**3 + x**2 + x + 1) дає y = 271453 (так і в коді з пари, с. 1).

Форматування оператором %

print("First = %d, second = %d" % (1, 2))
print("%s було %d років, коли він пішов у %d клас" % ("Миколі", 7, 1))
print("Високосний рік має %d днів" % 366)
print("Знижка %d%%" % 15)
print("%.2f і %e" % (3.14159, 0.000123))

Високосний рік має 366 днів
Знижка 15%
3.14 і 1.230000e-04

Зліва - шаблон, справа після % - значення в дужках. Кожен %d (ціле), %s (рядок), %f (дійсне), %e (експоненційна форма) забирає одне значення по черзі. %% - сам знак відсотка. Одне значення можна без дужок (с. 3). Правило: скільки %... у шаблоні, стільки значень справа, інакше TypeError. Цей стиль старий, але в чужому коді (і в Лекції 3) трапляється часто.

PEP 8 і перевірка стилю

PEP 8 - офіційні рекомендації, як оформлювати код Python (Лекція 2, с. 6-12). Код з порушеннями все одно запуститься, але викладач перевіряє стиль, і читати такий код у 10 разів частіше, ніж писати (с. 6). Найважливіше:

Правило Як правильно Як не треба
Відступ 4 пробіли, без табуляції (змішування дає TabError) 2 пробіли або Tab
Довжина рядка до 79 знаків (докстрінг і коментар до 72) рядок на весь екран
Перенос усередині дужок: total = (first + second + зворотна риска \ у кінці
Порожні рядки 2 між функціями, 1 між методами класу 0
Пробіли x = 1, y = x + 3, f(a, b), data[1] x=1, f (a,b), ( a + b )
Змінні, функції snake_case: student_name, calculate_area() studentName, a, d1
Константи UPPER_SNAKE_CASE: MAX_SPEED, EARTH_RADIUS_KM = 6371 maxspeed
Класи PascalCase: BankAccount bank_account
Не брати l, O, I (схожі на 1 і 0); імена sum, list, str, type, id
Імпорти кожен на окремому рядку, на початку файлу: стандартні, сторонні, свої import math, os
Коментарі повне речення; не дублювати код; функції - докстрінг """..."""
Порівняння if value is None:, if is_valid: (про if - урок 3) == None, == True

Нове тут:

  • \ (backslash) - робить наступний символ звичайним; у кінці рядка - перенос.
  • type - каже, що це за команда і де вона. Назва: type - «тип».
  • id - показує твій номер у системі (uid) і групи. Назва: identity - «особа» (ID - ідентифікатор, номер).

Інструменти (с. 12-14): лінтери знаходять проблеми, не запускаючи код (pycodestyle - лише PEP 8; flake8 - PEP 8 + невикористані імена; pylint - глибше, ставить оцінку з 10; mypy - перевіряє типи). Форматери самі переписують код (black - «безкомпромісний», ширина 88; autopep8; isort - сортує імпорти). Запуск: pip install flake8 black, потім flake8 my_program.py. У Linux Mint pip install працює лише всередині venv (source ~/univer/.venv/bin/activate), інакше помилка externally-managed-environment - курс Linux-Mint, уроки 02-03.

Нове тут:

  • pip install - ставить бібліотеку Python (лише у venv). Назва: pip - pip installs packages - «pip ставить пакети» (назва, що посилається сама на себе); pip installs packages - «pip ставить пакети»; install - «встановити».
  • source - виконує команди з файлу просто в цьому вікні термінала. Назва: source - «джерело». ~/univer/.venv/bin/activate - увімкнути venv (окремий Python для лаб); вимкнути - deactivate.
  • ~ (tilde) - твоя домашня тека, /home/evgen.

2. Розібраний приклад

Умова. Користувач вводить відстань у км і час у годинах. Функція повертає рядок із середньою швидкістю, округленою до 1 знака. Структура - як у ЛР1, с. 11: функція з doctest, ввід, виклик, вивід, перевірка.

# ввід: 120 | 1.5
import doctest


def average_speed(distance_km: float, hours: float) -> str:
    """Повертає рядок із середньою швидкістю, км/год.

    >>> average_speed(120.0, 1.5)
    'Середня швидкість: 80.0 км/год'
    >>> average_speed(0.0, 2.0)
    'Середня швидкість: 0.0 км/год'
    """
    speed = distance_km / hours
    return f"Середня швидкість: {speed:.1f} км/год"


distance = float(input("Відстань, км: "))
time_hours = float(input("Час, год: "))
message = average_speed(distance, time_hours)
print(message)
doctest.testmod()

Відстань, км: 120
Час, год: 1.5
Середня швидкість: 80.0 км/год

Кожен рядок:

Рядок Що робить
import doctest Підключає модуль для перевірки прикладів з докстрінгів. Імпорти - на початку (PEP 8).

"""Повертає рядок ... >>> ...""" Докстрінг з двома doctest: виклик після >>> і очікуваний результат. Рядок у лапках, бо функція повертає str.

return f"Середня швидкість: {speed:.1f} км/год" Збирає рядок, :.1f - 1 знак після коми, і віддає його в місце виклику.
(2 порожні рядки) PEP 8: дві порожні лінії після функції.

time_hours = float(input("Час, год: ")) Так само: "1.5" → 1.5.

print(message) Лише тут щось зʼявляється на екрані. Функція сама нічого не друкувала.
doctest.testmod() Проганяє обидва приклади з докстрінгу. Якщо все добре - мовчить.

"""Урок 2. Розвʼязки задач з doctest.

Відкривай лише після 2 спроб написати самому.
Перевірка: python3 -m doctest _rozvyazky/urok02.py -v
"""
import doctest


def temperature_report(celsius: float) -> str:
    """Повертає рядок «C °C = F °F», а для морозу дописує « (мороз)».

    Формула: F = C * 9 / 5 + 32. Обидва числа - з одним знаком
    після коми. Мороз - коли температура нижче нуля (0.0 - ще ні).
    Без if: використай прийом «рядок * умова».

    :param celsius: температура в градусах Цельсія
    :return: рядок-звіт

    >>> temperature_report(0.0)
    '0.0 °C = 32.0 °F'
    >>> temperature_report(36.6)
    '36.6 °C = 97.9 °F'
    >>> temperature_report(100.0)
    '100.0 °C = 212.0 °F'
    >>> temperature_report(-40.0)
    '-40.0 °C = -40.0 °F (мороз)'
    >>> temperature_report(-0.5)
    '-0.5 °C = 31.1 °F (мороз)'
    """
    fahrenheit = celsius * 9 / 5 + 32
    # celsius < 0 - це логічний вираз: True або False.
    # У множенні True поводиться як 1, False як 0, тому
    # " (мороз)" * True = " (мороз)", а " (мороз)" * False = "".
    # Строго «< 0», а не «<= 0»: 0.0 °C ще не мороз (див. doctest).
    frost_note = " (мороз)" * (celsius < 0)
    # :.1f - один знак після коми. 97.88 показується як 97.9,
    # але саме число fahrenheit не змінюється (це лише показ).
    return f"{celsius:.1f} °C = {fahrenheit:.1f} °F{frost_note}"


def receipt(item: str, price: float, quantity: int) -> str:
    """Повертає чек з двох рядків, склеєних через символ нового рядка.

    Перший рядок: назва товару (займає щонайменше 8 знаків,
    вирівняна вліво), риска, кількість і ціна за штуку.
    Другий рядок: загальна сума. Ціни - з двома знаками після коми.
    Один return з одним f-рядком.

    :param price: ціна за штуку, грн
    :param quantity: кількість штук (0 або більше)
    :return: текст чека

    >>> receipt("Milk", 28.5, 2)
    'Milk    | 2 x 28.50\\nTotal: 57.00 UAH'
    >>> receipt("Tea", 45.0, 0)
    'Tea     | 0 x 45.00\\nTotal: 0.00 UAH'
    >>> receipt("Chocolate", 52.25, 3)
    'Chocolate| 3 x 52.25\\nTotal: 156.75 UAH'
    >>> print(receipt("Bread", 19.9, 1))
    Bread   | 1 x 19.90
    Total: 19.90 UAH
    """
    total = price * quantity
    # {item:<8} - ширина щонайменше 8, вирівнювання вліво. Ширина -
    # це МІНІМУМ: "Chocolate" має 9 літер, його не обрізає, тому
    # риска стоїть одразу після назви (див. третій doctest).

    # doctest без print показує його як \n, а print - як перенос.
    return (f"{item:<8}| {quantity} x {price:.2f}\n"
            f"Total: {total:.2f} UAH")

7. Поясни чому

1. Чому у лабах функція має повертати результат через return, а не друкувати його?

Еталон

print показує текст людині, а функція при цьому повертає None: з результатом далі нічого не зробиш (не додаси, не передаси в іншу функцію, не перевіриш). doctest порівнює саме повернене значення. Крім того, ЛР1, с. 11-12 вимагає розділяти обчислення (функція) і ввід-вивід (поза функцією): так функцію можна тестувати й використовувати з будь-яким джерелом даних.

2. Чому input() + input() склеює числа, а не додає?

Еталон

input завжди повертає рядок (str), навіть якщо набрали цифри. Що робить +, залежить від типу: для чисел - додавання, для рядків - склеювання. "12" + "18" = "1218". Тому одразу пишуть int(input(...)) або float(input(...)).

3. Чому код, що порушує PEP 8, працює, а викладач однаково вимагає flake8?

Еталон

PEP 8 - не синтаксис, а домовленість (Лекція 2, с. 7): інтерпретатору байдуже, чи є пробіли навколо =. Але код читають у 10 разів частіше, ніж пишуть, і в команді всі мають писати однаково. Частина правил ловить справжні проблеми: імʼя sum ламає вбудовану функцію, flake8 бачить невикористані змінні, mypy - рядок там, де чекали число. І ще: проходження flake8 не означає правильний алгоритм, а зелений doctest не означає гарний стиль (ЛР1, с. 9) - перевіряють обидва.

8. Що запамʼятати

  • input() повертає рядок завжди; числа - int(input()) / float(input()).
  • print(..., sep=" ", end="\n"): sep між значеннями, end у кінці; print повертає None.
  • %: кількість %d/%s/%f = кількість значень; %% - знак відсотка; %d відкидає дріб.
  • f-рядок: {x:.2f} знаки після коми, {n:02d} нулі зліва, {s:<10} / {s:>10} / {s:^10} ширина і вирівнювання (ширина - мінімум). Форматування змінює показ, не число.
  • def імʼя(параметр: тип) -> тип:, докстрінг, return. Без return - None. Змінні в функції локальні.
  • Друкує ≠ повертає. У лабах функція повертає, друк - поза нею.
  • Анотації типів Python не перевіряє, це робить mypy.
  • PEP 8: 4 пробіли, ≤ 79 знаків, 2 порожні рядки між функціями, snake_case, UPPER_SNAKE_CASE, не sum/list/str. Перевірка: flake8, pycodestyle, ruff; виправлення: black.

Де в лабах:

  • ЛР1, завд. 1: частку виводять з трьома знаками (12.700, 44.000) - це :.3f (ЛР1, с. 4, с. 14).
  • ЛР1, завд. 2: формат HH:MM:SS - {hours:02d}:{minutes:02d}:{seconds:02d} (ЛР1, с. 4, с. 16).
  • ЛР1, завд. 1-3: функція повертає str одним return, частини через \n (ЛР1, с. 6); введення - int(input(...)) поза функцією; структура програми - ЛР1, с. 11.
