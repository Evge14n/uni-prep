1. Ідея

У Лекції 6 дві різні половини. Перша - як оживити черепашку (анімація, клавіші, миша). Друга - рекурентні співвідношення: як цикл рахує послідовність, де кожен член залежить від попередніх. Насправді це одна ідея: стан на наступному кроці рахуємо зі стану на попередньому. У м'ячика стан - висота і швидкість, у послідовності - останній член (або кілька останніх).

1.1. Анімація = цикл кадрів (Лекція 6, с. 1-2)

Мультик - це швидка зміна картинок. Програма робить те саме: у циклі 1) змінює числа стану, 2) переносить черепашку в нове місце, 3) показує кадр, 4) трохи чекає. Щоб кожен рух не малювався окремо (повільно, з миготінням), лекція вимикає автоматичне оновлення screen.tracer(0) і сама показує кадр screen.update(). Паузу між кадрами дає time.sleep(0.01) - 0.01 с.

# не запускати: turtle
import time
import turtle

screen = turtle.Screen()
screen.tracer(0)                  # не малювати кожен рух окремо
ball = turtle.Turtle(shape="circle")
ball.penup()                      # м'ячик не лишає сліду
ball.goto(-250, 150)
dx, dy = 4, 0                     # швидкість: 4 вправо, 0 по вертикалі
gravity = -0.4                    # щокадру швидкість вниз зростає на 0.4
for frame in range(1200):         # 1200 кадрів
    dy += gravity                 # 1) змінили швидкість
    x = ball.xcor() + dx          # 2) нова позиція = стара + швидкість
    y = ball.ycor() + dy
    if x > 285 or x < -285:       # стіна: горизонтальна швидкість міняє знак
        dx = -dx
    if y < -235:                  # підлога: відскок і втрата енергії
        y = -235
        dy = -dy * 0.9
    ball.goto(x, y)               # 3) перенесли м'ячик
    screen.update()               # 4) показали кадр
    time.sleep(0.01)              # 5) пауза ~ 100 кадрів за секунду
screen.bye()

Уся «фізика» тут - звичайні числа, їх можна порахувати без вікна. Ось той самий крок для м'ячика, що падає з висоти 10 на підлогу 0 (гравітація -2, при відскоку швидкість гаситься вдвічі):

height = 10.0
speed = 0.0
for frame in range(6):
    speed += -2.0
    height += speed
    if height < 0:
        height = 0.0
        speed = -speed * 0.5
    print(frame, height, speed)

Кадр 2: швидкість стала -6, висота 4 - 6 = -2 - м'ячик «провалився» під підлогу. Умова ставить його на 0 і перевертає швидкість: -(-6) · 0.5 = 3.0 - тепер вгору. Кадр 3: 3 - 2 = 1, висота 0 + 1 = 1. Так і виглядає відскок. Зверни увагу на порядок: спершу швидкість, потім позиція, потім перевірка підлоги.

1.2. Події: миша, клавіші, таймер (Лекція 6, с. 3-5)

До цього програма йшла за сценарієм. Тепер вона чекає дій користувача. Ти кажеш turtle: «коли станеться X - виклич мою функцію f». Такі функції називають обробниками подій (с. 3).

виклик коли turtle викличе функцію
screen.onclick(fun) клацання мишею; fun(x, y) отримує координати клацання
screen.onkey(fun, "Up") відпускання клавіші ("Up", "space", "q" ...); fun() без аргументів
screen.ontimer(fun, 30) один раз, через 30 мілісекунд
screen.listen() обов'язково: вікно починає «слухати» клавіатуру, інакше клавіші не працюють
screen.mainloop() запускає очікування подій; програма «засинає» і лише відповідає на них

Головне правило: функцію передають без дужок. screen.onkey(toggle_pen, "space") - «ось тобі функція, виклич її потім». А screen.onkey(toggle_pen(), "space") викличе її ОДРАЗУ, ще до натискання, і передасть turtle її результат None. Коли функції треба аргумент, лекція обгортає виклик у lambda (с. 4): screen.onkey(lambda: move(90), "Up") - «функція без аргументів, яка, коли її викличуть, зробить move(90)».

# не запускати: turtle
import turtle

screen = turtle.Screen()
t = turtle.Turtle()
STEP = 20

def move(angle):
    t.setheading(angle)           # подивитись у потрібний бік
    t.forward(STEP)
    if abs(t.xcor()) > 280 or abs(t.ycor()) > 280:
        t.backward(STEP)          # вийшли б за межу - крок назад

def toggle_pen():
    if t.isdown():                # перо опущене?
        t.penup()
    else:
        t.pendown()

screen.listen()
screen.onkey(lambda: move(90), "Up")
screen.onkey(lambda: move(270), "Down")
screen.onkey(toggle_pen, "space")   # без дужок!
screen.onkey(screen.bye, "q")       # q закриває вікно
screen.mainloop()

У ЛР4 (с. 8) цикл анімації зроблено не for + sleep, а таймером: функція кадру в кінці сама себе записує на наступний виклик - screen.ontimer(main_loop, 30). Перевага: програма між кадрами не «спить» і встигає обробляти клавіші й мишу. А стан, який змінюють обробники (тема, режим), у ЛР4 тримають у глобальних змінних з global (ЛР4, с. 9) - лекція замість цього кладе лічильник у словник counter = {"clicks": 0} (с. 3), бо вміст словника функція може змінювати без global.

1.3. Кілька черепашок, рекурсія, поради (Лекція 6, с. 5-8)

Кілька черепашок (с. 5-6): кожна turtle.Turtle() - окремий об'єкт зі своїм станом. Їх тримають у списку racers і рухають у for racer in racers:. Лідер: max(racers, key=lambda r: r.xcor()) - «найбільша за значенням xcor()».

Рекурсія (с. 6-7, у лекції це бонус): функція викликає сама себе. Щоб вона зупинилась, потрібен базовий випадок - if depth == 0: return. Дерево: гілка = стовбур + дві менші гілки, кожна з яких теж дерево. Сніжинка Коха: відрізок = чотири менші відрізки зі «шпилем» посередині.

# не запускати: turtle
def koch(t, length, depth):
    if depth == 0:                 # базовий випадок: просто відрізок
        t.forward(length)
    else:
        for angle in (60, -120, 60, 0):
            koch(t, length / 3, depth - 1)   # той самий малюнок, утричі менший
            t.left(angle)

У ЛР6, завд. 1 рекурсія заборонена умовою - там лише цикли.

Поради з лекції (с. 7-8): turtle.Terminator - з'являється, коли закрив вікно, а програма ще малює (у Jupyter лікується рядком turtle.TurtleScreen._RUNNING = True); швидко - t.speed(0), screen.tracer(0) + screen.update(), t.hideturtle(); фігура «не замикається» - перевір, що сума поворотів 360°; t.undo() - скасувати останню дію; t.clone() - копія черепашки з тим самим станом; t.setundobuffer(None) - вимкнути пам'ять для undo на дуже довгих малюнках. Стиль turtle.forward(100) (без об'єкта, як у ЛР4, с. 1) - для швидких проб; t = turtle.Turtle() - коли черепашок кілька або є події.

1.4. Рекурентне співвідношення першого порядку (Лекція 6, с. 8-12)

Послідовність задана рекурентно, якщо відомий перший член a₀, а кожен наступний рахується з попереднього:

a₀ = u
aₙ = f(n, p, aₙ₋₁),   n ≥ 1

Факторіал: a₀ = 1, aₙ = n · aₙ₋₁. Тобто 1, 1, 2, 6, 24, 120 (с. 9). Комп'ютеру так рахувати зручніше, ніж за явною формулою: одна змінна і цикл. Шаблон лекції (с. 9):

a = u
for n in range(1, N + 1):
    a = f(n, p, a)

Після циклу в a лежить aₙ. Ліва a - новий член, права a - попередній. Одна змінна, бо старий член після обчислення нового вже не потрібен.

Як знайти рекурентну формулу. Для aₙ = xⁿ / n! лекція ділить сусідні члени (с. 10):

 aₙ       xⁿ      (n-1)!      x
───── = ───── · ──────── = ───     ⇒   aₙ = aₙ₋₁ · x / n,   a₀ = x⁰ / 0! = 1
aₙ₋₁      n!      xⁿ⁻¹        n

Жодного ** і жодного факторіала - лише одне множення й одне ділення на крок. Саме цього вимагає ЛР5, завд. 1 (с. 5: «не можна ... піднесення до степеня і функцію, яка рахує факторіал»), бо x ** 200 і factorial(200) окремо - величезні числа, а їх частка - нормальна.

Нумерація не з нуля (с. 11): якщо перший відомий член aₘ, то цикл починається з m + 1: for n in range(m + 1, N + 1). Гармонічна сума Sₙ = 1 + 1/2 + ... + 1/n: S₁ = 1, Sₙ = Sₙ₋₁ + 1/n, тому S = 1 і range(2, N + 1). Ще приклад з с. 12: Sₙ = 2·Sₙ₋₁ + n², S₁ = 1.

1.5. Співвідношення старших порядків (Лекція 6, с. 12-15)

Тепер новий член залежить від кількох попередніх. Фібоначчі - другий порядок (с. 13): F₀ = F₁ = 1, Fₙ = Fₙ₋₁ + Fₙ₋₂. Однієї змінної вже мало: треба пам'ятати два останні члени. Скільки порядок - стільки додаткових змінних (с. 14). Після обчислення нового члена змінні зсуваються на одну позицію:

до кроку:     F2 = Fₙ₋₂    F1 = Fₙ₋₁
обчислили:    F  = F1 + F2
зсув:         F2 = F1      (найстаріше - першим!)
              F1 = F

Правило з лекції (с. 14): спочатку зсунути найстаріші значення, потім молодші. Якщо спершу зробити F1 = F, старе F1 загубиться, і F2 = F1 запише туди нове значення - обидві змінні стануть однаковими.

older = 1
previous = 1
for n in range(2, 7):
    current = previous + older
    older = previous
    previous = current
    print(n, current)

2. Розібраний приклад

Умова (Лекція 6, с. 14-15). Визначник Dₙ порядку n: на головній діагоналі 5, над нею 3, під нею 2, решта нулі. Розклад за першим рядком дає Dₙ = 5·Dₙ₋₁ - 6·Dₙ₋₂ (6 = 3 · 2), D₁ = 5, D₂ = 5·5 - 3·2 = 19. Напиши функцію, яка ПОВЕРТАЄ Dₙ.

У лекції програма стартує з D₂ = 5 і D₁ = 19 (імена D2, D1 там означають «два кроки тому» і «крок тому»), а цикл з n = 3. Пастка: при N = 1 цикл не виконується, і програма друкує 19, хоча D₁ = 5. Виправлення без жодного if - підставити «нульовий» визначник D₀ = 1. Тоді D₂ = 5·5 - 6·1 = 19, як і має бути, і цикл можна починати з n = 2. Той самий прийом D₀ = 1 є в ЛР6 (с. 4).

def tridiagonal_det(order: int) -> int:
    """Повертає визначник Dₙ: 5 на діагоналі, 3 над нею, 2 під нею.

    >>> tridiagonal_det(1)
    5
    >>> tridiagonal_det(2)
    19
    >>> tridiagonal_det(5)
    665
    """
    older = 1
    previous = 5
    for n in range(2, order + 1):
        current = 5 * previous - 6 * older
        older = previous
        previous = current
    return previous


for order in range(1, 6):
    print(order, tridiagonal_det(order))

Що не так

Порядок зсуву. previous = current виконується першим, і старе Fₙ₋₁ губиться; older = previous записує вже нове значення. Функція повертає 32 замість 13 (ти це бачив у «Передбач вивід»). Найстаріше - першим.

# ВИПРАВЛЕНО
def fibonacci(number: int) -> int:
    """Повертає Fₙ, де F₀ = F₁ = 1, Fₙ = Fₙ₋₁ + Fₙ₋₂ (Лекція 6, с. 13).

    >>> fibonacci(6)
    13
    >>> fibonacci(1)
    1
    """
    older = 1
    previous = 1
    for n in range(2, number + 1):
        current = previous + older
        older = previous
        previous = current
    return previous

# БАГ
def next_frame(height: float, speed: float) -> tuple[float, float]:
    """Один кадр м'ячика над підлогою 0: гравітація -2 за кадр.

    Якщо м'ячик опинився нижче підлоги, ставимо його на 0 і відбиваємо
    вгору, швидкість після відскоку - 0.9 від тієї, що була.

    >>> next_frame(10.0, 0.0)
    (8.0, -2.0)
    >>> next_frame(1.0, -3.0)
    (0.0, 4.5)
    """
    speed += -2.0
    height += speed
    if height < 0:
        height = 0.0
        speed = speed * 0.9
    return (height, speed)
Що не так

Забули мінус при відскоку. Перед ударом швидкість від'ємна (вниз): -5. speed * 0.9 = -4.5 - знову вниз, і в наступному кадрі м'ячик знову «провалиться». Відскок - це зміна напрямку: -speed * 0.9 = 4.5, вгору. У лекції саме так: dy = -dy * 0.9 (с. 2). Перший тест проходить, бо там підлоги не торкнулись.

# ВИПРАВЛЕНО
def next_frame(height: float, speed: float) -> tuple[float, float]:
    """Один кадр м'ячика над підлогою 0: гравітація -2 за кадр.

7. Поясни чому

1. Чому при зсуві змінних (с. 14) спершу пишуть a3 = a2, потім a2 = a1, і лише потім a1 = a?

Відповідь-еталон

Присвоєння затирає старе значення. a3 = a2 безпечно: старе a3 (найстаріший член) вже не знадобиться. Після цього a2 вже скопійоване в a3, тож можна затерти a2 значенням a1. І лише тоді a1 - новим членом. Якщо почати з a1 = a, старе a1 зникне раніше, ніж його скопіюють в a2, і дві змінні стануть однаковими.

2. Навіщо в анімації screen.tracer(0) і screen.update(), якщо черепашка й так усе малює?

Відповідь-еталон

Без tracer(0) turtle перемальовує вікно після кожної дрібної команди: стерти, перенести, намалювати. Око бачить ці проміжні стани - миготіння, і це повільно. tracer(0) каже «малюй у пам'яті», а update() - «покажи готовий кадр одним махом». Так кадр з'являється цілим (ЛР4 називає це подвійною буферизацією, с. 8).

3. Чому в screen.onkey(toggle_pen, "space") після toggle_pen нема дужок, а в screen.onkey(lambda: move(90), "Up") з'являється lambda?

Відповідь-еталон

onkey хоче отримати саму функцію, щоб викликати її пізніше, при натисканні. Ім'я без дужок - це і є функція; з дужками - це її негайний виклик і результат (None). move потребує аргументу (кута), а onkey викликає без аргументів. lambda: move(90) - маленька функція без аргументів, яка «пам'ятає», що треба зробити move(90). Вона не виконується одразу, лише коли її викличуть.

4. Чому для aₙ = xⁿ / n! лекція рахує через aₙ₋₁ · x / n, а не прямо x ** n / factorial(n)?

Відповідь-еталон

Прямо - на кожен член окремо n множень для степеня і n для факторіала, а рекурентно - одне множення й одне ділення. До того ж xⁿ і n! окремо бувають величезні (200! має 375 цифр, x ** 200 для великих x переповнює float), хоча їх частка - звичайне число. Рекурентно ми ніколи не тримаємо ці гіганти. Саме тому ЛР5, завд. 1 забороняє ** і факторіал, а в завд. 2 вимагає рахувати доданок через попередній.
